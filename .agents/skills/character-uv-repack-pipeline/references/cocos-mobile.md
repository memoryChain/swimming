# Cocos Creator 与移动端接入

## 资源替换

- 保持运行时 GLB/GLTF 和独立遮罩的路径不变，覆盖文件时保留现有 `.meta`。
- GLB 内部的 mesh、material、image、armature 名称应与旧资源一致。Blender 的图片 `filepath_raw` 也可能决定 glTF image 名称，仅修改数据块名称不一定够。
- 不要手工改写 `library/` 缓存。让 Cocos Creator 重新导入源资源，再检查导入结果。
- 不自动启动或重启 Cocos Creator；如果编辑器已打开但缓存未刷新，提示用户对模型和遮罩执行“重新导入”。
- 不用 Cocos 编辑器截图做验证。使用离线 Blender 渲染，或由用户在现有编辑器会话中确认。

## 压缩和采样

- 在 Cocos 完成重新导入后，再运行项目的纹理策略修复与检查命令。
- GLB 内嵌图片使用 ASTC 等无 mip 链压缩产物时，Texture2D 子资源必须关闭 mip sampling，否则部分 WebGL/iOS 设备可能显示紫色或损坏像素。
- 保留 PNG/JPG fallback，不要只验证桌面预览；ASTC 最终效果应在真实 iOS/Android 设备上复核。
- 遮罩属于数据纹理，保持通道和全不透明 alpha 等既有约定。不要让颜色空间转换改变通道权重。

## 包体和渲染预算

- 优先保持单 SkinnedMeshRenderer、单材质和单次主体绘制。
- UV 合并可能减少导出顶点数，但更高分辨率底色会增加嵌入 GLB 大小。始终比较“GLB + 独立遮罩 + 压缩构建产物”的合计。
- 角色底色与遮罩尺寸应服从项目统一预算，不为单个模型设置隐性特例。SpeedSwimming 的角色底色和换色遮罩统一使用 512×512；清晰度不足必须通过 UV 像素密度、接缝、打包和烘焙质量解决，不能升到 1024。
- 避免为重整 UV 增加第二套运行时材质、额外网格或运行时贴图处理。重整和烘焙应在离线资产流水线完成。

## 接入后验证

1. 确认 `.meta` UUID 保持稳定。
2. 确认 Cocos 导入的 prefab、mesh、skeleton、material 和 texture 子资源有效。
3. 确认骨骼数、三角面数、材质数与基线一致。
4. 运行项目角色资源测试、纹理策略检查和相关构建检查。
5. 在角色选择、调试模型和实际动作中确认原色与换色。
6. 对联网项目确认资源替换不改变同步协议或角色标识；纯贴图与 UV 变更通常无需新增同步字段。
