# UV 重整工作流与经验

## 1. 先判断“碎片”来自哪里

把三个概念分开统计：

- 几何连通块：模型拓扑是否真的被拆成大量独立三角片。
- Blender 顶点：同位置顶点是否因导入、硬边、蒙皮或 UV 被重复。
- UV 岛：连续几何在纹理空间是否仍被切碎。

三者的数量可能完全不同。GLB 导入后顶点数通常还会因 UV 缝和法线缝再次增加，因此必须同时记录 Blender 顶点数和导出后顶点数。

## 2. 安全焊接门槛

对候选距离（通常从 `1e-7` 开始）统计同位置顶点对，并逐对比较：

- 顶点组名称与权重；
- 顶点法线；
- 是否属于应保持分离的硬边、镜像边界或独立附件。

只有权重与法线一致、且不会改变造型语义时才焊接。先在报告里预测焊接后的几何连通块，再在工作副本中执行。焊接后确认面数、骨骼、顶点组、包围盒和静止姿势不变。

## 3. 保留双 UV 层

复制原 UV 为 `UVMap_Source`，创建 `UVMap_Repacked`。烘焙前不要删除源 UV。

推荐顺序：

1. 按身体部件和可见性规划接缝，优先把长缝放在背面、内侧或自然服装边界。
2. 对每个闭合几何部件至少提供一条可展开接缝。
3. 使用 Angle Based Unwrap；必要时再执行有限次数的 Minimize Stretch。
4. 打包后检查退化面、越界、重叠、像素占用和边距。

不要默认使用 Smart Project。它常能消除退化面，却仍留下数百个细碎岛。对角色直接使用无接缝的普通 Unwrap，则可能生成大量零面积面。

## 4. 用像素密度而不是岛数判断质量

对每个面计算：

`target_uv_area / source_uv_area`

重点观察 `p01/p05/p50/p95/p99`，并统计小于 `0.25` 或大于 `4` 的面。总 UV 面积接近并不代表局部密度正常；一个大岛内部仍可能把腰包、鞋带、脸部或文字压缩得很小。

如果局部密度差异过大，可以在低密度、高密度与正常区域的边界增加接缝，再重新展开。但每增加一批岛都要重新评估打包边距：岛越多，边距占用越大，所有图块可能被整体缩小。

经验结论：

- 追求极少岛通常会导致局部拉伸或细节模糊。
- 过度细分虽然改善局部形变，却可能因边距占用而降低整体密度。
- 应在“视觉保真、足够边距、导出顶点数、岛数”之间取平衡，而不是只优化一个数字。

## 5. 边距与分辨率

边距按最终目标分辨率评估，不按超采样烘焙分辨率评估。移动端线性采样和块压缩场景，通常从最终纹理的 8–12 像素边距开始；大量小岛时要同时检查空间利用率。

先用目标分辨率的 4 倍烘焙，再高质量缩小，可降低锯齿和细缝。目标分辨率首先服从项目的统一标准；如果项目规定角色贴图固定为 512，就把 512 当成硬上限，不能给个别模型升到 1024 兜底。512 重排后细节变软时，应重新分配关键区域像素密度、调整接缝和岛数量、减少无效留白或改善烘焙过滤。只有用户明确修改项目级策略后，才评估提高分辨率。最终仍要比较模型、底色和遮罩的总字节数及构建产物。

## 6. 同步烘焙

烘焙采用“源 UV 采样、目标 UV 写入”：

- 底色使用正确的 sRGB 色彩空间；
- 遮罩、法线和数据贴图使用 Non-Color；
- 遮罩通道语义必须保持不变；
- 烘焙时提供足够 dilation，但防止扩张污染邻岛；
- 最终运行时材质只引用目标 UV。

如果一次操作后只剩少量退化 UV 面，可在独立 Blender 进程中修复并重新打包。连续在同一编辑状态里混用 unwrap、直接改 loop UV 和 pack，有时会受到选择状态或缓存影响；用新进程复核比假设成功更可靠。

## 7. 必须做的视觉验证

至少输出：

- 原版与候选的正面、侧面、背面；
- 脸、服装接缝、腰带/腰包、鞋面、文字和小配件近看；
- 高对比换色的正面、侧面、背面；
- 两个大幅度动作，例如游泳划臂、挥手、下蹲或入水预备。

检查皮肤渗色、颜色岛断裂、UV 缝发黑、薄片附件错位、关节拉伸处裂缝。若固定尺寸候选模糊，先判定是局部像素密度不足、展开形变还是烘焙映射问题，再回到 UV 布局修正；不要用突破项目尺寸标准的贴图掩盖问题。

## 8. 最终验收表

- 面数、骨骼数、骨骼名称、顶点组、包围盒符合基线。
- 单网格/单材质等运行时约束没有退化。
- UV 无退化、无越界、无非预期重叠。
- 原色外观和所有遮罩通道通过多视角验证。
- 动作变形下没有接缝或蒙皮异常。
- 导出后顶点数有实际改善，或有明确理由接受变化。
- 模型加所有贴图的总字节数符合目标平台预算。
- 候选文件内部图片、材质、网格和骨骼名称已恢复为稳定运行时名称。
