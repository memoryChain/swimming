# 设计、状态与协作经验

以下视觉取向和页面约定来自划水大师的已确认方向；修改前仍以当前项目设计与最新用户要求为准。

## 先统一风格，再补细节

- 用户希望有游戏感、简洁而有细节，避免像后台原型，也避免低幼或过度装饰。参考图用于提炼卡片层次、圆角、材质、吊牌结构和留白，不照搬其他游戏的角色/IP。
- 先复用大厅/角色页已有的蓝青色、浅色卡片、深蓝文字、黄绿主按钮和货币图标。用少量斜切、暗纹、挂扣或柔光形成层次，不把所有参考的装饰堆进一张卡。
- 一次多方案应各有明确差别，不要只换色。用户选定后收敛到原文件局部修订，不继续无授权发散。
- 联机页采用 UI 卡片组织，不做场景化空间。结算页可以放大真实领奖角色表达荣耀感，这是不同页面的选择，不相互套用。

## 布局与字重

- 先用原稿同一画布对齐，再检查宽屏/窄屏适配。划水大师近期设计源为 1672 × 941，但不是其他页面的硬编码默认。
- 对齐内容块的可见边界，不按外扩阴影或挂扣最高点机械对齐。卡片间距、行高、内边距独立控制。
- 昵称、当前角色名、准备状态分成三层，给各自稳定空间；昵称超长需有截断/缩字策略，不能挤走状态。
- 升级预览的当前值、箭头、下一等级值使用稳定列。箭头放两个数值列的中间，不跟随某个数字的文字长度漂移。
- 正文、辅助提示、按钮、标题和关键数值分级设置字重，不一律加粗。例如“邀请好友”按已确认要求保持常规字重；数字英文使用批准的粗体入口，并核实跨设备实际字体。
- 小型赛制展开指示优先清楚的小三角；与字号、点击区域分离，不靠扩大箭头来扩大热区。

## 状态先于皮肤

制作前列出「身份/状态 → 显示文案 → 是否可点 → 点击结果」，不要仅画默认态。

### 角色页

- 已上场且当前选中的角色，原主按钮位置显示加粗纯文字“已上场”；其他可用角色仍允许确认选择。
- 大厅与详情页使用同一属性口径和数据源，详情页另算升级预览；不能一个显示评分、另一个显示底层速度却不标注含义。
- 技能图标及圆框和大厅复用，不重新上传；标签、技能和数值的局部调整不重建角色预览。

### 联机页

- 右侧共 8 个成员位，包含房主。左侧房主卡内放房间编码、人数、赛制；房主可通过上拉抽屉切换，成员不可编辑。
- 成员信息显示当前角色。准备/取消准备是成员操作，开始比赛是房主操作，文案、可用态和反馈要区别；取消准备的配色读取定稿，不能臆造此前未记录的精确色值。
- 点击成员头像的小弹窗须有足够深浅对比。踢人仅对允许操作的其他成员开放，不能只隐藏入口而不校验权限。
- 最新约定：返回自动退出并回大厅，不再另设“退出房间”按钮，也不重复设置底部邀请按钮；邀请由空位承接。
- 这些是交互约定，网络调用必须沿现有房间抽象实现；结算“返回房间”的保活流程与退出房间不是同一操作。

### 结算页

- 保留游戏实时领奖台场景，放大角色，但兼顾台面露出、脚底接触、动作最高点与左上荣誉条遮挡。
- 排名区采用局部深色渐变遮罩增强可读性，不用厚重整块底框压住场景。遮罩在信息下方且不拦截点击。
- 排行榜表头为深色条；每人独立长条底图，行稍高、间隙紧凑，前三名区分底色；本人标记独立于名次底色，不能只给第二名固定做绿框。
- 1/2/3 徽章保持同一圆形主体、视角、光照、3D 潮玩材质和绶带系统。通过金/银/铜与适量细节区别，不让第三名视觉尺寸比第一名更大。普通名次也有同系列普通徽章，数字可更新。
- 荣誉条至少支持冠军、亚军、季军、普通名次；未完成、退出、淘汰不能误授前三名。模式信息和平均速度同组，奖励使用游戏现有货币 icon。
- “我的排名”用定稿的外框/底色及文字强调，检查在每个名次和不同背景上仍清楚，避免新增黑边或过强发光。

## 交付沟通

先说明改好的视觉结果和证据，再说明仍需用户确认的游戏内表现。局部问题应指出具体原因，例如丢失实色描边、字体未随包、透明边距被裁剪，而不是笼统地说“已优化”。把已验证经验写入维护文档，未证实猜测不要固化成规则。
