# 运行时接入与验证

## 先定位页面与资源

- 在项目根目录读 `AGENTS.md`，确认 Cocos 版本、资源分包、字体/纹理构建入口与验证限制。
- 查看 prefab、一次性构建节点的代码和加载入口，搜索运行时对字体、颜色、尺寸、SpriteFrame、trim、缩放和 active 的覆盖。不要只改设计文件却忽略实际生效代码。
- 划水大师资源路径集中在 `assets/scripts/core/ResourcePaths.ts`。结算新资源位于 `assets/race/ui`，首包既有共享 UI 沿原路径引用；不能机械地把所有新图放 `assets/resources`。
- 结算具体实现和验证入口见项目根目录的 `docs/开发记录/界面接入/结算界面接入说明.zh.md`、`scripts/export-settlement-runtime.jsx`、`tests/settlement-runtime.test.cjs`；这些路径属于宿主项目，不是技能安装目录的相对路径。

## 保持像素关系

- 使用原设计坐标做统一等比适配；不要拿另一个横竖屏页面的默认分辨率直接覆盖。
- 带透明留白的按钮/描边，区分纹理画布、可见区域、点击区域。需要按完整画布定位时使用 `Sprite.SizeMode.CUSTOM` 和 `trim=false`，再按记录的透明边距补偿。
- 生成式透明 UI 可能带有肉眼几乎不可见的低 alpha 尾迹，普通 `trim` 仍会把尾迹计入边界，导致可见主体在画布内偏上或偏下。接入前除原始 alpha 外，再以约 0.5%～2% alpha 阈值测量可见包围盒，并把可见主体重新居中到固定画布；若底板主体偏心，应先修正底板素材并保留 `.meta`，不要给每个图标和 Label 分别添加反向偏移。
- 保持 PS 的真实叠放顺序，特别是背景、白色外沿、本人描边和外发光；有问题先查资源 alpha、裁剪、缩放、层级，不叠加更多节点掩盖。
- 宽屏左右布局先核对 Canvas 的实际 UITransform：相机已经适配不代表 Canvas 尺寸已更新。固定设计坐标可留在左右控件组内，用 Widget 对齐真实屏幕边界。贴角装饰及其内部标题、箭头和点击区域应共用适配组，保持原稿相对位置；安全区调整必须核对整个组合，不能单独平移文字使其越过斜边。侧栏按自身安全区布局。窗口监听随节点销毁清理，不放进比赛逐帧更新。
- 非平铺的标题角标、渐变遮罩若出现一像素边线，检查纹理是否误用了 repeat；线性过滤可能混入另一侧的颜色或 alpha。按需将其 Texture2D 子资源改为 clamp-to-edge，保留 UUID，不先改图或增加遮挡节点。
- 额外视觉边距与设备安全区通常取较大值，不直接相加，否则双侧安全区设备会明显收窄内容。回归应同时覆盖单侧、双侧及无安全区，不能只用一种模拟值；未采集真机值时，不把模拟的边距当作设备实测数据。
- 当页面要求按完整屏幕统一留白时，应在页面布局入口显式关闭整栏安全区约束；仅把相加改成取较大值仍会被较大的安全区限制。微信胶囊等实际遮挡单独处理。回归要覆盖真实页面组装入口，不能只验证未被页面正确配置的通用辅助函数。
- 跨 Canvas／相机的锚定提示框必须先由来源相机 worldToScreen，再由目标相机 screenToWorld，最后 convertToNodeSpaceAR。两个画布的世界原点和相机中心可能不同，直接转换世界坐标会把弹框推到屏幕角落；回归需故意设置不同原点和屏幕缩放，不能只用同原点节点替身。
- 文字位置按基线、行高与容器核对；过小的文本框或错误 lineHeight 会触发 SHRINK，导致“同字号却变小”。
- 相机距离控制角色大小，取景目标控制露出台面的位置，角色站位补偿控制脚底接触；三者不要混为一个全局缩放参数。针对领奖改专用参数，不误改比赛/预览共用站位。
- 角色材质若是固定卡通/无光照，不默认新增灯就能生效。先查现有材质与场景限制；优先复用已验证的低开销表现，退出时恢复临时材质值。不要将特定项目的材质补亮说成新增了真实灯光。

## 头像与卡片裁切

- 测量框素材的实际圆心、内径和透明边距，再确定头像位置与尺寸；图片画布、外框可见直径、内圈填色直径是不同数值。可以略覆盖内圈抗锯齿过渡，不能盖住白色描边。先找共用加载入口，再检查选择页、大厅、房间、结算等全部使用点。
- 固定圆形头像可在导出阶段写入抗锯齿圆形 alpha，使多个界面直接复用，不额外增加每个头像的运行时 Mask。使用超采样或等效方法生成平滑圆边，保留透明像素下原有 RGB，避免线性采样产生白边或黑边。不能把背景一并抠掉：背景在圆内保留，圆外透明。
- 源图保留完整正方形与高清版本，运行时分辨率按最大显示尺寸、设备像素密度和分包预算选择；不要把高清原图直接塞进首包。依赖完整画布时使用 CUSTOM 尺寸、trim=false，并检查异步 SpriteFrame 回调没有覆盖裁切设置。
- 圆角角色卡需要让画面受卡片内部的圆角裁切约束；仅在上面叠白框不能挡住方图漏出的四角。可用一次建立的静态圆角 Mask，边框和文字保持各自层级，不在每帧重画遮罩。
- 替换头像时保留已有 UUID、资源路径与稳定 avatarId 对应关系；不要因为重新设计而重排身份目录或改变其关联的比赛外观。网络仍同步既有 ID，同版本客户端解析同一素材，不引入图片传输或逐帧工作。
- 验证至少涵盖四角全透明、中心不透明、圆边平滑、主体安全区、内圈无底色缝、外框保留，以及不同使用尺寸。离线合成实际框素材可检查边缘，但不能代替引擎与真机验收。
- 本项目已验证导出入口为 `scripts/export-street-avatars.py`；固定文件映射与尺寸见 `docs/开发记录/界面接入/头像设计与裁切接入说明.zh.md`。源文件不可用时先恢复源文件，不拿已缩小的运行时图反复放大导出。

## 字体必须能跨设备复现

- 静态中文遵循项目字库：正文 Regular，批准的标题/按钮/关键值 SemiBold；粗细来自实际字体文件，不用描边/阴影/重复 Label 伪造。
- 划水大师新增静态文案后运行 `pnpm fonts:build` 和 `pnpm fonts:check`。不手改生成字符表或 TTF；构建钩子只审计，不在 Creator 构建期间临时下载/生成字体。
- 当前字符扫描读取完整源码，中文注释也会影响字体子集。UI源码修改后即使没有改可见文案，也要运行`pnpm fonts:check`；发现过期就运行`pnpm fonts:build`后再次审计，保留字体.meta，等现有Creator会话导入TTF后再构建。
- 数字英文与中文分离时，拆 Label 并保持统一对齐。明确区分系统字体声明与项目随包字体：`Arial Black` 字体名本身不是嵌入资源，不能保证另一台设备一致。需随包时核实字体文件与嵌入授权，不能擅自复制本机商业字体。
- 用户名、聊天等无界文本保留全覆盖回退，不能因为静态示例能显示就切到子集字库。
- 当前值、升级值、未完成状态等可能使用不同字体时使用独立 Label，避免异步字体回调把状态切换后的标签覆盖回旧字体。
- Cocos 3.8.8 的 CHAR 缓存共享 1024×1024 字符图集，同一字符的不同字号、字体和颜色会分别占用空间；容量耗尽后可能整段漏字。多页面中文 UI 不应全部强制 CHAR，事件更新的文字可使用独立文本纹理；仍须控制字符串赋值频率，并在真机核对绘制开销。字体加载回调应核对标签当前需要的字重，不能覆盖已改成系统字体的动态昵称。
- 高频 HUD 数字可局部使用 CHAR，前提是字符、字体、字号、颜色和描边组合有界且通过真实引擎容量检查。BITMAP 会为不断变化的整段数字占用新槽，不能照搬事件型页面策略。覆盖全部状态/数字、缩放字号、AI 文案、反复显隐，检查字形顶点、UV 范围和满图警告；昵称与其他无界文本保持原策略。增加字号、主题或字体后重新核查，不能用少量示例证明共享图集永远不会耗尽。
- 微信默认关闭动态图集时，BITMAP 昵称不能保证合批。固定比赛名单可在名单事件中建立局部文字纹理页，将全覆盖系统字体昵称和有限名次圆标缓存到同页；不打开全局动态合图、不让无界昵称占用全局 CHAR。用 Label 的 `updateRenderData(true)`、`assemblerData.canvas` 和 `renderData.data` 复制引擎实际字形并保留几何与中心偏移，子帧明确设置 rect 和 originalSize，等待真实随包字体后再缓存数字。页面只在名单变化时绘制和上传，换位只切帧，投影只移动节点；画布／字体／容量失败保留完整文字并可重试。名单版本门控迟到回调，名单替换及所属节点销毁释放私有帧、纹理、ImageAsset 和 Canvas。验证须关闭动态图集，逐像素对照字形并检查反复更名后的延迟销毁；浏览器测量不能替代微信适配层画布、系统字体、Emoji 与显存的真机验收。

- Cocos 3.8.8 的缓存字体可能同步触发文字测量。空字符串标签若先应用字体、后设置 SHRINK，会在默认 NONE 模式下被测量成零宽。先设置溢出/换行策略，再应用字体，最后恢复设计文本框；检查“初始空值→赋值”及冷/热字体缓存，不能只验证非空示例。
- 将有限文字切换到 CHAR 时，同时核查 Overflow.NONE 自动尺寸。字符组装器可能改变文本框高度，影响文字位置及邻接控件的布局；依赖原自动尺寸的角色名可保留 NONE，仅将周围有限读数合批。先比较真实引擎的尺寸、几何与世界坐标，不能用固定位置补偿；主页面的缓存开关不要顺带作用于隐藏弹窗长文、后台错误或其他无界内容。
- 房间昵称缓存以实际显示文字作为页的更新条件，准备、忙碌、赛制和普通广播刷新不得重画名单。可保留禁用的原 Label 作为后续字形来源与失败回退，缓存 Sprite 一次创建；故障页不在普通状态刷新时反复尝试。跨页使用 CHAR 时，验证已经访问的生涯、联机、赛中 HUD 与赛前文字的累计容量，隐藏页面不等于已回收字形；同时验证姓名像素、原坐标、权限、迟到头像、换座位与旧页释放。
- 结算排行榜分列合批时，人数缩减须同时隐藏底图、头像、文字、昵称和本人框；本人描边保留在全部行上方。昵称私有页的身份键包含行槽位、文字和本人颜色，空昵称换位也不能复用旧槽位绑定；成绩和奖励刷新只更新读数。大字号荣誉与外部生涯消息保持独立文字纹理，避免扩大全局 CHAR 占用；容量检查累计覆盖已访问的其他页面。

## 状态与联机

- 常驻大厅进入比赛后，隐藏的弹窗 Canvas 仍可能与新场景处于同一父节点。弹窗按所属 Canvas 缓存，不能按同名兄弟节点认领；相机优先级必须高于所属 UI，随所属 Canvas 销毁释放。暂停教学必须先确认引导挂在活动画布，挂载失败不得先冻结调度器。回归应同时执行真实分层、旧页面暂存、新页面挂载、点击恢复和返回，不能只用独立界面替身证明进场可用。

- 登录交接须区分“业务代码可执行”与“下一页可完整呈现”。加载遮罩应覆盖必要图片/字体、存档恢复、当前角色/材质/展示动作和渲染提交，不能在分包回调或节点创建后就移除。收集嵌套请求及共享缓存的新订阅，并覆盖超时、失败重试、销毁和邀请打断；回调不能把旧页面重新揭开。先展示后补图的测试应人为延迟资源复现，同时验证代码版本，桌面数据不能替代真机画面验收。
- 页面复用不等于首次进入时创建全部隐藏页面。节点首次按需构建，后续复用稳定层级；资源预加载与页面实例化分开。预加载范围必须服从当前产品策略：本项目 UI 为独立 CDN Bundle，按打开页面加载，不在登录扫描全部 UI 或创建隐藏页面；角色、动作和场景放微信分包，下载分包不等于解析全部资产。热缓存应同步交付，不能仅因首次建页就无条件显示转圈。大厅角色仍只使用当前展示动作，比赛和调试的完整动作需求通过显式选项保留。
- 节点/监听一次创建，状态变化只改受影响控件；点击已选项应无操作。只在显示值变化时写 Label/颜色/active，不重建整页或无关 3D 预览。
- 图片异步回调检查节点有效性以及请求路径仍匹配，防止旧头像覆盖新成员。
- 大厅与详情共用属性模型，结算使用已结算的权威成绩，不在展示层重算排名或伪造未完成时间。
- 房主/成员、准备/取消、已上场/可选、未完成/正常完赛分别测试。按钮防重复必须覆盖触摸和键盘。
- 涉及同步前读项目联机文档第 8 节。联机房间保活返回不调用 `endGame`；所有单机/联机分支沿既有会话标志，不改变单机玩法或新建协议。
- 结算等事件 UI 可少量分配；隐藏 UI 无逐帧工作。彩带/补光调整也需考虑网格、材质、更新频率及移动端成本。

## 导入与验收

- 清理 UI 冗余时，路径或 UUID 有引用不等于仍在使用。继续核对引用方法是否从生产入口可达、节点是否长期隐藏或被新视图替代，以及数组/动态键选择的全部状态。没有调用入口的旧方法应连同资源声明清理，避免保留死代码造成误判。
- Prefab 中隐藏节点的 SpriteFrame 仍可能将旧图片带入包。删除图片前先解除废弃依赖；裁剪节点时同步构建器读取和事件绑定，验证所有对象索引、父子关系与组件归属，保留 Prefab 原 `.meta`。不要删除仍用于输入或当前视图挂载的节点。
- 无损 PNG 优化不能只比较解码像素，还要保留 ICC、sRGB、gAMA、cHRM 等色彩信息，以及方向和像素比例；源图像素相同但色彩信息丢失仍可能改变显示。默认不重编码 JPG，不降分辨率，保留 `.meta`；16 位 PNG 和 APNG 在工具未覆盖其精度或动画前应跳过。源文件节省量与生成 ASTC/回退图后的上传包节省量分别统计，不直接相减。
- 修改构建插件后，核对新构建日志和实际产物是否执行了新步骤；Creator 会话可能缓存旧插件，不能只凭源码或“构建成功”判定精简已生效。上传前用独立进程检查实际构建，发现漏处理时使用可重复执行、带备份的后处理入口；涉及资源编码时先确认该包已包含兼容解码器。上传包大小与源文件大小分别记录，并留出余量。

1. 新图等待已有 Creator 会话生成 `.meta`；替换保留原 `.meta`，不编造 UUID。确认 Texture2D/SpriteFrame、原始宽高和资源引用。
2. 按项目无损优化脚本处理后执行 `pnpm textures:fix`、`pnpm textures:check`。新图缺 `.meta` 必须单独报出，审计通过不能掩盖漏检；不能手动给首包 UI 添加压缩副本。
3. TypeScript 使用项目固定版本；划水大师 macOS 为 `npx --yes --package typescript@5.4.5 tsc --noEmit --ignoreDeprecations 5.0 --skipLibCheck`，Windows 使用 `npx.cmd`。
4. 运行对应页面测试：状态切换后节点/监听稳定、回调一次、旧资源不覆盖、本人标记唯一、字体/尺寸/资源存在、返回目的地正确。
5. 离线原尺寸排版与定稿对比，再检查更宽/更窄的画布、安全区和长昵称。横屏项目不强套 720 × 1280；竖屏项目再使用 9:16、18:9、19.5:9、20:9 的对应矩阵。
6. 不自动启动/重启 Creator，不截取 Creator 窗口或其启动的预览。可做本地离线 HTML 验图，并明确它不是引擎截图；真实领奖动作、灯光、脚底和微信真机由用户在现有会话确认，或用用户另行批准的方法验证。

## 静态图集、动态图集与九宫格缓存

- 简单选项的等宽圆角描边不能用两张相同圆角半径的九宫格底图缩小套叠；内半径应比外半径减少描边宽度，否则转角会明显加粗。可使用真正的边框资产，或基础控件在状态边沿一次绘制圆角路径与等宽描边；禁止逐帧重绘。极窄的标题标记也不能直接挤压大面板九宫格，否则会变成椭圆。
- 弹窗整体偏移且遮罩同方向缺边时，要同时排查前序3D相机的viewport与弹窗相机，不先加固定坐标补偿。角色取景尽量保持完整非负视口，通过相机布局调整位置，并回归后续弹窗渲染。安全区坐标要结合可视原点换算。

- Cocos运行时缓存的SpriteFrame可能已经进入动态图集，此时`frame.texture`是合图纹理，不能将它直接赋给新SpriteFrame而丢弃原frame的rect/UV；返回页面后会把整张图集拉伸成面板，出现头像、徽章等碎片。
- 已采用静态图集时，以缓存 SpriteFrame 的 `clone()` 创建私有九宫格帧并设置切边，保留 rect/UV；局部裁切的坐标加上源 rect 原点，尺寸取子帧 rect，不能取整张 atlas 的 texture 宽高。节点只释放私有克隆，共享图集和帧留给资源缓存。静态帧禁止再次进入动态图集。只有明确的独立原图入口才从原始 Texture2D 创建帧，不为局部问题关闭全局动态合批。
- 自动图集 `.pac` 在构建时合成，Creator 浏览器预览仍用原帧。禁动态合图只适用于真实静态图集帧，预览回退原帧须保留可合图状态；不为优化预览强制改微信压缩或图片缓存清理策略。局部裁切克隆已有动态合图的源帧时，也要更新克隆 `original` 的原纹理裁切原点，否则引擎重置图集后 UV 会偏移；不要改共享源帧。
- ScrollView 的 Mask 只裁像素，离屏节点仍会提交绘制；在挂载、滚动事件和再显示时按视口交集切换卡片 root 的 active，保留节点／选择／滚动位置并带外框余量，不在隐藏页面或比赛逐帧遍历。Mask、文字缓存、渲染顺序须分别核查，重开 Creator 或改成图集不能单独证明 drawcall 下降。状态驱动页面可局部使用 BITMAP 整段文字缓存；只在动态合图可用时有合批收益，容量不足须能回退完整独立文字，不能复用全局 CHAR 漏字方案。
- 排行逐行「底圈→头像→数字」会反复切换图像/文字纹理，静态图集分组后的底圈与头像还可能属于不同纹理页。可按整列底圈、头像、数字分层，保留每行中心、显隐、身份与异步检查；结构挂载一次，换位仅写变化属性。先追踪纹理、材质、buffer 和 stencil，勿凭圆环填充类型或颜色猜拆批原因。用同一冻结场景恢复旧/新绘制结构隔离收益；UI 批次须在引擎清批前读取，再分别测主体 HUD、其他覆盖层和总 drawcall，不能用场景总数评价图集是否启用。
- 带圆角肖像的整排名牌不能只改文字缓存：逐卡的遮罩与底图/文字交错仍会拆批。可按整排底板、肖像、装饰、固定文案、昵称分层；保留每张肖像的实际裁切，不能为降低统计值删除遮罩。各层通过原 Tween 的固定回调同步变化位置/透明度，保持错峰入场，不增加 Tween 数量或比赛逐帧同步。缺席泳道和异步身份同时门控各层；用真实引擎检查中间动画帧，测卡片和头顶姓名的开销时分别隐藏，避免误认来源。
- Cocos 3.8.8 的 FILLED 组装器不按 SIMPLE 的方式补偿裁切，设置 `sprite.trim=false` 不能防止径向圆环变形。首次转 SpriteFrame 会默认 `trimType=auto`；必须保留原透明画布并等待重新导入，审计同时检查裁剪尺寸、原始尺寸和 offset。兼容裁切帧时，FILLED 节点的尺寸／位置还原为子图在原画布中的实际矩形，径向 fillCenter 还原为原画布圆心；直线填充区间也要映射并裁剪到实际子图。左右镜像须计入节点 scale，不能用固定像素挪动圆环。回归应执行真实组装器验证顶点与 UV，单纯核对节点坐标捕获不了该错误。
- CDN 静态图集按共同展示和跨页复用分组；大背景和大插画保持独立，避免巨型图集扩大首次下载、显存和缓存失效范围。生产代码加载整组 SpriteAtlas，再按名称取帧；禁止缺帧时默默退回散图。动态取帧需关闭自动删未使用帧，并确认构建保留可加载 SpriteAtlas、移除源 texture/image。
- 首次页面进入需等待所需图集、嵌套绑定和布局提交后整页展示，失败整页重试、取消防止迟到挂载；热缓存直接显示。资源加载门禁不阻塞房间网络，也不能在每帧重建页面。项目流程与未完成的引擎验证见 [UI 静态图集接入与维护](../../../../docs/操作手册/开发与资源/UI静态图集接入与维护.zh.md)。
- 大厅内页面切换统一使用透明转圈，保留底层画面；资源计数或下载进度回调不能将透明等待切成进度条。深色启动遮罩与启动进度保持独立，失败时仍提供可点击重试提示。
- 回归要覆盖冷加载及已经合图的热缓存，反复销毁/重建、过期异步回调与帧释放；只模拟完整原图的测试捕获不了该问题。

- 本项目 Creator 微信产物曾将 `[...map.values()]` 转为 `[].concat(iterator)`，使预加载列表混入迭代器、UUID 变成 undefined；集合转数组使用 `Array.from()`。仅用 ES2020 转译跑测试不能证明发布兼容，应覆盖产物的数组展开方式，确认资源列表是扁平数组且每项 UUID 有效。
