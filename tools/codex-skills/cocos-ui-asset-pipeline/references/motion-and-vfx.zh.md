# 动效与特效制作规范

适用于本项目 Cocos Creator 3.8.8 的大厅、弹窗、比赛 HUD 动效及泳道特效。目标平台为微信小游戏，重点考虑 iOS JavaScriptCore。平台、输入、资源和操作限制以仓库 `AGENTS.md` 为准；本文记录可复用的制作方法，具体时长、尺寸、粒子数不作为所有效果的统一模板。

## 制作顺序：先核准事件，再调整外观

1. 明确用户指的是哪个动作、哪个位置、哪个瞬间。截图中的箭头、描述的接触点和真实游戏状态优先；不要把“手掌拍到水面”理解成按键判定、手臂前伸或身后尾流。
2. 核对当前资源和代码，明确事件来源、坐标空间、层级与生命周期。每个效果至少说清楚：何时出现、在哪里出现、向哪里运动、多久结束、如何重置。
3. 方案预览用于讨论美术与节奏；已获接入授权后实现，并用真实游戏验证。不要将预览授权自动扩展为接入，也不要在已有明确授权后反复询问同一步骤。
4. 按“触发 → 位置 → 方向 → 可见度 → 节奏 → 预算”逐项排查。用户说看不见时，先查有没有在正确时刻、正确位置发射，不能只一轮轮加大尺寸和透明度。
5. 定稿记录当前参数、源码与资源位置、自动检查及实测范围。历史调参保留为原因记录，明确哪些数值已被新版替代。

## UI 动效：结构、输入与生命周期

- **布局与动画分开持有变换。** 外层 Widget/锚点负责安全区和分辨率适配，稳定的内部容器负责入退场。入场、选中位移、按钮按压各自避免争写同一个变换。
- **只在状态变化时启动。** `false → true` 播入场；每帧重复可见、重复选中不能重播。游戏阶段变了但 HUD 仍可见时，不应再次入场。
- **快速操作接续当前画面。** 改选或关闭途中重开时取消本控制器持有的旧 Tween，从当前显示值接续。避免硬跳回初始位置，不用全局停止 Tween 误伤角色或其他界面。
- **动效不能拖延玩法。** HUD 入场不延迟第一划、蓄气、起跳或权威读数；实际输入到达时可立即让操作提示就位。不能为演出添加假进度、假满气或数字从零滚动。
- **触控范围与装饰分离。** 全屏左右半屏划水区域不随手掌装饰缩放；弹窗遮罩和退场输入阻挡不跟面板一起缩小。退场结束才释放应保留的底层阻挡，销毁必须释放。
- **按钮业务用 CLICK。** 按下/松开/取消仅控制视觉；手指移出或取消不能误保存。离场导航和保存操作防重复触发，异步完成校验原节点身份，不能操作重建后的页面。
- **结构只构建一次。** 切选项只改受影响控件，不重建页面、不重绑监听、不重启无关 3D 预览。隐藏、销毁、重开时清理自有 Tween、回调、监听和残留变换。
- **节奏按功能定。** 入口可适当错开、主操作响应更快、关闭通常比打开短；这是设计选择，沿用具体页面已确认数值，不把一次水花或弹窗的参数套到所有页面。

## 场景特效：真实接触、空间与轨迹

### 触发时机

- 动作阶段信号可表达意图，不能证明模型已接触表面。手掌拍水应检测当前可见手骨下降进入水面接触带；头前伸展信号曾在手仍离水时提前触发，放大粒子也修不好时机。
- 接触检测要有重新布防条件：抬离表面后才允许下一次下降触发。在水里保持、向上出水、初始生成于水下，不应当作新的拍水。
- 接触带用于近似骨骼原点到可见表面的距离，须按实际模型核准。当前水花用腕部骨骼近似手掌下缘，不等同于精确网格碰撞；换角色或水面高度后必须复验。
- 前后帧跨过表面时插值求接触点，避免低帧率时发射点已落到水下或前移。瞬移、重开、离屏恢复、离水动作要重置采样，不补发旧事件。
- 同一次接触统一驱动水片、水滴和波纹。GOOD/PERFECT 是额外判定反馈，不能作为普通拍水的必要条件，也不能让其冷却吞掉真实接触反馈。

### 空间与运动

- 区分“发射点跟随角色”与“已发粒子跟随角色”。入水点和波纹出生后固定世界坐标；路径尾流按位移与最小间隔采样，已有泡沫留在走过的路径上。
- 停止前进、离水或离屏时停止新尾流，必要时清空；瞬移不得把两段路径连起来。不要用一张始终固定在脚后的贴片假装已经留在水面的尾迹。
- 轨迹相对角色朝向定义：前、后、左右外侧和上方。转向、反向游动后仍应正确，不能只写死世界 X/Z。
- 当前拍水的椭圆滴以各手外侧后方为主要方向，少量小滴补充碎散感；先扬起，再在重力下落回。窄锥控制主要方向，适量随机改变散开角度、尺寸和寿命，避免整齐重复或大量向前乱喷。
- 本项目 Cocos 粒子锥体沿局部 `-Z` 发射；旋转要结合根节点朝向核对。用实际粒子的速度分量验证方向，不能仅凭欧拉角数值推测。
- 粒子方向、身体前进和相机跟随共同决定屏幕轨迹；验证至少包含左右手、正反向和转向，必要时对照世界坐标记录。

## 美术与可见度

- 正式效果使用美术纹理、序列帧、少量池化粒子或固定网格材质动画。不要用大量运行时 Graphics 路径拼水花、环、柔光、渐变或速度线。
- 水片负责清晰的入水轮廓，少量大滴表达方向，细滴提供碎散，波纹和尾流表达水面残留。避免所有层同尺寸、同速度、同寿命，也避免为丰富度无节制叠层。
- 单次水片通常只需一张；图集播放展开、破裂和消失。不要在短时间连续补发多张大水片造成白块或贴纸堆叠。
- 在正式比赛镜头和实际显示尺寸下看效果。近景能看见不代表正常比赛能看见；检查水面反光、角色身体和泳道绳遮挡、深度测试、排序及透明材质。
- 可见度由贴图 alpha、材质 tint、起始颜色、寿命透明度、尺寸曲线、拉伸长度及混合方式共同决定。多项相乘可能把有效轮廓压到很小；不要只看粒子数量大于零。
- 粒子应保留足够长的可辨识阶段，再淡出/缩小。标称寿命 0.3 秒不等于可见 0.3 秒，尺寸在 72% 生命周期已归零就会提前消失。
- 检查水滴长宽和拉伸长度，避免变成很大的规则椭圆。细滴宜复用已有纹理与系统，通过出生尺寸/寿命区分；不要仅为几颗小点新建一套系统。

## Cocos 3.8.8 已验证的易错点

| 问题 | 制作和检查方法 |
| --- | --- |
| 代码创建的粒子模块为 null | 运行时不会像编辑器那样自动补齐所有模块。当前实现通过公开类注册创建 Shape、ColorOvertime、SizeOvertime、TextureAnimation；Shape 调用 `onInit(system)`，其他模块绑定已就绪的 processor。初始化保持幂等。 |
| 异步加载完成后 processor 未就绪 | 在配置依赖处理器的模块前保证节点激活、组件 onLoad 已完成；还要校验对象有效性和销毁状态。不能只判断纹理加载成功。 |
| 几乎透明 | `AlphaKey.alpha` 在本项目引擎中使用 0～255，写成 1 几乎透明。其他 API 的范围分别核准，不能把这个单位套给所有 shader 参数。 |
| 宽高参数看似无效 | 分别设置尺寸时启用 `startSize3D`；检查生命周期尺寸曲线与 renderer 的拉伸系数。 |
| 刚设置的方向/长度被改回 | 审查完整初始化顺序和所有写入点。`applyParticleTexture` 曾把手部长度覆盖成通用值，最终绑定须保留分类配置，并在运行时读回确认。 |
| 水片过曝变白块 | 检查纹理、材质 tint、shader 乘数和混合方式；当前使用引擎已有 alpha-blend 技术，不能假设默认加法适合所有透明素材。 |
| 资源没更新却以为代码没效果 | 查实际加载版本、资源 UUID 与运行时参数。只在已授权的现有 Creator 会话内触发导入；不擅自启动或重启编辑器。 |

同一粒子系统可在一次接触内分批设置出生尺寸/寿命，分别发主滴和细滴；已发粒子应保留其出生参数。模块或材质级参数可能影响全部存活粒子，不可把它们当成独立单粒子参数。复用系统后检查其他入口是否完整恢复自己需要的配置。

## 微信小游戏性能与联机

- 制作前记录峰值系统数、粒子容量、单次发射量、寿命、同时可见角色数、材质/纹理和透明覆盖面积。发射器没增加不代表没有成本，增大水片会增加 overdraw，增加细滴会增加模拟和填充。
- 复用节点、系统、材质、向量和采样缓存。不要在比赛更新中创建数组、Color/Vec、闭包或格式化调试字符串；曲线和模块在初始化阶段构建。
- 入退场使用短时 Tween，结束释放引用；不为一次入场加常驻 update。Label 只在最终显示值改变时赋值，读数通常不超过 10Hz；装饰投影/复杂 UI 采样通常不超过 30Hz，不影响游戏模拟频率。
- 普通 HUD 不逐帧 `Graphics.clear()` 重绘。隐藏调试 UI 在格式化、投影和绘制前返回；离屏特效暂停发射与模拟并按生命周期清理。
- 背景 AI 可保留简化层级，具体预算沿用当前配置。不要为了与主角完全一致自动扩容所有选手。
- 纯视觉随机可使用 `Math.random()`；不得影响加速、能量、判定和名次。远端特效消费已同步的可见动作/状态，接触检测只生成外观，不借机新增游戏判定或网络消息。
- 单机原玩法保持不变；如确需修改同步状态，先按 AGENTS 阅读联机架构文档。日志和诊断采样只用于验证，不留在正式比赛热路径。

## 资源、验证与交付

- 源稿、导出脚本、预览和 GIF 放在运行时资源目录外。沿用资源统一路径与原 `.meta`/UUID；比赛子包资源按现有目录和压缩策略维护，不把大纹理复制到主包。
- 新增/重导 PNG、JPG、GLB 后等待 Creator 生成元数据，再运行 `npm run textures:fix` 和 `npm run textures:check`。没有资源改动不重复生成纹理。遵守压缩 mip 链与回退要求。
- 修改运行时 TypeScript 后运行固定版本检查：`npx --yes --package typescript@5.4.5 tsc --noEmit --ignoreDeprecations 5.0 --skipLibCheck`，Windows 使用 `npx.cmd`。
- 回归围绕行为写：重复显隐、快速开关、取消触摸、销毁后的异步回调；水花验证真正接触、左右/反向、瞬移恢复、普通划水与判定反馈、发射预算。已有相关测试位于 `tests/lobby-motion.test.cjs`、`popup-motion.test.cjs`、`race-hud-status.test.cjs`、`swimmer-splash.test.cjs`；测试环境按现有 harness 提供依赖。
- 实录先确认实际加载新版，再录普通速度、左右交替、近景与比赛视角；涉及转向、起跳、静止时额外录对应场景。必要时记录事件帧、接触点、速度、出生尺寸和存活数量。
- 检查完整运动序列，不仅挑最明显的一帧。GIF 标明实录、慢放或概念预览；不得把生成示意图当游戏验证，也不得把近景验证说成全部比赛视角通过。
- 遵守 AGENTS：不截图 Cocos Creator 或由其启动的预览窗口；独立浏览器录制使用当前授权范围。已有本次授权可继续执行，不把一次会话授权写成永久全局权限。
- 桌面类型检查、单元测试和浏览器实录各自说明范围。iOS/Android 微信真机的透明排序、帧耗、包体与手感仍须真机确认，不能用桌面结果替代。

## 每次交接应留下什么

记录效果目的与真实触发源、坐标/方向、参数单位、资源与代码入口、峰值预算、取消/重置行为、联机影响、已完成和待完成验证。通用经验更新本文，场景专属参数更新对应说明；不要把临时脚本路径、本机绝对路径或一次截图当成可复现的共享制作流程。
