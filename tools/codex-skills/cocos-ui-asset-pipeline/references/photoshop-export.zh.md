# Photoshop 定稿与透明切图

## 找到正确源文档

- 先读 PS 状态，再核对文档完整路径、画布和层树。相似标题、未保存的历史窗口、当前活动文档都不能单独证明它是定稿。
- 修改用户指定的原 PSD；临时副本只用于导出/实验，用后关闭且不覆盖源文件。不要另建“最终版2/3”代替维护。
- 交付组按功能命名，文字、按钮底图、图标、头像、选中态独立。冠军/亚军/季军/普通等必要状态是最终设计的一部分，不能作为过程稿删掉。
- 清理前核对最终可见效果和引用；先确保可恢复副本，再移除确定废弃的过程图层。不要顺手清理其他打开的文档。

## 导出顺序

1. 复用资源先解析原路径；只导出真正新增/修改的目标。
2. 在临时副本中隔离目标分支及必要父组，隐藏无关兄弟节点与动态文字。按钮导出前尤其检查智能对象内的文案。
3. 记录原始画布位置、裁剪矩形、可见边界、外发光范围及原层级。不要只记宽高。
4. 按源形状实际属性栅格化；保持填充、描边、样式不透明度。检查依赖底层内容的混合模式，独立 PNG 的普通透明合成不一定复现 PS 混合效果。
5. 导出 RGBA PNG，深/浅背景分别合成检查。透明像素可能保存高亮 RGB，不能仅凭查看器的透明显示误认成实心色块。
6. 在真实大小和缩放大小核对边缘；保留现有 `.meta`、源文件和原资源路径。按项目工具无损优化后再检查纹理政策。

## 本人绿框的已验证故障

划水大师结算 `row-self` 曾只剩外发光，游戏出现深色内圈，原因是导出时把原矢量形状的 `fillOpacity` 强制设为 0，实色描边也随之消失。

- 修复是保留源值，在临时副本栅格化后重新导出；不是补一个代码黑/绿描边。
- 保持原 PSD 的外框与底板顺序。该页面 `SelfHighlight` 位于行底板下方；别将这一顺序推广到所有选中框，其他素材须查看自己的原图层。
- 切图含外扩柔光，不能拉伸成行底板尺寸。此次行底为 615 × 68，描边画布 666 × 117；具体偏移留在导出脚本和页面文档，不跨页面照抄。
- 回归时检查第 1/2/3/普通名次的本人标记、层级、尺寸与唯一可见状态；真实 PNG 合成确认实色边仍在，不能只用代码字符串断言证明视觉正确。

## 避免工具级失误

- PS 工具的预览质量、导出格式等按当次工具 schema 使用；预览 `quality` 曾为 1–12，不能想当然传 80。
- 调用依赖 activeDocument/activeLayer 的操作前重新取状态。脚本显式返回结果；失败后先检查残留临时文档，不盲目重跑整批导出。
- 未修改 PS 设计只重新导出正确图层时，不需要保存成新版本，也不要把临时栅格化回写给源矢量。
