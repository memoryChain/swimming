# 真机 UI 适配修复（2026-09-07）

对应 Android 2400×1080 与 iPhone 2532×1170 截图反馈。

## 变更

- 大厅左右面板、模式卡和按钮，以及角色页列表、详情和确认区，分别放入稳定的左右控件组。组内保持原设计坐标，用 `Widget.ON_WINDOW_RESIZE` 对齐完整 Canvas，显式关闭整栏系统安全区缩进。宽屏大厅两侧额外留白均为 48，角色页左侧为 48、右侧为 60 个设计单位；16:9 保持原始间距。控件本身的设计留白另计。
- 根据灵动岛遮挡反馈，左右面板都在上一版基础上向内增加 24 个设计单位，不只移动当前遮挡的一侧。手机横屏翻转后，两边仍保留这段额外空隙；角色右栏延续原稿比左栏多 12 的定位补偿。实际灵动岛边缘的净空仍需双向横屏真机确认。
- 登录场景的 Canvas 原本只有固定 1280×720 UITransform。共用布局入口在初始化及窗口变化时同步可见尺寸，并在销毁时注销监听；不移动 Canvas，不改变相机或角色预览。
- 顶部头像栏和金币栏跟随完整屏幕左右边界，头像栏不再叠加系统安全区；微信胶囊继续单独避让，预留比例乘实际可见宽度。
- 角色页复用大厅的 cover 背景，去掉第二张固定尺寸背景，消除宽屏黑边。
- 角色及房间的标题装饰贴屏幕左上角；标题文字、返回图标和点击区域与三角装饰共用一个适配组，保持原稿相对坐标。不能再给标题控件单独叠加左侧安全区，否则文字会向右越过三角斜边。
- `header-bg.png` 和 `right-shade.png` 原为 repeat 采样；改为 clamp-to-edge，防止另一侧颜色在线性采样时污染边缘。保持贴图内容、UUID 和压缩预设。
- 项目字体不再强制使用有限的共用 CHAR 图集，改用 `CacheMode.NONE` 的独立文本纹理；静态中文继续使用随包字体。昵称使用系统全覆盖字体，并防止晚到的字体回调覆盖新字重或动态文本设置。

## 验证与边界

- TypeScript 5.4.5 类型检查；房间与结算运行时回归；字体生成与审计；纹理策略审计。
- 布局替身测试覆盖 16:9、19.5:9、20:9、固定 Canvas 初始化、刘海避让与监听清理；字体测试覆盖异步回调乱序、动态昵称、关闭面板以及重复创建。
- 上一版仅把安全区相加改为取较大值，仍会以较大的系统安全区限制侧栏，用户真机反馈未解决。本版在页面调用处关闭整栏安全区约束，而不是继续改其计算系数。
- 新回归直接执行生产代码中的大厅及角色页面布局入口，覆盖 1280×720、2400×1080 和 2532×1170 比例；令系统安全区接口抛错，确认这些页面布局不再依赖它。通用布局工具的可选安全区功能仍单独测试。未读取用户真机运行时数值，未以模拟测试代替真机验收。
- 控件组只在创建和窗口事件时布局。没有增加比赛帧更新、网络协议或比赛数据变更。现有角色、难度和房间状态更新仍沿用原有局部更新路径。
- 未启动 Creator、未截图或执行微信真机。需要在已有 Creator 中完成字体及两张贴图元数据的导入，再重新构建并复测这六处表现。字体缓存改变后也应观察 Android/iOS 页面绘制开销；自动化测试不能证明真实 GPU 字体渲染和采样结果。
