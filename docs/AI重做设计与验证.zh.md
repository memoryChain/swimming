# 角色 AI：规则、策略与验证

## 已确认的边界

- 身体能力 = 角色定义 + 1～30 级成长；与玩家共用属性解析、起跳、划水、心率、体力、蓄气和固有能力。智力不改物理参数。
- 赛事独立配置等级段和智力阵容，不读取玩家存档决定对手强度。标准／狂野与 200／400 米不是智力档位。
- 四个正式档：新手、普通、高手、专家；额外提供仅测试使用的变态档。
- 取消根据玩家差距偷偷提高准确率或补偿速度。允许对所有附近对手争位、冒险冲刺，正常支付体力和心率代价。
- 只通过按下、保持、松开、短按踢腿、技能请求控制泳者。不得直接写速度、位置、体力或判定结果。
- 体力不会恢复；踢腿用于节省后续体力并降低心率。心率缩窄 PERFECT 区间，不能把降心率当成直接加速。

## 身体与智力

每位 AI 有稳定的 `characterId / level / intelligence`，模型、体重、蓄气资质、心率特性与能力均取这个角色。体力、技巧、爆发力采用玩家同一成长函数。

智力分开配置：松手误差、出发蓄力范围、划间停顿、踢腿频率、决策间隔、预算纪律、技能判断与转向可靠性。PERFECT 比例是这些输入在真实判定区间下产生的结果，不预先发放 PERFECT。

变态档使用满蓄力、最小合法输入间隔、无随机松手误差和更频繁的策略评估。它仍受动作占用、输入分类、真实判定、心率、体力和技能资格约束。该档是当前算法的极限基线，不声称求得数学上的全局最优。

## 决策顺序

1. 结束、远端真人、隐藏对象不决策；转身与技能阶段服从共享动作锁。
2. 出发与折返水下段按玩家规则踢腿；恢复可划水时重新开始输入周期。
3. 读取自己的资源、当前赛程、距下一面墙的距离、速度和可观察的附近对手。
4. 按剩余距离建立体力预算，预留最后冲刺；400 米相同体力需要更大的踢腿占比。
5. 按角色心率目标和恢复阈值选择持续划水、控制划频、踢腿恢复或冲刺。采用最短保持时间与进入／退出阈值，避免每帧反复切换。
6. 满气后评估技能资格、完整空间、体力成本、心率负担与冲刺预算。低智力允许犹豫或较差时机，但不能绕过共享拒绝条件。
7. 狂野模式对附近所有选手采用争位／避让；正常转向优先回正，无读玩家输入或未公开未来状态的能力。

## 逐角色策略

| 角色 | 主策略 | 资源与技能取舍 |
| --- | --- | --- |
| 蛙妹 | 稳定持续划水 | 利用宽判定区间容忍较高心率，避免为追求过低心率而频繁停手；保留末段体力。 |
| 蛙少 | 分段划水、频繁小跳 | 正常支付较低跳跃成本；空间够就积极释放，避免满气浪费，不套普通角色的大跳距离。 |
| 超级腿 | 踢腿与短划段交替 | 强腿用于长程巡航和降心率，最后把剩余体力用于有收益的划水。 |
| 猫姐 | 灵活巡航、避开重型对手 | 快升快降心率适合短恢复；被撞后利用恢复优势继续比赛，不长期追撞。 |
| 忍者哥 | 精准优先 | 较低目标心率，保护狭窄 PERFECT 区间；高智力更能发挥强奖励，低智力依然会失误。 |
| 健身教练 | 节奏管理 | 正常阶段控制在呼吸管理划频门槛内；必要时冲刺突破门槛并承受代价。 |
| 飞毛腿 | 折返驱动的分段配速 | 保留蹬墙后的高速滑行，临墙避免投入不能完整兑现的海豚跳。 |
| 潜水哥 | 潜航避碰 | 踢腿潜航兼顾省力与避碰，划水按规则上浮；禁止海豚跳。 |
| 风火轮 | 连续精准划水 | 将恢复集中成段，减少频繁中断连击；连击收益不能凌驾于耗尽风险。 |
| 机甲 | 持续输出 | 划水免体力成本，预算不限制；仍处理心率和判定，禁止海豚跳。 |
| 肌肉男 | 爆发与有限争位 | 低体力、慢恢复要求提前预算；狂野模式利用重量争位，避免为撞人绕远路。 |

## 验证与完成条件

- 全角色、不同等级、四个正式档和变态档覆盖 200／400 米；记录成绩、PERFECT、踢腿时间、体力余额、耗尽时间和海豚跳次数。
- 同种子复现阵容和决策；联机按共享赛事配置生成身份，房主校正可见状态及体力比例，远端真人不受 AI 操作。
- 检查同角色同等级属性一致、禁跳角色、折返空间、400 米预算、满气不重复扣费、重赛重置和隐藏对象早退。
- 离线测试只证明所覆盖的运动／策略逻辑；碰撞、多端网络、实际场景成绩以及 iOS／Android 性能仍需真机验证。

## 已接入的参数与入口

| 智力 | 出发蓄力范围 | 松手误差标准差（动作圈比例） | 划间停顿秒 | 踢腿频率上限 | 决策间隔秒 |
| --- | --- | ---: | ---: | ---: | ---: |
| 新手 | 0.35～0.72 | 0.100 | 0.200 | 3Hz | 0.60 |
| 普通 | 0.62～0.87 | 0.060 | 0.120 | 4Hz | 0.40 |
| 高手 | 0.80～0.96 | 0.027 | 0.060 | 5Hz | 0.25 |
| 专家 | 0.93～1.00 | 0.009 | 0.025 | 6Hz | 0.15 |
| 变态（测试） | 1.00 | 0 | 0 | 8Hz | 1/30 |

正式档另有随机划间停顿；实际手臂开始还须经过共享长按分类和动作占用检查。变态档允许在前一划结束前预按另一侧，重叠部分分类等待，仍完整等待共享分类时长。技能预算允许拒绝满气请求；禁跳角色始终由能力资格拒绝。

所有正式入口当前指向 `AI_EVENTS.club`（1～5级，新手／普通／高手混合）。另备 `regional`（8～15级）与 `elite`（20～30级），通过 `AI_EVENT_BY_MODE` 配置；没有加入基于玩家存档的追级。正常赛事不会抽到变态档。

进入大厅后，在左下方“角色养成”按钮下面点击“AI 测试”；登录封面不再显示此入口。可以选择全部角色、1～30级、标准200米／狂野200米／狂野400米与固定种子，再点击智力档开始。默认是7个AI对手＋玩家的8人测试赛，也可切成1个AI对手的2人赛。7个对手可以选择“多角色混合”（7个不同角色）或“全部同角色”；所选等级、智力应用于全部AI，玩家保留自己的角色属性。单对手使用指定角色。此入口在预览和小游戏中均显示；打开或关闭设置弹框不重建大厅、不重载角色预览。角色、等级、人数和赛制按钮只更新对应文字，连续切换不创建新节点或加载模型。相同种子在调试重赛倒计时重新播种，阵容不重抽。本地测试选项不覆盖联机阵容。

弹框完整继承 Popup 专用画布的渲染层，不能再覆盖为主画布的 UI_2D，否则不同相机原点会让面板偏至左下角。全屏遮挡拦截触摸，880×620面板按可见屏幕等比缩放并居中；窗口变化才更新尺寸，关闭时移除监听。回归执行真实登录入口并验证专用层、四种屏幕尺寸、反复打开关闭，以及真实比赛创建入口在所有玩家泳道下分别生成1／7个对手和对应角色等级。

测试赛点击“玩家 · 查看AI”后，按玩家→AI 1→AI 2→…→AI 7→玩家循环观战（单对手为玩家与AI切换），按钮显示当前AI序号。镜头、HUD与诊断面板始终使用同一选中对手，自动跳过淘汰、失效或远程选手；重赛与玩家完赛恢复玩家视角。HUD读取当前AI的速度、心率、体力、赛程进度、蓄气和技能资格，排名头像突出该AI。左右手标为“AI 左划／AI 右划”，显示真实AI输入的按下、松手、动态完美区、结算评价与连击；短按踢腿也有按压反馈。海豚按钮保留就绪显示但只读，玩家的触摸仍只控制玩家，不会操纵AI或覆盖观战反馈。切回玩家立即恢复玩家读数及真实按压状态，清理旧反馈和订阅；重赛、隐藏和离开时不残留。数值保持10Hz、划水显示30Hz采样，无比赛帧新增节点或临时快照；本地观战设置不影响联机或AI决策。验证包含反复切换、禁跳／无限体力角色、只读技能按钮、隐藏零反馈，以及有无展示订阅时AI成绩与资源完全一致。

玩家和AI头顶的旧PERFECT圆盘均已移除，统一使用HUD手掌完美区。AI信息面板默认折叠为“AI 信息 · 展开”小按钮，展开后右上角可“收起”；收起时隐藏底板、阵容和诊断，停止诊断采样与文字更新，展开立即读取当前观战对手。按钮节点及监听只创建一次，折叠状态不影响镜头、HUD和比赛逻辑。AI信息面板放在左侧数值区右边、赛程进度条下方：按1280×720基准左边距244、顶部90、宽360，逐行22高；7个AI加两行诊断最高276，不压住下方手掌弧线。面板跟随HUD的安全区缩放，仅窗口变化时重定位。诊断保留策略、体力预算、冲刺预留、踢腿时间与海豚跳次数，体力和心率直接看HUD。

调试赛自动显示角色等级、智力和策略诊断：持续划水／省体力／降心率／冲刺／潜航避碰、当前体力、心率、预算、冲刺预留、踢腿时长与技能次数。诊断每秒最多5次，相同文字不重写；隐藏和正式比赛不生成诊断快照。

`TuningDebugControls.ts` 的 `aiPlan.*` 提供预算倍率、目标心率偏移、冲刺距离倍率、踢腿保持时长倍率和跳跃空间余量，可按原流程保存到 `tuning.json`。已退役的追赶、性格和统一难度倍率不再参与计算，旧存储键被兼容忽略。

## 联机和生命周期修正

- AI身份、等级和智力按完整泳道表生成，再跳过本地玩家槽位；不同设备的同一泳道解析同一身体能力。
- 体力快照继续传比例，各端以角色等级对应的上限还原。房主迁移延续已有状态，不恢复体力。远端真人始终不执行AI输入。
- 所有AI在倒计时重置；玩家晚跳不再清空AI已发生的资源消耗。重新分配角色会更新能力、总量和策略，局内调参重算运动倍率不会重启AI或补体力。
- AI互撞也服从双轴阻挡和击退，取消原有只做横向分离的例外。
- 玩法协议升至45；没有增加包字段，同场所有客户端须更新到同一版本。
