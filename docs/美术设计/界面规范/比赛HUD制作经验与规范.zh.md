# 比赛 HUD 制作经验与规范

整理日期：2026-09-08。依据本次设计修订、[统一界面规范](界面制作规范.zh.md)与仓库 UI 技能整理。本文记录视觉设计和交付经验，不代表所有交互已实现或通过真机验证。最新用户要求及项目 AGENTS.md 优先。

## 一、设计原则

比赛画面和操作判断优先，UI 帮助玩家看懂状态，不能抢占角色动作、前方泳道与节奏观察区域。游戏定位是轻松休闲竞技；机甲角色不等于科幻 UI。

- 信息靠边布置，中央保留比赛视野。先减少底板、描边和无关装饰，再考虑缩小必要信息。
- 重要性通过字号、明度与状态变化区分，不靠所有控件同时放大、加白圈或发光。
- 先用一个典型比赛画面确定风格，再扩展其他状态和界面；局部修订不重做全页。
- 真实游戏截图用于检查遮挡和可读性，不能只在纯色背景上判断效果。

## 二、已确认的视觉组织

| 元素 | 制作要求 |
| --- | --- |
| 速度 | 左上突出显示，硬朗粗体；单位弱于数值。专用字体为 ShuiMasterSpeed-Heavy，不能用近似字体替代。 |
| 心率、体力 | 左侧偏上，以心形、闪电与圆环表达；环宽一致。心率过高使用独立警示状态。 |
| 泳程 | 顶部细进度条，米数在条的一侧；不重复设置顶部蓄气条。 |
| 右侧名次 | 贴右侧边，顶部“排名”；只放头像和贴近头像的名次，本人适度放大并加亮圈。 |
| 泳道内玩家信息 | 名次加紧凑正圆底，与名字并列；名次数字字体与右侧列表一致，避免遮挡角色和互相重叠。 |
| 起跳 | 右侧偏下；蓄气使用与心率、体力同粗度的圆环，满蓄气时中心具有明确按钮形态。海豚朝左。 |
| 节奏线 | 左右严格镜像、倾斜排列，避免与操作控件交叉；两端渐隐。完美区是一段靠近下方尾端的连续区域。 |

颜色沿用定稿：半透明深灰蓝承托，青色表达进度，黄绿色表达完美区，金色强调本人或可操作状态，红色表达异常。具体色值、尺寸和位置读取当前主 PSD，不把概念稿估算值固化为标准。

图标统一简洁、略可爱的剪影，检查实际小尺寸轮廓、视觉重量和留白。心形、闪电、手掌、海豚沿用认可素材，不混用写实图标、细线图标和复杂剪影。

## 三、交互与状态边界

- 历史稿表现为按住按钮后白点沿线移动，进入完美区间表示完美划水。完美区必须有起止范围，移动线条时连同区段一起移动；左右独立状态不能被强制同步。
- 当前项目显示半透明手掌按钮与动态完美区弧线，触控范围保留整个左右半屏；玩家自行选择左右手，不自动交替。显示只消费已有划水进度和松手判定，不改变玩法。
- 松手、越区、重复触发等判定以实际玩法为准；区段长度和白点运动由规则驱动，不能用设计坐标定义游戏平衡。
- 每个动态控件记录正常、进行中、可用、按下、异常等适用状态，并说明触发条件；未确定状态应标明待对齐，不擅自补玩法。
- 视觉尺寸与触控热区分开定义。静态高亮不等于已实现点击，静态红色也不等于已实现闪烁。

## 四、字体、素材与比例

### 划水评价：位置、字形与等级递进

本轮已确认圆润文字的静态方向及绿色完美区右侧的位置，并认可随连击升级增强表现的方向。分档动效、扫光和星点尚未完成接入或真机验证；不能把方向确认写成已实现功能。

**位置与风格**

- 评价贴近弧线下方尾端的黄绿色连续完美区，不能跟着上方移动圆点定位。本轮左侧示例明确放在绿色区段的右边，与区段大致同高并留出间隙；不是移动到屏幕右侧。右手对应位置须另行检查遮挡和边缘空间，不从左侧单张预览推断已确认布局。
- 字形饱满、圆润、基本直立，保持休闲竞技的亲和感；粗斜体容易显得硬朗，不能沿用速度数字的风格来制作评价。采用明亮颜色和克制的细描边、短阴影，避免厚重立体字、大白边和霓虹光团。
- 本轮 PS 静态稿使用 Arial Rounded MT Bold 制作英文评价。这是设计参考，不代表该本机字体已获准或已随游戏打包；运行时字体仍须符合项目字体政策，不直接依赖本机字体或用描边冒充字重。
- 长词尤其是 Unbelievable 要逐项检查角色、手臂和节奏线遮挡，必要时适度缩小字号；不能为统一字号而挤占操作观察区域。

**评价与连击的对应关系**

这里的升级依据是连续 PERFECT 的次数（连击），不是联机次数。以下为当前 HUD 文案映射；七种展示文案不增加底层划水判定档位。

| 文案 | 当前触发条件 | 已认可的表现递进方向 |
| --- | --- | --- |
| Good | GOOD 划水 | 绿色圆体，轻弹。 |
| Great | 连续第 1 次 PERFECT | 青色圆体，轻弹。 |
| Excellent | 连续第 2 次 PERFECT | 紫色，适度强化弹出并增加少量星点。 |
| Perfect | 连续第 3 次 PERFECT | 金黄色，适度强化弹出并增加少量星点。 |
| Amazing | 连续第 4 次 PERFECT | 橙色，略微放大，短促扫光和星点。 |
| Crazy | 连续第 5 次 PERFECT | 粉色，略微放大，短促扫光和星点。 |
| Unbelievable | 连续第 6 次及以上 PERFECT | 暖金色，最高档强调，可增加一次轻微回弹。 |

GOOD 会中断连续 PERFECT；失误也会中断，但当前 HUD 不显示负面评价。展示逻辑以 `assets/scripts/ui/UIController.ts` 为依据，不因美术升级改变得分、推力、能量、统计或联机判定。

**华丽程度与性能边界**

- 华丽程度主要来自出现瞬间的动效，不靠常驻文字持续变大。高档文字的视觉增幅以约 10%–15% 为初步设计范围，仍须按最长文案和实际画面调整；这不是已验证的运行时参数。
- 较强效果只在首次升档或连击里程碑触发；普通后续划水保持轻弹。里程碑间隔尚待实现时确认，不擅自固化具体数字，也不每次高等级划水都触发全套闪光。
- 星点、扫光等使用小图集、少量复用精灵或项目批准的低开销资源方案；不能用每帧 Graphics 重绘、多层光晕或临时创建大量节点实现。
- 动效由评价事件触发，不能从每帧更新反复启动 Tween；隐藏时零帧工作。接入时评估透明叠层、填充率、draw call、分配及 iOS 微信小游戏表现。
- 效果属于本地表现，不新增影响比赛结果的随机性或同步数据；联机时消费现有玩家判定结果，单机判定保持不变。

**设计验证与交付**

- 先用一个有代表性的评价在真实截图上确认位置和风格，再扩展七种评价；总览包含完整界面示例与全部局部效果，不能只展示脱离场景的字样。
- PS 保留七种独立、可编辑的文字状态，并让界面示例一次只显示一种；装饰与文字分层，方便后续调整。不能把生成的整张截图作为可编辑 UI 成果。
- 本轮交付文件为 `比赛HUD-1280x720.psd`、`划水评价总览.psd` 和 `划水评价总览.png`。路径以实际打开文档为准，不在共享规范中固化个人桌面绝对路径。
- 概念图生成后在 PS 中复现，仍需重新核对字形、字重、间距和实际尺寸。每次续做先确认当前文档与层树；缺少预期状态组时先核对源文件，不盲目重跑脚本或覆盖用户修改。
- 静态总览只能确认排版、颜色与装饰密度，不能证明弹出、回弹或扫光效果。获得游戏接入授权后再修改运行时资源和代码。

### 通用字体与素材检查

- 速度字体必须核对实际字体文件、字重与字符覆盖。已发生多次“安装后仍不像原稿”的问题，安装成功不等于文字层已使用正确字体。
- 静态通用中文使用随项目打包的 ShuiMaster UI 字体。现有 PSD 排名数字为 PingFangSC-Semibold；运行时须落实批准的可分发字体，不能依赖设计电脑本机字体。
- 玩家头像与角色卡立绘是不同素材入口；使用当前正式资源并核对映射，不能继续使用临时图或按文件名猜身份。
- 圆环、名次底和头像保持正圆，适配时不能非等比拉伸。先检查透明边距、实际圆心与内径，再定位外框。

## 五、Photoshop 制作与保存

- 后续新页面为 **1290×720 px、RGB、72 DPI**。旧 HUD 的 1672×941 主稿与用户要求的 1280×720 副本保留原用途，不混淆三种尺寸。
- 每页维护固定主 PSD，就地修改并及时保存。操作前读当前路径、尺寸、层树与可见状态，保留用户手动修改。
- 按功能分组；文字、图标、底板、圆环、进度、本人强调和异常状态独立。文字可编辑，形状优先矢量，头像使用智能对象。
- 对称线条用同一几何源镜像；完美区、端部渐隐与线条一起维护，避免单独拖动导致错位。
- 原始比赛截图与旧 UI 局部修复分层保留，不改动无关场景。参考图层隐藏，不能混入最终导出。
- 仅在临时副本扁平化导出预览。正式切图分离按钮背景、图标与文字，不能烘焙按钮文案或比赛背景。

## 六、反复修订得到的经验

| 出现的问题 | 后续做法 |
| --- | --- |
| UI 过于科幻、白边和排名板抢眼 | 先减少视觉重量，围绕休闲竞技定位统一组件。 |
| 字体看起来不一致 | 核对真实字体与字重、文本层设置及缩放，不用描边模拟粗体。 |
| 左右线不对称、与按钮交叉 | 用画布中轴校验镜像关系，线、完美区与渐隐整体调整。 |
| 将完美判定画成一个点 | 先理解操作过程，再设计连续判定区和移动指示。 |
| 评价靠近移动圆点，或放错完美区一侧 | 以尾端绿色连续区段定位；按用户标注确认区段左右侧，不把“右边”理解成屏幕右侧。 |
| 评价粗斜体过于硬朗，七档仅换颜色 | 改为圆润字形；按连击分档设计瞬间反馈，较强效果限制在升档和里程碑。 |
| 圆底变成椭圆 | 检查组变换与非等比缩放，不只检查源形状宽高。 |
| 海豚、心率、体力风格不一 | 固定已确认剪影与环宽体系，以小尺寸效果验收。 |
| 误用临时角色图 | 对照当前资源引用与正式素材，不以旧桌面文件为唯一依据。 |

## 七、交付与接入检查

设计交付前检查：比赛视野、实际尺寸可读性、字体、正圆、头像裁切、左右镜像、完美区间、图标方向、状态互斥、主 PSD 保存及最新预览。

只有获得接入授权才修改游戏资源。运行时要求：

- 文本与控件属性只在显示值变化时更新；普通读数通常不超过 10Hz，屏幕跟随标签通常为 30Hz。
- 不每帧重绘 Graphics，不用大量程序图形模拟渐隐与光环；复杂效果采用美术资源或已有低开销方案。
- 隐藏 HUD 不做比赛帧工作；稳定层级和监听只建立一次。
- 排名和玩家身份读取权威状态，不能固定绑定头像顺序；单机与联机分别验证。
- 按项目政策完成字体、透明通道、资源映射、纹理和包体检查。真实设备的遮挡、触控与性能仍需验证，离线预览不能代替真机验收。

比赛开场卡片属于独立页面，其泳道号码牌、赛制条和本人标签不直接推广到比赛中 HUD。
