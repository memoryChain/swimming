# 划水大师界面制作规范

本规范依据比赛 HUD 的已确认设计与用户修订整理。后续界面制作先读本文，再读具体页面源 PSD；用户最新要求优先。通用风格与制作方法适用于新页面，比赛 HUD 的控件和交互不强行套用到大厅、联机或结算页。

## 画布与源文件

- **后续新界面统一使用 1290 × 720 px、RGB、72 DPI。** 1290 是用户最终指定宽度，不自动改成 1280 或标准 16:9。
- 已有比赛源稿为 `docs/美术设计/界面方案/race-hud-style-study/比赛HUD.psd`（1672 × 941）；用户另存的 `比赛HUD-1280x720.psd` 是尺寸副本。保留两份，不能把另存副本误当作后续新页面尺寸规范。
- 每个界面维护一个固定主 PSD；后续修改在同一个文件内进行，每次完成一组有效修改及时保存。只有用户要求另存尺寸或版本时另建副本。
- 操作前核对 Photoshop 实际文档路径、尺寸、层树、可见状态。用户可能在 PS 中自行调整，不能用旧脚本或旧文档覆盖当前状态。
- 旧稿适配新画布时等比缩放元素后重新排版、检查安全区；不要非等比拉伸圆形、头像与文字。

## 视觉方向

- 轻松、清爽的休闲竞技风格，可参考圆梦之星等游戏的亲和感与简洁度。机甲是角色设定，不能因此将 UI 做成科幻仪表、霓虹面板或机械边框。
- 比赛画面优先：保护主角、手臂动作、前方泳道和节奏观察区域。信息贴近屏幕边缘组织，中央只留必要反馈。
- 避免大片白底卡片、粗白描边、大面积排名底板、强发光与无关装饰。浅色文字或图标可用轻微阴影提升可读性，不堆叠外框。
- 常态控件使用克制的半透明深灰蓝底；青色表示状态/进度，黄绿色表示完美区，金色强调本人或可操作状态，红色用于心率过高提示。不是每个按钮都要做高亮金底。
- 新页面复用已确认组件和真实资产；用户只要求局部修改时不擅自改全页风格、布局或交互。

## 图标、字体与头像

- 图标统一简洁、略可爱的剪影造型：少细节、轮廓清楚、同类笔画/体量一致。看实际小尺寸效果，不只看放大稿。
- 心率为心形，体力为闪电，划水为手掌；海豚以已确认 PSD 轮廓为准，长吻、厚实头背、向下弯的身体、宽尾鳍，朝左。已有定稿图标直接复用，不每次重新生成。
- 数字和文案保留真正的文字层。实际字体名称、字重和缩放必须核对，不以近似字体、描边、叠字或像素风字体冒充原稿。
- 比赛速度使用专用 `ShuiMasterSpeed-Heavy`，源码与字体在 `docs/美术设计/界面方案/race-hud-style-study/fonts/`，覆盖 `0–9`、小数点、`m/s` 和空格。其余字符不保证覆盖；新页面需要新字符时扩展源字体生成脚本。
- 通用静态中文优先使用项目 `ShuiMasterUI-Regular` / `ShuiMasterUI-SemiBold`。当前 PSD 的右侧和泳道排名数字按用户要求统一为 `PingFangSC-Semibold`；这是设计稿现状，不能据此绕过游戏字体打包政策。运行时接入需落实可分发字体和字形覆盖，不能依赖本机字体。
- 头像复用游戏当前真实资源，身份映射以 `docs/开发记录/界面接入/头像设计与裁切接入说明.zh.md`、`IdentityConfig.ts` 和 `ResourcePaths.ts` 为准。文件名可能描述旧形象，不能据文件名猜人物。
- 头像使用独立智能对象，圆外透明，圆心对齐边框，检查小尺寸内缘是否漏缝。正圆底图宽高相等、无透视拉伸；排名数字在圆内居中。
- 静态稿中头像排列仅为示例，不能反推真实玩家身份或将名次固定绑定某个头像。

## 比赛 HUD 的布局与交互

- 左上突出速度，硬朗直立粗体，单位小于数值，不在角色头顶重复显示速度。
- 左侧偏上显示心率和体力，图标配圆环。心率过高有独立警示；闪红属于动态状态，静态稿不能当作已实现的动画。
- 顶部使用细泳程条，米数放条的一侧。顶部不再放独立蓄气条。泳程图标备选不视为全部定稿，实际显示以当前 PSD 为准。
- 右侧排名贴边，顶部写“排名”，仅头像＋数字；数字靠近头像，本人头像与数字放大、保留金色亮圈，不加昵称长条底。
- 泳道内显示“名次＋名字”，名次有紧凑正圆底，普通紫色、本人金色；排名数字与右侧列表使用相同字体。不要盖住角色动作，近远玩家避免标签互相遮挡。
- 历史 HUD 定稿中的左右划水按钮使用弱化手掌图标和半透明圆底。**当前运行时以 AGENTS.md 为准：HUD 显示半透明手掌按钮与动态完美区弧线；左右半屏点按／按住分别操作，不自动交替，触控范围不限制为按钮。** 以下布局仍需核对当前主稿和接入说明，不直接把稿件坐标作为玩法参数。
- 划水线在按钮内侧：**右线在右划按钮左边，左线在左划按钮右边**。线条为倾斜弧线，左右关于画布中轴镜像，与按钮不交叉。
- 线条两端使用可编辑蒙版逐渐透明，中段可辨认；不要用硬截断或一整团模糊替代渐隐。
- **按住对应按钮后，小白点开始沿线移动；进入完美区间表示完美划水。完美区是一段连续高亮弧段，不是一个点。** 区段靠近下方尾端，有起止边界，随弧线移动并左右镜像。旧中心点与横向十字刻度不再显示。
- 静态稿中的左右白点可同高展示；真实交互应分别绑定左右手的状态。区段长度、运动速度与数值判定需来自游戏规则，不将稿件坐标当成平衡参数。
- 划水评价采用圆润、基本直立的字形，贴近尾端绿色完美区；本轮左侧示例确认放在该区段右边，不跟随上方移动圆点。七种文案按连续 PERFECT 次数递进，增强表现以瞬间动效为主；分档动效仍待实现。完整映射、PS 制作及性能约束见 [比赛 HUD 制作经验与规范](比赛HUD制作经验与规范.zh.md)第四节。
- 起跳放右侧偏下，圆环表示蓄气，粗度与心率/体力环一致。满蓄气时内部明确呈现可点击按钮，保留海豚与正常/按下状态；蓄气中弱化。文案、按钮面、图标与进度环分层。
- 松手、越过完美区、长按是否重复触发等尚未在本轮完整确定，不自行写成已确认玩法。接入前需与实际判定逻辑对齐。

## Photoshop 分层与背景

- 按功能分组，控件底、图标、文字、数字、头像、进度、警示与状态分别建层，命名能直接定位用途。底与形状优先用可编辑形状层，头像用智能对象。
- 保留必要正常/禁用/高亮/按下/异常状态；状态组独立开关。修改图层时保留用户设定的隐藏状态，不因变换而意外显示旧元素。
- 背景优先使用用户提供的真实游戏截图。去旧 UI 时保留原图与局部修复层，尽量仅修补旧 UI 覆盖区，保留角色姿态、镜头、泳道、曝光与场景细节。
- 不将整张生成效果图作为“可编辑 UI”；原设计参考层可隐藏保留，不能误混入最终可见层。
- 导出在临时副本执行，不扁平化主 PSD。按钮底、图标、文字分别处理，切图不能烘焙按钮文案或比赛场景。
- 同步导出预览用于对照；预览是设计检查，不是游戏运行、可点击交互或真机性能的证明。

## 完成前检查

1. 对照最新用户要求和当前 PSD，确认没有覆盖用户手动修改。
2. 核对新页面 1290×720、字体、正圆比例、头像裁切、图标方向和文字可编辑性。
3. 检查左右镜像、完美区段位置、线条端部渐隐、与按钮的间距；检查小尺寸和场景上的可读性。
4. 核对各状态单独显示正确，不叠出重复数字/图标，旧参考和废弃控件保持隐藏。
5. 保存主文件、导出最新预览，确认实际文件尺寸和保存状态。

## 接入游戏时的边界

本文记录设计约定，不授权自动接入。接入时继续遵守 AGENTS.md 与仓库 UI 技能：文字变更才写属性、显示降频、隐藏 UI 零帧工作，不逐帧重绘 Graphics，不以大量过程绘制实现光环/渐隐。按钮视觉与触控热区分开验证。联机名次按权威状态和玩家身份显示，不按头像顺序或本地模拟推断。字体、纹理、包体与真机验证按项目政策完成，不自动启动或截图 Cocos Creator。
