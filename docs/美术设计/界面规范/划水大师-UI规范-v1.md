# 《划水大师》UI 视觉与制作规范 v1.1

> 适用边界：本文保留 1280×720 既有页面的视觉令牌与组件经验。后续新页面画布统一为 1290×720；画布、当前 HUD 交互与主 PSD 维护优先遵循 [界面制作规范](界面制作规范.zh.md)，运行时字体、按钮文字与性能遵循项目 AGENTS.md。

适用范围：登录页、大厅、角色选择与养成界面、模态弹窗。  
基准画布：`1280 × 720 px`，横屏 `16:9`，PSD 分辨率统一为 `72 ppi`。  
基准文件：

- `划水大师-login-ui-1280x720-v12-layered-runtime.psd`
- `划水大师-大厅-A版-1280x720-v1.psd`
- `划水大师-角色-ui-1280x720-v2-organized.psd`
- `划水大师-头像选择-1280x720-production-v5-潮玩头像.psd`

## 1. 设计定位

### 1.1 核心气质

- **轻松、明亮、运动感**：以蓝青色环境建立清爽泳池氛围，用荧光黄绿强调唯一主操作。
- **角色优先**：角色模型或主视觉永远是第一视觉焦点；背景保持柔和、低对比和适度景深。
- **信息清晰**：功能卡片保持水平、规整、留白充足，不使用影响阅读的倾斜文字和过度装饰。
- **适度幽默**：幽默感主要由角色姿态、插画和模式内容承担，不依赖杂乱的 UI 造型。

### 1.2 视觉层级

统一阅读顺序：

1. 角色或品牌主视觉
2. 荧光黄绿主操作
3. 当前选择状态或核心信息
4. 次级功能与资源信息
5. 背景装饰

同一屏幕只允许一个最高权重的荧光黄绿主操作。

## 2. 色彩系统

以下颜色作为设计与 Cocos 实现的基础令牌；允许因插画、抗锯齿和颜色管理产生轻微显示差异。

| 令牌 | 色值 | 用途 |
|---|---:|---|
| `Brand/Navy-900` | `#06275A` | 主文字、深色胶囊、深色图标、按钮文字 |
| `Brand/Blue-500` | `#168FE8` | 品牌环境蓝、场景主色 |
| `Brand/Cyan-300` | `#76C8FF` | 浅蓝描边、辅助高光、弱选中 |
| `Brand/Lime-500` | `#DFFF00` | 唯一主操作、关键选中、重要状态 |
| `Neutral/White` | `#F7FBFF` | 卡片主底、浅色文字 |
| `Neutral/Gray-100` | `#EEF1F5` | 属性行、弱分区底 |
| `Neutral/Gray-700` | `#313844` | 白卡后的错位阴影卡 |
| `Action/Yellow-500` | `#FFD21C` | 升级、养成等次级付费/成长操作 |
| `State/Green-500` | `#38D01D` | 上场中、成长后的正向数值 |
| `Stat/Heart` | `#FF4775` | 体力 |
| `Stat/Technique` | `#FF7A32` | 技巧 |
| `Stat/Burst` | `#1BC7DF` | 爆发 |

### 2.1 使用比例

- 蓝青背景与环境色：约 `60%–70%`
- 白色、浅灰信息面：约 `20%–30%`
- 深海军蓝文字与容器：约 `8%–12%`
- 荧光黄绿：单屏建议不超过 `5%`，仅用于主操作与关键选中
- 黄色、橙色、粉色等功能色：只承担明确语义，不作大面积背景

### 2.2 禁止项

- 不使用大面积纯黑遮罩。
- 不让荧光黄绿同时承担多个同等级按钮。
- 不在高饱和背景上直接放小号文字；必须增加稳定底板或降低背景对比。
- 不用颜色作为唯一状态线索；同时配合描边、锁图标、标签或明暗变化。

## 3. 字体与文字层级

### 3.1 字体

- PSD 排版可以使用 `PingFang SC` 作为设计阶段近似字体，但不得把它当作运行时依赖。
- Cocos 静态界面统一使用项目内置字体：
  - 标题、按钮、关键数值：`ShuiMasterUI-SemiBold.ttf`
  - 标签、列表、描述：`ShuiMasterUI-Regular.ttf`
- 数字需要运动感时优先使用项目内置 `Semibold` 字面，不依赖设计电脑上的 `Arial Black`。
- 动态玩家名、聊天等无法静态收字的内容使用批准的全字库或系统字体回退。
- 新增或修改静态文案后必须重新生成并检查字体子集，不得手工修改字符清单。

### 3.2 1280×720 基准字号

| 层级 | 建议字号 | 字重 | 示例 |
|---|---:|---|---|
| 页面主标题 | `32–36 px` | Semibold | 角色 |
| 主操作 | `38–55 px` | Semibold | 开游、确认选择 |
| 卡片标题 | `26–30 px` | Semibold | 铁臂狂鲨 |
| 强调数字 | `24–30 px` | Bold/Black | 2461、200 |
| 正文标签 | `18–22 px` | Medium | 体力、技巧、爆发 |
| 描述文字 | `15–18 px` | Regular | 提升冲刺阶段速度。 |
| 辅助状态 | `14–18 px` | Semibold | LV.1、上场中 |

### 3.3 排版规则

- 所有功能文字水平放置，禁止旋转或透视变形。
- 中文按钮文字不使用全角空格拉开字距。
- 数字与单位保持统一基线；等级统一写作 `LV.1`。
- 文案图层必须可编辑，禁止烘焙到按钮底图或卡片背景中。

## 4. 布局与安全区

### 4.1 画布与边距

- 基准画布：`1280 × 720 px`
- 常规安全边距：左右各 `24–32 px`，顶部 `24 px`，底部 `20–24 px`
- 微信胶囊、圆角屏和异形屏适配时，以运行时安全区为准，顶部组件整体平移，不单独挤压内部间距。
- 核心交互热区不得贴近屏幕物理边缘。

### 4.2 顶栏基准

登录页 v12 顶栏作为全局组件源：

- 玩家信息：`x=33–266`，`y=10–96`
- 设置：`x=999–1055`，`y=25–81`
- 货币：`x=1055–1253`，`y=25–81`
- 设置和货币容器高度：`56 px`
- 图标与胶囊保持同一视觉中心线 `y≈53 px`

角色页有左侧返回标题，因此只复用右上设置与货币组件；右侧组合宽度可缩至内容宽，但高度、图标比例、圆角和数字字体保持一致。

### 4.3 触控尺寸

- 最小有效热区：`48 × 48 px`
- 高频主按钮建议高度：`80–120 px`
- 标签页建议高度：`44–52 px`
- 颜色选项视觉尺寸可小于 48 px，但实际点击节点必须达到最小热区。

## 5. 核心组件

### 5.1 玩家信息胶囊

- 头像圆形，外圈可使用荧光黄绿强调。
- 名称区使用深海军蓝横向胶囊。
- 默认只显示头像与玩家名；非必要不加入等级、在线点和额外进度条。
- 头像、外环、名称底板、文字必须独立分层。

### 5.2 设置按钮

- `56 × 56 px` 圆形深海军蓝底。
- 白色齿轮居中，图标视觉尺寸约 `28–32 px`。
- 默认、按下、禁用只改变底色/缩放/透明度，不替换整套结构。

### 5.3 货币胶囊

- 高度 `56 px`，深海军蓝底，左右圆角。
- 顺序：货币图标 → 数字 → 加号。
- 数字右对齐或居中于剩余区域；位数增加时优先扩展胶囊宽度，禁止压缩字号。
- 加号是独立按钮，点击热区至少 `48 × 48 px`。

### 5.4 主操作按钮

- 主色：`Brand/Lime-500`。
- 文字：`Brand/Navy-900`，Semibold。
- 造型：水平圆角矩形，可保留右侧网点装饰和底部浅色错位边缘。
- 登录页“开游”和角色页“确认选择”属于同一组件族，仅宽度与字号不同。
- 状态：
  - 默认：荧光黄绿主填充
  - 按下：整体下压 `2–3 px`，亮度降低约 `6%`
  - 禁用：降低饱和度与透明度，不显示为可点击高亮

### 5.5 次级成长按钮

- 用黄色表达“升级/养成”，不得与主操作使用同一荧光绿权重。
- 货币图标、花费数字和动作文字独立。
- 可采用白色外描边，但不增加强发光。

### 5.6 白色信息卡

- 主卡：`Neutral/White`，圆角 `16–20 px`。
- 后方叠一张 `Neutral/Gray-700` 深灰卡，偏移约 `12–20 px`，形成轻量层次。
- 正文区以浅灰条分组；不使用高透明玻璃、重模糊或不规则扭曲外框。
- 卡片与内部文字保持水平。

### 5.7 标签页

- 两段式标签，共用一个水平容器。
- 选中：深海军蓝底＋白字。
- 未选中：浅灰底＋深海军蓝字。
- 荧光黄绿只用于必须强化的临时状态，不作为角色详情标签页的默认选中色。
- 点击当前标签应无操作；切换只更新两个标签和对应内容组。

### 5.8 角色卡

- 基准宽度约 `160–172 px`，卡间距约 `8–12 px`。
- 构成：插画区＋底部白色信息条＋角色名＋等级。
- 选中：橙黄或荧光色描边，并可显示星标。
- 上场中：绿色文字标签，标签必须归入对应角色卡组。
- 锁定：插画降亮度/降饱和＋锁图标；文字仍需可读。
- 卡片状态通过同一组件的图层状态表达，不复制整套 UI 逻辑。

### 5.9 属性行

- 图标、标签、当前值、箭头、目标值分列对齐。
- 当前值用深海军蓝，成长后的值用绿色。
- 三项属性的图标风格必须统一：实心扁平图形、相同视觉重量、相同外接框。
- 角色等级使用深色胶囊，保留 `LV.1`，不显示经验进度条。

### 5.10 技能区

- 标题条、技能图标、技能名和描述独立分层。
- 临时技能图标允许智能对象占位，但正式资源必须替换为项目统一图标。
- 图标为圆形深色底，技能主体使用明亮单色或双色，不再使用旧的绿色游泳小旗图标。
- 描述限制为一行短句，超出时优先精简文案，不压缩字号。

### 5.11 模态弹窗

头像选择弹窗作为模态弹窗的视觉与实现基准：

- 背景使用深海军蓝半透明遮罩，参考值 `rgba(2, 20, 38, 0.68)`；保留大厅环境辨识度，不使用模糊和大面积纯黑。
- 弹窗主体使用白色大圆角面板，顶部为紫蓝色渐变/色带，并允许在一个角落加入低透明网点装饰。
- 弹窗标题独立居中，不再叠加左上角贴纸式标题；标题保持单行、可编辑。
- 主体信息按“标题 → 选择内容 → 辅助编辑 → 操作按钮”垂直排列，组间留白稳定。
- 取消使用青色按钮；提交使用黄色按钮。两者必须有清晰差异，提交按钮视觉权重更高，但不与页面级荧光绿主操作混淆。
- 按钮文字、标题、昵称与辅助文案均使用 Cocos `Label`，不得烘焙进切图。
- 点击弹窗主体不得穿透到大厅；点击遮罩或“取消”关闭且不保存。

#### 头像选择弹窗基准尺寸

以下坐标以 `1280 × 720` 画布左上角为原点：

| 元素 | 位置/尺寸 | 说明 |
|---|---|---|
| 主面板 | `x=293, y=115, w=696, h=436` | 中心约 `(640, 333)` |
| 标题 | 中心约 `(640, 174)` | `30 px`、Semibold |
| 头像第一排 | 中心 `x=440/540/640/740/840, y=260` | 五列等间距 |

| 头像人物 | `100 × 100 px` 原图；运行显示画布约 `72 × 72 px` | 使用带肩部版本，可见人物高度约 `65 px` |
| 选中双环 | 约 `103 × 103 px` | 绿色双圈，位于人物和底框之上 |
| 选中对勾 | `40 × 40 px` | 相对头像中心约 `(+34, +33)` |

## 6. 页面规则

### 6.1 登录页

- 品牌 Logo 是第一焦点，开游按钮是第二焦点。
- 顶栏使用全局玩家、设置、货币组件。
- 联机入口为可选次级操作，不与开游按钮争夺视觉权重。

### 6.2 大厅

- 中央为独立实时 3D 角色，背景不烘焙角色。
- 左侧角色信息、右侧模式、右下主操作形成稳定三栏关系。
- 模式插画承载轻松幽默感；文字区有独立色条或白底，保证缩小后可读。

### 6.3 角色界面

- 左侧角色卡、中部实时 3D 预览、右侧详情面板。
- 默认打开“属性”状态；“外观”是同位置互斥状态。
- “确认选择”为唯一主操作；“升级”是黄色次级成长操作。
- 切换外观色板只更新材质/颜色和选中框，不重建 3D 角色。

### 6.4 头像选择弹窗

- 固定使用 `5 × 2` 的十头像布局，不因屏幕变宽改列数；弹窗始终相对画布中心锚定。
- 遮罩覆盖整个可见区域，面板保持 `1280 × 720` 基准比例，不随超宽屏横向拉伸。
- 头像点选和随机昵称只修改弹窗内的草稿状态；点击“确认使用”后头像与昵称一次性保存。
- 点击“取消”或遮罩应恢复到打开弹窗前的资料，不产生部分保存。
- 点击已选头像为无操作；选中变化只移动绿色双环/对勾并更新旧、新两个按钮状态。
- 玩家确认头像后，大厅左上玩家信息应同步显示对应头像。头像、蓝色底图和原有外环必须共用同一圆心。
- 新头像 ID 只能追加，不能重排或改名已有 ID；如头像 ID 到联机角色外观的共享映射发生变化，必须同步提升联机协议版本。

## 7. PSD 图层规范

### 7.1 顶层命名

按功能区命名，编号只表达大区块，不用于每一个细小图层：

```text
07_ACTIONS / 确认选择
06_HEADER / 返回与标题
05_TOPBAR
04_DETAIL_PANEL / 属性（默认）
04_DETAIL_PANEL / 外观
03_CHARACTER_LIST
02_CHARACTER_PREVIEW（运行时替换为3D）
01_BACKGROUND
```

### 7.2 图层前缀

| 前缀 | 含义 |
|---|---|
| `BG /` | 背景 |
| `UI /` | 底板、描边、分隔等界面图形 |
| `TEXT /` | 可编辑文字 |
| `ICON /` | 图标 |
| `IMAGE /` | 卡片插画、模式图 |
| `CHARACTER /` | 角色占位或渲染预览 |
| `ACTION /` | 可交互操作组 |
| `STATUS /` | 状态标签 |
| `FX /` | 网点、高光等装饰效果 |
| `ARCHIVE /` | 备用或旧图层，默认隐藏 |

禁止继续使用“组 1”“图层 7”“矩形拷贝”等无语义名称。

### 7.3 状态组织

- 属性与外观为两个同级状态组，默认：属性显示、外观隐藏。
- 卡片状态放在对应 `CARD` 内，不允许把“上场中”等状态文字漂浮在顶层。
- 备用视觉必须明确标注并默认隐藏。
- 智能对象用于可复用插画、背景和复杂图标；文字、简单形状保持可编辑。

### 7.4 头像弹窗图层结构

头像弹窗 PSD 使用以下顶层结构：

```text
06_ACTIONS
  PRIMARY / 确认使用
  SECONDARY / 取消
05_NICKNAME
  ACTION / 随机昵称
04_AVATARS / 头像选项
  STATE / 当前选中
  10 / 救生员少女
  ...
  01 / 女潜水员
03_TEXT / 标题
02_PANEL
01_BACKGROUND
```

- 每个头像组内至少包含 `IMAGE / 角色头像（嵌入智能对象）` 与 `UI / 蓝色头像底`。
- 绿色双环与对勾集中放入一个 `STATE / 当前选中` 组，不为十个头像复制十套选中素材。
- 头像智能对象使用统一画布和缩放规则；替换角色后以可见人物高度校正，不以透明画布边界判断大小。
- 弹窗底板、按钮底图、图标和头像保持独立；导出时不得把整张弹窗合并成单张截图。

### 8.2 导出规则

- 背景、按钮底、图标、文字分别导出；按钮文字绝不烘焙进 PNG。
- 可九宫格拉伸的底板保留干净边缘和明确中心拉伸区。
- 同类小图标优先合并图集，控制微信小游戏包体与 Draw Call。
- 主包 `assets/resources/ui` 不额外生成 ASTC/PVR/ETC 变体；遵循项目纹理策略。
- 新资源导入 Cocos 生成 `.meta` 后，运行 `npm run textures:fix` 与 `npm run textures:check`。
- 头像弹窗运行时资源放在 `assets/race/ui/avatar-picker-v1`，不要放进微信主包的 `assets/resources/ui`。
- 头像、底框、选中环、对勾、昵称栏、随机图标和按钮底图均保留真实 Alpha；导出后必须检查四角透明，禁止把透明棋盘格烘焙进图片。

## 9. Cocos 实现约束

- 稳定 UI 层级只构建一次；标签切换、选中、颜色变化只更新受影响节点。
- 点击已选角色或已选标签应为无操作。
- 角色模型只在角色资源身份变化时重建；切标签、换肤色、查看属性不得重启预览动作。
- 监听器只绑定一次，刷新状态不得重复注册。
- `Label.string`、`Node.active`、颜色和尺寸只在值变化时写入。
- 大厅和角色页为非比赛界面，但仍需控制透明层、全屏模糊、动态图形和运行时分配。
- 联机状态下，外观选择等会影响其他玩家可见结果的数据，应通过既有网络会话同步；纯本地预览不能替代正式确认状态。
- 弹窗节点、十个头像按钮和监听器只在首次挂载时创建；再次打开只重置草稿和显隐。
- 头像贴图与 UI SpriteFrame 应缓存复用，异步回调写入前检查节点和资源仍有效。
- 选中状态使用一个共享的绿色双环/对勾节点移动位置，不清空或重建头像网格。
- 随机昵称只更新草稿 `Label.string`；最终确认把头像和昵称作为一次资料更新提交，避免联机房间监听到半更新状态。
- 弹窗仅在大厅使用，不进入比赛帧更新路径，不得新增 `update()`、持续 `Graphics.clear()` 或每帧格式化文字。
