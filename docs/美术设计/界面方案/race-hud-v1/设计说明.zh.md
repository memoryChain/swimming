# 比赛界面设计提案 v1

本套为视觉概念设计，覆盖结算以外的比赛流程。未改动游戏代码、运行时资源或既有结算页。概念中的场景、角色、头像由参考图生成，不作为替换模型或头像的依据。最终文字、状态阈值及运行时布局以下表和规格为准；生成图片中的文字不是可直接导入的字图。

## 视觉与布局
- 设计基准：1672 × 941，横屏约 16:9。四格板每格为缩略概念，不能当作原尺寸切图。
- 延续已确认页面：深蓝 #091F4B、青 #32CDE5、暖白 #F5FAFF、黄绿 #D5FF00。金色用于蓄气与高质量反馈，橙红用于延迟和资源不足。
- 状态卡为局部深蓝实色或高不透明度底板，亮水面下仍保持文字对比。普通正文与关键数值分级。
- 全屏左右半屏隐形触控保持现状。无新增可见左右按钮、摇杆、技能按钮、暂停按钮；调参入口不进入正式美术稿。
- 微信右上系统胶囊区域预留；右侧排名卡位于其下方。安全区应以设备 safeArea 与胶囊实际 bounds 为准。
- 速度提案移至左下固定位置；主角头顶仅保留识别箭头。进度、冲刺状态、划水评价各有独立区域，不能随镜头互相挤占。

## 组件全状态
- 发令：TAKE YOUR MARKS / GET READY / READY ON THE BLOCK / LOCK IN；只在现有首拍显示，不补造倒计时3、2、1。
- 起跳品质：power < 0.55 为 GOOD；0.55～0.85 为 GREAT；>=0.85 为 PERFECT；late 使用独立橙色。GO退出后再展示品质反馈。
- 蓄力条现有色段：power >0.82 高段，>0.45 中段，其余低段。色段与品质阈值不是同一套，不混用。
- 评价：Good绿色 / Great青色 / Excellent紫色 / Perfect金色 / Amazing橙色 / Crazy粉色 / Unbelievable金色。BAD不新增负面大字。短暂显示后沿现有淡出节奏。
- 体能：正常、低体能、极低体能；数值与颜色双重辨识，不能只靠颜色。心率同样沿现有区间。
- 排名：收起、展开、本人任意名次、长昵称、退出、淘汰、未完成；未完成不显示前三奖牌。排名弹层关闭时零布局更新。
- 终点：自己未到达时保留必要操控反馈；自己到达后切观赛等待。数字9/3只是示例，实际取RaceManager状态。
- 纯滑行：仅小提示“滑行中，准备划水”，不自动启用常规状态卡；随现有hideCountdown/showGliding门控。

## 资源与分层交接
- 复用既有头像 assets/race/ui/avatar-picker-v1 及线上人物头像映射，不能使用概念图里重复的生成头像。
- 复用既有UI字库：ShuiMasterUI-Regular / ShuiMasterUI-SemiBold。人物昵称等动态文本保留批准的全覆盖回退。
- 新制：紧凑状态卡底、三条填充/轨道、小状态图标、进度轨道、名次胶囊、发令条、蓄力竖槽、局部完赛卡、必要评价装饰。
- 所有数字、按钮文本、昵称、口令均独立文字层；卡底、图标、箭头与文字分离。整张概念不能作为运行时UI。
- 保留真实3D泳馆、机甲模型和水体；生成图里的几何细节不属于修改范围。
- 下一阶段若定稿PSD，建立对应状态组而不每页复制整个体系；保留全部文字可编辑，定稿前不从四格图自动裁游戏素材。

## 运行时与联机约束
本轮仅设计，不改变比赛逻辑或网络。
后续接入时继续使用现有RaceManager / UIFlowController / FinishRankOverlay / UIController数据入口。所有名次、终点时间和淘汰结果取当前权威数据；联机不得本机重排。退出沿已有房间流程，比赛结算后返回房间保持keep-alive，不新增endGame调用。
HUD稳定构建一次，更新只发生于状态边沿；数值10Hz并比较文本，跟随标签30Hz；面板隐藏立即返回。填充优先Sprite fillRange，纹理柔光与速度线不由Graphics逐帧生成。逐项核对透明层覆盖、draw call、字体刷新以及真机iOS成本。

## 验证范围
输出实际尺寸为每张1672×941（四格合计），每格约836×470；未得到提示词请求的3840×2160。适用于风格与布局审阅，分层定稿需按完整画布重新建立组件。

概念图待定稿校正项：09名次卡有重复展开三角，应只保留一个；部分进度图标未精确对齐填充末端；13体能24的填充颜色/比例未准确呈现低体能，应按当前最大体能计算并使用低体能橙红色；人物昵称、头像和场景泳道编号以真实资源为准。以上不代表新增设计规则。
