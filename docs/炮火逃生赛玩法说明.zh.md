# 炮火逃生赛玩法说明

更新日期：2026-09-18

## 玩法定位

炮火逃生赛是 200 米娱乐玩法，替代原来的末位淘汰赛。入口继续使用稳定模式 ID `last-place-brawl`，避免旧存档和既有联机房间选择失效；玩家看到的名称、规则、HUD、结算原因和联机语义均已切换为炮火逃生赛。

随机性只决定炮击目标、落点微偏和波次组合。预警出现后落点锁定；命中结果由玩家与落点的距离分区确定，不再使用同样命中却随机决定是否淘汰的暗骰。

## 比赛规则

- 全程安排十次炮击，触发距离为 25、48、70、82、104、116、138、148、158、170 米。
- 180 米后不再生成新炮击，保留最后 20 米冲刺。
- 每发炮弹预警 1.25 秒，水面同时显示红色核心区和橙色外围冲击区。
- 核心区约为纵向 1.05 米、横向 0.82 米的椭圆；若多人同时进入，只淘汰离中心最近的一人。
- 外围冲击区约为纵向 2.8 米、横向 2.35 米；命中只产生后退、横向击飞、翻滚、布娃娃松动和大水花，不淘汰。
- 连续炮击不重复选择同一名目标；预警后炮弹不会继续追踪选手。
- 场上只剩一名选手时停止炮击，并立即判定最后幸存者获胜。

## 目标与公平性

房主从仍在比赛的选手中选择目标，并根据目标当前速度预估落点。每次只有一个活动炮弹，因此不会生成覆盖全部泳道、没有逃生路线的叠加危险区。炮击目标可能是领先者或后方选手，不固定惩罚末位。

AI 在炮弹预警后读取落点，按自身操作纪律产生不同反应延迟，再向核心和外围之外的最近可用区域横移。AI 使用正常转向输入，不免疫命中。

## 表现与性能

- 两侧岸边各放置一门低多边形炮台，炮弹以高抛物线飞向锁定落点。
- 炮台由一个合并网格和一个共享材质渲染；炮弹、预警和水柱各使用一个固定共享网格。
- 预警、水柱和炮弹只修改 `active`、位置、旋转和缩放，不逐帧重建网格，不使用比赛热路径 `Graphics.clear()`。
- 表现层最多 20Hz 更新；玩法判定仍按比赛更新频率运行。
- 顶部状态条最多 10Hz 更新，并且只在最终文字或颜色变化时写入 Cocos 属性。
- 核心命中沿用永久淘汰、短暂击飞、水花、淘汰提示和观战流程；结算单列“炮击淘汰”。

## 联机权威

- 单机和房主运行炮击调度、目标选择和命中判定；访客不自行决定结果。
- 随机来源为房主种子派生的 `SeededRandom`，不使用 `Math.random()` 影响比赛结果。
- 可靠事件 `l` 同步炮击编号、落点、预警时长和版本；可靠事件 `x` 同步命中掩码、淘汰泳道和版本。
- `S|` 快照同步炮击版本、淘汰掩码、完成炮击掩码，以及当前活动炮弹的编号、落点和剩余预警时间，用于丢包恢复和房主迁移。
- `R|` 最终结果保留独立的炮击淘汰原因。
- 协议版本为 52，旧版本不能与当前版本混跑。

## 代码入口

- 规则和命中：`assets/scripts/core/CannonBrawlController.ts`
- 炮台、炮弹、预警与水柱：`assets/scripts/core/CannonBrawlPresentation.ts`
- 顶部状态条：`assets/scripts/ui/CannonBrawlHud.ts`
- 比赛编排、击飞、淘汰和观战：`assets/scripts/core/GameManager.ts`
- 排名与最后幸存者结算：`assets/scripts/core/RaceManager.ts`
- 联机事件和快照：`assets/scripts/net/NetRaceInput.ts`、`NetRaceSnapshot.ts`、`NetRaceController.ts`
- 离线回归：`tests/cannon-brawl.test.mjs`、`tests/net-race-codec-ordering.test.mjs`

## 验证范围

离线回归覆盖核心唯一淘汰、外围只击飞、确定性首发落点、AI 躲避目标、最低人数保护、活动炮弹快照恢复、可靠事件编解码、结算原因及 HUD 更新策略。仍需在 iOS／Android 微信真机检查正常比赛镜头下的预警辨识度、炮弹遮挡、水柱透明排序、击飞手感、弱网时序和房主迁移。
