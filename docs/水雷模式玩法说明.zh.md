# 水雷模式玩法说明

## 定位

水雷模式是独立的 200 米娱乐玩法。模式入口 ID 为 `minefield-brawl`，规则 ID 为 `minefield`。水雷是泳池中的公共障碍物，不会被玩家拾取、携带或传递。

## 核心规则

- 开局生成 7 枚水雷，出生点分散在不同纵向位置和横向区域。
- 出生布局、漂移相位由比赛共享种子确定。水雷围绕锚点缓慢漂动，始终留在可游区域内。
- 选手身体进入水雷判定椭圆时立即爆炸。直接触雷范围拆为“水雷自身椭圆＋人物身体椭圆”，总触发距离仍保持原来的纵向 `1.35` 米、横向 `1.05` 米；判定会扫掠上一帧到当前帧的移动路径，身体边缘擦到水雷或高速游过时都不会漏触发。
- 直接触碰水雷的选手会被击倒，进入 2.5 秒急救阶段；随后在原赛程进度和自己的泳道中心以零速度重新入水，并获得 2 秒无敌保护。击倒不计为永久淘汰。
- 爆心外围扩大到约纵向 3.2 米、横向 2.5 米；范围内其他选手只会被冲击波击退、翻滚并失速，不进入急救。
- 每枚水雷一局只能爆炸一次。爆炸后永久消失，本局不再刷新；只有重新开始一局比赛时才恢复全部水雷。
- AI 在接近同横向区域的水雷时会向水雷另一侧绕行。

## 表现与镜头

- 所有水雷复用一份低面数网格和一份材质，仅各自保留一个世界节点。模型由分面球壳、凸起腰线、八根分段尖刺、顶部触发器和侧面警示牌组成；不对称细节用于强化轮廓和旋转读性。
- 水雷不再在水面直接显形。启用掩码从隐藏变为可用时，各实例按 `0.04` 秒的小间隔开始入场：先在水下约 `0.82` 米处制造低强度扰动，再用 `0.72` 秒破水上浮，经过 `0.3` 秒回落稳定后接入常态漂浮。破水只复用低强度的池化水爆网格，不新增粒子系统或运行时绘制。
- 水雷在水面附近轻微上下起伏，并以约每秒 14° 缓慢自转、叠加不超过 9°／7° 的俯仰和侧倾漂摆；爆炸使用 3 个预建节点循环复用同一份共享网格和材质。
- 爆炸水花由暖色爆心、双层水面冲击环、环形水冠、九束有厚度的弧形水柱和少量块状水滴组成；不再使用两张交叉透明面表现水柱，避免比赛镜头下出现白色三角形。
- 水雷变换和爆炸缩放最多按 20Hz 更新，不重建网格，不使用运行时 `Graphics`。
- 本模式不写入或接管 `RaceCameraDirector`，也不启用事件画中画。赛前规则卡说明“碰到立即爆炸”，比赛开始后不重复弹出规则 Toast；本人触雷时使用娱乐玩法共用的个人反馈，其他选手触雷只播放世界爆炸、水花和角色受力。

## 联机

- 房主是唯一命中判定方。访客可以本地播放相同的确定性漂移，但不能自行决定谁触雷。
- 每次命中通过可靠帧事件发送水雷 ID、直接命中泳道、爆炸位置、受冲击泳道掩码和 revision；访客只接受递增 revision，避免重复受力。独立模式与六合一使用同一套直接击倒规则。
- `S|` 周期快照同步权威漂移时钟和存活掩码。已经爆炸的水雷在掩码中保持永久失活，因此事件丢失、晚到和房主迁移都不会将其重新生成；更旧 revision 仍会拒绝。
- 视觉漂移不依赖 iOS JavaScriptCore 与 Android V8 的浮点锁步一致性；周期快照会修正可见偏差，比赛结果仍只以房主事件为准。

## 首版调参入口

当前关键参数集中在 `MINEFIELD_TUNING`：水雷数量、水雷自身接触半径、人物身体触雷半径、外围冲击半径、漂移半径与速度、AI 预判距离和避让偏移；对应参数已接入 Debug 调参面板与 `tuning.json`。

## 验证范围

离线回归覆盖确定性水雷布局、直接击倒与外围冲击范围、扫掠命中、可靠事件去重、快照恢复、爆炸后本局永久失活、重开比赛恢复、旧快照拒绝、20Hz 表现更新、隐藏状态零遍历、水下扰动与破水上浮参数、精修水雷结构、轻微三轴漂转，以及爆炸水花不再使用交叉薄片。仍需在 iOS／Android 微信真机检查击退手感、上浮节奏、模型小尺寸辨识度、透明排序、连续多雷入场／爆炸时的填充开销和正式比赛镜头下的水花辨识度。
