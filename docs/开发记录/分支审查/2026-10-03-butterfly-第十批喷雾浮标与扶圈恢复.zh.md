# 第十批：喷雾浮标与扶圈恢复

## 这次加了什么

入口：**比赛准备页 → AI 测试 → 娱乐 → 喷雾浮标**。开始后泳池里有七个带警示气球的浮标，它们缓慢漂移。

- **直接撞到浮标**：气球爆开并喷水，人物停止前进，先失衡，再找圈、双臂扶圈。恢复共 3.5 秒。
- **恢复完成**：在自己泳道中心、原有赛程进度继续游，起步速度为 0；之后有 2 秒碰撞保护。保护期间可以正常操作。
- **附近被波及的人**：受到冲击、减速、侧推和短暂身体晃动，继续游泳，不进入扶圈恢复。
- **途中补充**：领先者到 65、130 米时，只补充已经被用掉的浮标槽位，总数不超过七个。有人完赛后停止补充。

这次没有把浮标加入上一批“低强度组合”。普通赛、联机房间、教学和 Boss 不启用。TapTap、抖音打包、正式蝶泳及原分支 mipmap 改动继续暂缓。

## 审查结论

适合按上述范围合到本地 main 测试。未直接覆盖原分支的 GameManager、人物基础数值、云端或联机代码。恢复状态、规则、模型表现和资源加载拆开，人物运动仍由主干 Motor 负责。

原恢复代码包含其他娱乐玩法、网络快照和海龟拖圈依赖，本批删除了未启用接口。扶圈按当前角色骨架确定大小与双臂接触，赛前准备，碰撞时不会重新绑定模型或加载资源。

恢复接口不会调用整场 `startRace`，因此不重置体力、心率、蓄气、赛程进度和角色已积累的能力。未完成输入会取消。人物退场、完赛或退出场景时取消恢复，不能被计时器拉回比赛。

浮标在新位置覆盖选手时保持隐藏且无碰撞；安全范围连续空出 0.45 秒后才出现。命中检查覆盖两帧之间经过的路径，因此高速或低帧率经过也能碰到；复位及特殊动作中断的旧路径会清除。

七份 GLB 合计 **173,380 B，约 169.3 KiB**。浮标与浮圈逐字节保留来源，主 UUID 保持原值。五份喷水网格按原运行时形状转成 `modelresource/entertainment/SprayBuoySplash.blend`，三角形位置、绕序和颜色均与冻结来源对照通过，没有自创造型。游戏中仅使用导出的 GLB；没有运行时造网格回退。

浮标和扶圈共用主干无光照水线材质，并登记到相机的水面分层。浮标稳态高度略降低，以保证底座实际穿过水面；气球原始局部位置保留。喷水沿用原来的透明无光照材质，登记水面分层，以显隐、缩放和位置播放短动画。

这些资源没有图片，不增加贴图压缩档位或 mip 配置。

## 性能与同步

- 浮标固定七个；每个两块网格。每位参赛者最多一个浮圈。
- 喷水固定三个入场槽和三个命中槽；五种网格共享，满槽复用旧效果。
- 八人场景按全部槽位同时显示估算，上限 37 个额外 MeshRenderer、16,840 个额外三角面。这是合批前的保守模型预算，不是真机 draw call 或帧率结果；通常部分槽位隐藏。
- 模型、节点和材质在赛前创建。20 次重赛不增加数量，比赛中无新增资源加载。姿态和浮标／喷水表现最多约 20Hz 采样，命中和恢复规则仍按比赛模拟推进。
- 普通赛不加载七份资源、不创建恢复序列、浮圈或喷水池；隐藏的池不持续写渲染状态。
- 排期和漂移使用独立的 SeededRandom，不消耗主干公共随机序列。**本批不开放联机**；恢复位置、暂停和范围冲击需要权威同步后才能进入房间赛。相同种子检查不等于跨设备同步验收。

透明喷水仍有叠加绘制开销，八人密集触发时需在 iOS 微信真机测量；离线检查不能证明真机帧率。当前保留在 AI 测试入口，待效果与真机确认后再讨论正式入口。

调参面板“娱乐调试”增加浮标漂移范围、恢复／保护时长、扶圈大小、前倾及起伏参数。旧 tuning.json 缺少这些键时使用原版默认值；现有主干数值没有覆盖。

## 引擎与真机待确认

五份新的喷水 GLB 必须由现有 Creator 会话生成元数据。代码检查和原资源 `.meta` 的 `imported` 字段不能代替当前项目的真实导入缓存；实际导入后运行：

```sh
python3 scripts/check-spray-buoy-assets.py --imported
npm run textures:fix
npm run textures:check
```

然后在上述入口重点试：直接撞浮标、附近冲击、恢复后的左右操作、八人密集触发、水线与相机切换、重赛与中途退出。未构建或部署平台包，未自动推送。

本批没有搬原分支的恢复卡、随机恢复文案、画中画、导演 HUD 或气球爆开音效；当前交付范围为原有浮标、喷水、失衡与扶圈动作及恢复规则。
