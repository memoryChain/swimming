# butterfly 第二批：统一埋点与抖音实现

日期：2026-10-03。整合基础：`main@05d133bbab85355986c7e9c95573a011206ca135`。功能来源：`feature/butterfly-debug@e5dca0327ed8d5e70bf5f38d39489022491e8e4b`。实施分支：`codex/butterfly-platform-events`。

## 审查结论

本批纳入跨平台共用的基础业务事件、统一上报接口和抖音实现。用户进一步明确埋点属于所有平台，微信当前尚未接入；因此没有直接复制分支的“游戏流程调用抖音服务”结构，而是将业务事件、平台选择和具体 SDK 实现分开。

此批适合先整合：事件只观察已有的大厅与比赛状态，不产生玩法输入、不修改数值、不改云端票据或结算、不改变联机协议。自动检查通过后纳入本地 main，推送由用户自行 review 后处理。

| 范围 | 本批处理 |
| --- | --- |
| 共用业务事件 | 大厅可操作、开赛、结束、原地重赛，共用字段与去重规则 |
| 统一接口 | `IPlatformAnalytics` 定义平台能力、启动来源和事件上报；`GameAnalytics` 屏蔽平台差异 |
| 抖音实现 | `DouyinAnalytics` 调用既有启动桥接及 `tt.reportAnalytics`；平台来源判定和复访服务留在 `DouyinEngagement` |
| 微信、网页、编辑器 | 使用 `DisabledAnalytics`，明确关闭上报，不创建比赛记录器、不缓存事件、不调用 SDK 或启动计时器 |
| 侧边栏导航服务 | 保留已审查的能力查询、导航超时与来源订阅接口，暂不接按钮或弹窗 |
| 后续平台 | 实现同一个接口并在平台工厂选择实现，保留现有业务触发点和事件字段 |

## 基于主干的接入与重构

- `GameFlowController` 只通过可选记录器消费业务事件，对抖音模块没有运行时依赖；实际类型来自通用的 `RaceAnalyticsTracker`。未接入的平台返回空记录器，开赛上下文也不会被调用。
- `GameManager` 保持编排职责：从统一入口取得记录器，提供当前模式、赛程、角色和本地／联机上下文。教学返回空上下文，避免混入普通比赛漏斗。
- `LoginManager` 使用主干现有加载屏障，等资源与角色准备完成、大厅遮罩移除后才记录可操作；失败、取消或邀请直达房间不提前计入大厅。
- `RaceManager` 只增加只读 `elapsedSeconds`，退出事件读取现有计时，不增加或更改计时逻辑。
- 单机在本地玩家触壁时记录完赛，提前返回大厅不会改成退出；AI、远端玩家和观战目标不触发本地终态。
- 联机仍先调用主干 `resolveNetLeaderboard`，采用解析后的权威名次与时间，再记录终态；原有云端结算输入和异步回调版本保护保持不变。主干既有权威成绩超时回退仍生效。
- 明确返回操作调用 `recordPlayerExit`，同局只记录一个终态；场景销毁或杀进程不会被当作主动退出。解绑后迟到的权威成绩不补报、不结算。
- 正式比赛“再来一次”若按主干规则返回大厅申请新票据，不把它冒充原地重赛；`race_again` 只记录实际原地重赛路径。

事件字典为 `config/analytics-events.json`，通用版本配置为 `assets/scripts/platform/AnalyticsConfig.ts`。当前 `schema_version=2`、`is_test=1`、`build_version=main-platform-events-test-1`，仍是待平台验收的测试标记。

`sidebar_return` 可由真实侧边栏来源触发；跳转成功本身不等于复访，普通前后台切换也不算。`sidebar_guide_click`／`sidebar_jump_result` 在字典与服务测试中保留，但本批没有接入界面，因此不能把它们写成已完成完整入口验收。

## 主干保护与性能

没有替换任何主干文件整体内容；现有比赛流程文件只增加事件观察。`GameManager.update()`、比赛镜头快照复用、AI 定步长、HUD 降频与粒子休眠路径没有改动。上报、字符串和事件对象只在状态转换时产生，不增加每帧上报或排队。

`cloud/`、存档模型、经济事务、票据、幂等逻辑、云环境隔离、房间范围、联机版本及保活重赛沿用主干。`settings/`、微信构建 hook、CDN／分包／图集配置、角色资源和数值均未修改。未导入旧 `art/` 源稿或任何 TapTap 字体实验。

新增模块的中文注释被现有字体扫描规则纳入，新增“埋、桥”两个字符；通过现有 `build-ui-fonts.py` 与缓存的固定字体源正常生成，未手改字表／字体。字数 1500→1502，269 个扫描文件。正文两份字体合计增加 988 字节，启动字体大小仍为 77696 字节，原字体 UUID 和 `.meta` 保留。启动字体也随生成流程重新写出校验信息，其字形集合不变。

851 个用户本地忽略文件与本批路径没有重叠；整合前确认大小、修改时间和 mode 与第一批前记录相同，全部仍忽略。整合后再次核验。

## 验证结果

- 固定 `typescript@5.4.5`：`tsc --noEmit --ignoreDeprecations 5.0 --skipLibCheck` 通过，使用本机已有 Creator 声明，未启动编辑器。
- 共 13 个相关测试文件，**117 项全部通过**：平台统一契约、抖音服务／启动桥接、大厅加载、结算镜头、比赛性能、AI 跳水、教学跳水、划水反馈、海豚音效、结算展示、房间健壮性、云环境与兼容结算。
- `platform-analytics.test.cjs` 通过同接口的抖音、微信和其他平台模拟实现，验证业务字段和去重完全共用；验证工厂门控、关闭实现、跨场景复用以及上报异常不会阻断游戏。
- 抖音验证覆盖冷启动、热启动、来源字段替换、启动桥接复用、能力／导航超时、迟到回调、跳转不冒充复访、真实比赛回调和权威结算。上报数据只使用当前事件字典字段，不加入用户名、房间令牌或凭证。

- 字体生成及 `ui-font-policy.js` 审计通过；新脚本 `.meta` 与主干 UUID 无冲突；最终差异空白检查通过。
