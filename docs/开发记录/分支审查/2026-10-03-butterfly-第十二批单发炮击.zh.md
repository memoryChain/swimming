# 第十二批：单发炮击

## 这次能看到什么

入口：**比赛准备页 → AI 测试 → 娱乐 → 单发炮击**。建议先用狂野模式观察 AI 绕开落点。

- 泳池两岸各一座炮台，左右轮流发射水球，同一时间只有一发。
- 原版十个发射距离为 25、48、70、82、104、116、138、148、158、170 米；按可受击选手中的领先者触发。200／400 米都先沿用这份单项计划，没有自行扩充后半程。
- 水球飞行前，水面立即显示原来的红色中心和橙色外围提醒，默认 **1.25 秒**后落下。球从真实炮口出发，炮管随落点抬起并短暂回弹。
- 红色中心只击倒最靠近中心的一人；橙色外围的人受到冲击，仍可继续游泳。
- 击倒沿用主干现有落水与扶圈动作：默认恢复 **3.5 秒**，回到原赛程进度、自己泳道中心，再有 **2 秒**保护。体力、心率、蓄气和角色能力保留。
- 有人完赛后停止新发，已经发出的水球正常落下。完赛、离场和恢复保护中的人不再被命中。

这次是单项本地测试。普通比赛、联机房间、教学、Boss 和低强度组合都不启用炮击。

## 审查结论和处理

**适合先放到本地 main 测试。** 来源为 `feature/butterfly-debug @ e5dca0327ed8d5e70bf5f38d39489022491e8e4b`，整合前主干为 `9012539`。

原版在比赛中加载并替换模型，同时保留代码生成的备用网格；炮击接线又散在 GameManager 的网络、画中画、事件导演和恢复逻辑中。本批改为：

1. 九项所需资源全部在赛前完成加载；失败统一清理，离场后的迟到回调无效。比赛中不加载、不替换、不生成模型。
2. 单发规则、画面表现和比赛接线各在 `entertainment/` 的独立文件中。来源双发、网络快照、画中画、入退场导演和整套正式娱乐赛没有搬入。
3. 从现有浮标中抽出 `EntertainmentRecoveryRuntime`，让浮标和炮击共用身体暂停、AI 停划、扶圈、复位、闪烁及退出清理。原浮标的玩法和恢复时长保持。
4. 保留主干转身与恢复保护的受击资格，以及主干现有落水动作；没有覆盖 Swimmer 或迁入来源另一套炮击抛飞参数。
5. 修正来源飞行进度写死默认提醒时长的问题：每发按自己的实际时长飞行。提醒时长、最短及最长预判距离接入现有调参保存流程；旧 tuning.json 缺键时使用原版默认值。

**GameManager、Swimmer、正常角色动作和描边实现、公共比赛数值、现有 tuning.json、云端、联机协议与平台打包配置均未修改。**

落水喷水复用已导入的浮标喷水 GLB，并恢复原炮击的缩放与时长；扶圈复用现有资源。单发只建立一个喷水槽，不建立闲置的浮标入水池。表现最多 **20Hz**，AI 避让最多 **10Hz**，规则仍逐模拟步执行。隐藏后不持续修改渲染状态，没有新增比赛 HUD 每帧文字或 Graphics 绘制。

八人测试池共预建 **17 个 MeshRenderer、4 份共享材质、11,648 个三角面**，这个数字包括八个通常隐藏的扶圈和一个未启用的喷水碎水部件；平时两座炮台共四个渲染部件。重赛不增加节点、材质或加载次数。这是几何与生命周期预算，**尚未验证 iOS／Android 微信的实际帧率和透明效果开销**。

工具重建字体增加「炮、若」两个扫描字形，两个比赛字体合计增加 **1,132 B**；启动字体大小不变。全部现有字体 UUID 保留。

## 2026-10-04：取消炮台固定明暗

用户反馈炮台颜色暗淡，要求去掉固定明暗。核查确认炮台没有实时光照；来源在顶点色中写入了按面朝向变化的明暗。此外，导出的线性色又被 `builtin-unlit` 转换一次，进一步变暗。

- 在现有 `Cannon.blend` 中只重新着色，恢复原蓝／白／橙色板；喷口内部保留深蓝纯色。没有重建几何或重新设计造型。
- 重新导出 `CannonBase.glb`、`CannonNozzle.glb`，保留 `.meta` 和全部 UUID。水球和落点提醒的文件、材质均保持原样。
- 炮台复用已加载的 `VenueHeightShade` 无光照效果，使用直接读取线性顶点色的普通分支；不启用水线或额外明暗。描边的旧颜色转换离线写入一次，保留原显示明度和反绕序外壳。
- 参考数据明确记录颜色修正原因与色板，不再声称炮台颜色与原分支完全相同。可复现修正入口为 `scripts/flatten-cannon-colors.py`；后续编辑仍使用正常 Blender 导出入口。

两份模型的所有三角角点位置、绕序、面数及描边几何均保持；顶点数量和文件大小也未增加。八人池仍是 17 个渲染部件、4 份共享材质、9 次赛前资源加载，没有新增纹理、shader 文件或每帧工作。玩法、普通赛、角色和联机未修改。

实际 TypeScript 5.4.5 类型检查、30 项炮击／浮标／特效资源相关回归，以及现有着色器的 WebGL 1／2 共 32 种宏组合编译和链接均通过。已按实际 GLB 的颜色与材质处理方式检查正面、背面和侧面的离线对照；离线图不代表游戏画面验收。

**用户已在现有 Creator 会话重新导入两份模型。** 全部 15 份特效 GLB 的实际缓存位置、颜色、索引、Prefab 路径和节点变换均检查通过；纹理压缩修正与审计也通过，修改 0 个配置。其余炮击资源与 `.meta` 字节保持不变。游戏画面仍由用户在单发炮击入口检查。

## 后面还剩什么

- **定时水球接力**：选手携带倒计时水球，接触别人时传给对方，倒计时结束喷开。来源身体挂点只覆盖旧角色，需要先核对主干全部角色，再复用这次共用恢复。
- **鲨鱼**：分阶段出现并追逐、扑咬选手。要拆开追逐、受击、模型与提示，审查跳水及转身期间的判定。
- **海龟班车**：抓住拖圈搭乘海龟，再松手离开。牵涉双手、身体挂点和运动接管，排在后面。
- 喷泉与巨浪的其余强度档位、双发炮击、完整事件组合、画中画及正式入口／云端结算继续分批审查。
