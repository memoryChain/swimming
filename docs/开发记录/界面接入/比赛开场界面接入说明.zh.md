# 比赛开场界面接入

## 定稿与范围

源稿为桌面 `划水大师/比赛HUD/划水大师-比赛开场-1290x720.psd`，画布 1290×720。
导出前已读取实际路径、可见图层及保存状态；“我”标签已位于昵称旁。
本次仅替换比赛前的赛制介绍和选手名单，保留实时 3D 场景及原镜头时间，不修改比赛 HUD、倒计时、输入或结算。

用户确认的顺序：`raceInfo` 出现赛制条；1.5 秒后进入 `roster`，在下方淡入八张角色卡，赛制条保留；其他阶段淡出。开场相机消费未缩放的帧时间，避免调试慢速延长此间隔；比赛中的相机仍沿用原时间缩放。
使用现有阶段信号，不新增定时器或联机协议。淡入 0.25 秒、淡出 0.2 秒；相同阶段无操作，快速切换先取消旧 Tween。

## 数据与布局

- `GameManager.refreshPreRaceIntroRoster()` 按 `swimmerForLane()` 的稳定泳道建立名单，不按世界位置或结算名次推断身份；不存在的泳道保留空槽。
- 卡面和角色名取 `swimmer.cartoonRig.modelVariantId` 对应的角色定义。单机跟随实际选择，联机跟随既有成员身份所应用的实际外观，不改同步或养成逻辑。
- 本人按泳者对象身份识别；金边、金色泳道牌及昵称旁“我”标签可出现在任意泳道。
- 赛程取 `getRaceDistance()`，人数取实际名单，难度取当前配置；联机显示“联机对战”。规则沿用现有竞速胜利目标。
- 画布统一等比适配，整体底部对齐安全区域；不修改项目全局 1280×720 设计设置。宽屏卡片不横向拉伸，窄屏一起缩放，刘海安全区来自 `sys.getSafeAreaRect(false)`，单位已经是设计坐标。
- 静态中文与泳道数字使用随包 `ShuiMaster UI` 的 Regular/SemiBold，不能依赖 PSD 本机的 PingFang/Arial Black。昵称采用系统全覆盖字体，常规字号 17；截断超长内容并由 Label SHRINK 兜底，不挤占“我”标签。
- 字体不是栅格切图。变更静态文案后执行 `pnpm fonts:build`、`pnpm fonts:check`。

## 生命周期与性能

`PreRaceIntroPanel` 一次构建事件条和八张卡，重复 populate 只更新有变化的值；本人状态只影响本卡的显隐、颜色和名字空间。
纹理加载复用已有缓存与并发请求合并。立绘回调核对节点有效性及请求路径，空槽清除请求身份；异步返回不能重新显示普通/本人底板。
没有比赛逐帧文字格式化或 Graphics 重绘；`GameManager.update()` 对本组件的唯一调用为常量阶段比较，相同阶段立即返回。销毁时移除窗口监听并停止淡入淡出。

## 空文本与缓存字体修复

实际引擎截图暴露：初始非空的“泳道”“我”能显示，初始为空的赛制、泳道数字、角色名不显示。Cocos 3.8.8 的 `Label.font` setter 会同步调用 `updateRenderData(true)`；原先在设置 SHRINK 前应用缓存字体，默认 NONE 模式会把空文字测量成零宽，并覆盖已设置的 UITransform。

修复：先配置 overflow/换行/对齐，再应用字体，最后设置设计文本框和坐标。无需改为系统字体、烘焙文字或每帧强制刷新。回归测试模拟缓存字体的同步测量，验证初始空文案到真实数据的文本框不归零。该测试不代替用户在引擎内的显示确认。
