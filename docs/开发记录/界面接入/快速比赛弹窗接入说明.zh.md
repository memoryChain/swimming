# 快速比赛弹窗接入说明

2026-09-20，按用户确认稿将单人快速比赛改成大厅上的弹窗。本文替代旧说明中的“快速比赛独立整屏二级页”约定，生涯地图和好友房间不变。

## 视觉与资源

- 设计画布1290×720，弹窗底板位于(235,98)，尺寸820×514，按安全区等比缩放。
- 复用`avatarPickerUi.panel`紫边波点底板、`avatarPickerUi.confirmButton`黄色按钮、`avatarPickerUi.selectedCheck`绿色勾选，以及生涯页白色九宫格、当前出场标签和箭头。未新增运行时PNG，也未将生成效果图整体贴进游戏。
- 底部按钮位于(470,552)，尺寸350×77；玩法选项下缘506，按钮上缘552，净间距46px。仅保存失败时，在留白内显示一行错误。
- 距离和玩法各自独立单选；选中为浅绿底、绿色边框与绿色勾，非选中为浅灰蓝。默认200米＋狂野，已有账号保留存档偏好。
- 删除自动匹配说明、金币/积分说明、本场配置摘要和快速比赛规则入口。
- 角色栏沿用生涯的横向顺序：真实角色头像、当前出场、真实角色名、等级胶囊、更换。头像、名称、等级随当前角色读取，示例头像不固定为实际玩家。
- 所有文字是独立Label。正文与中文粗体使用工程字库；等级胶囊沿用生涯的数字字体入口。角色头像继续使用既有圆形裁切与身份映射。

## 代码与流程

- `assets/scripts/ui/QuickRacePopup.ts`：弹窗节点、静态底图、选择状态、角色栏、错误提示和安全区适配。
- `CareerEventPage.ts`：移除原快速比赛整屏内容，转交快速比赛弹窗；保留生涯已有修改。
- `CareerPrototypePanel.ts`：沿用现有单人开赛命令，导航快照额外保存尚未开赛的距离与规则。更换角色返回不会重置选择。
- `PrepareRaceFlow.ts`：快速比赛挂在`UILayer.Popup`，遮罩覆盖3D预览及常驻资源栏。大厅内容与3D角色继续可见，开关弹窗不调用角色重新加载；拖动入口另有弹窗状态门控。
- 点击关闭或遮罩回到大厅，再次打开保持本次会话配置。成功开赛沿用原存档写入，赛后“返回大厅”直接显示大厅，不自动打开快速比赛弹窗；再次点击快速比赛时读取上次保存的距离和玩法。
- 保存/准备期间禁用选择、更换、关闭、遮罩和重复开赛；保存失败就地显示错误并恢复操作。场景加载失败继续走项目已有`recoverPrepareAfterLoadFailure`恢复大厅逻辑。
- 弹窗通过页面dispose显式释放，即使挂在独立Popup层，也不会遗留遮罩或监听。

## 性能与联机边界

节点和监听一次构建，选择只更新新旧选项的基础形状颜色与勾选可见性；重复点击已选项不刷新。文字、颜色、按钮状态、可见性均比较后写入。九宫格继续从原始纹理建立自有SpriteFrame，规避缓存已合图纹理被当作整张底图的问题。

没有新增`update()`、比赛HUD路径、逐帧文字更新、逐帧Graphics重绘、特效或资源加载轮询。全屏遮罩为一次构建的静态矩形；底框、按钮与角色美术复用现有精灵；两个标题标记使用一次构建的简单圆角矩形，四个选择控件仅在状态边沿重绘基础圆角矩形与等宽描边，没有逐帧Graphics工作。角色裁切为一次构建的Mask。

本次只调整单人赛准备界面，开赛仍走`source: quick`；不改变AI匹配、奖励、随机数、房间保活及联机协议，好友房间继续走原入口并清除单人赛票。
