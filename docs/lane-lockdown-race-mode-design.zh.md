# 动态封道淘汰赛

## 定位

这是高难比赛的赛道压缩机制，不是所有比赛的默认规则。它迫使玩家在有限时间内向安全走廊移动，让中后程增加路线判断和与对手抢位的压力。

难度开关统一定义在 `GameBalance.ts` 的 `RaceDifficultyConfig.laneLockdownEnabled`：

- 入门：关闭。
- 竞技：关闭。
- 世锦赛：开启。

后续赛事配置也应复用该开关，不能在 UI 或 `GameManager` 内硬编码难度名。

## 走廊规则

- 初始 8 道，安全走廊依次收缩为 `8 -> 6 -> 4 -> 2` 道。
- 每次封道由首位触发选手的位置确定嵌套走廊，避免固定从两侧机械收缩。
- 启用该赛制时，玩家起跑道随机分配，主要 AI 保证不与玩家同道；未启用时沿用常规固定分道。
- 走廊范围用包含端点的一基泳道编号表示，例如首轮 `2..7`。

## 淘汰判定

封道事件的正确顺序是：触发、警示、按完整碰撞体评估、淘汰、激活实体边界。不能只按角色根节点所在泳道判定。

设碰撞体在横向上的范围为 $[z_{min}, z_{max}]$，安全走廊范围为 $[z_{safeMin}, z_{safeMax}]$，则存活条件为：

$$
z_{min} \ge z_{safeMin} + \varepsilon
\quad \text{且} \quad
z_{max} \le z_{safeMax} - \varepsilon
$$

警示阶段不应产生物理阻挡；实体边界激活后才参与碰撞。

## UI 与视觉

- 排名 HUD 显示当前安全泳道范围，而不是只显示倒计时。
- 封闭泳道采用深靛灰蓝水面遮罩，不使用红色。
- 警示时，即将关闭的整条泳道使用黄白交替闪烁遮罩；锁定边界使用青白色。
- 第一版视觉样片显示 `2..7` 安全走廊：两侧深靛封闭区域与青白边界。

## 当前实现

`LaneLockdownRaceController` 已实现高难度比赛的三次收缩：领先选手首次到达 $50$m、$100$m、$150$m 时，依次生成 6、4、2 道的嵌套安全走廊。每次先预警 3 秒：首轮让两侧即将关闭的泳道整片黄白交替闪烁；后续轮次会保留已封闭泳道的深靛遮罩与青白边界，并只让当前安全区中即将关闭的泳道黄白交替闪烁。倒计时结束后才按完整骨骼轮廓判定、淘汰越界选手并启用新的横向实体边界。

淘汰选手会停止运动并离开场景，但 `RaceManager` 会保留开赛时的完整参赛名单，因此其最终成绩仍显示为未完成，正常存活选手继续比赛直到结算。重赛预赛阶段会清除上局的走廊边界与水面遮罩。

玩家被淘汰时会显示“退出游戏 / 观战”选择。退出沿用现有的返回登录流程；观战会随机选中一位存活选手，并提供目标切换按钮。观战使用独立的第三人称自由跟随镜头：默认在目标身后，目标折返改变游进方向时自动切换到新的身后方；鼠标/触屏拖拽可左右环绕与调整俯仰，滚轮/双指可拉近拉远。当前观战目标被淘汰时，镜头会自动切换到下一位存活选手，直至比赛进入正常结算。

`LaneLockdownVisuals` 仅把安全范围交给 `WaterRefractionController`；`RuntimePoolWater` 在现有折射材质中合成封闭颜色和边界，避免独立网格被水面遮挡或与波纹不同步。HUD 在比赛中显示预警目标或当前安全泳道范围。

当 `laneLockdownEnabled` 为真时，玩家起跑道会随机分配，AI 填充其余泳道，保证每局唯一占道；当前仅世锦赛难度开启该赛制。
