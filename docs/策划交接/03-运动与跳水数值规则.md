# 03｜运动、跳水与速度数值规则

## 1. 规则口径

本文只描述当前运行时代码已经执行的规则。数值优先级为：

1. 启动时加载的 `assets/resources/config/tuning.json`；
2. `TuningDebugControls.ts` 注册的调参默认值；
3. `GameBalance.ts`、`SwimmerMotor.ts` 等代码中的常量。

因此本文把“运行时覆盖值”和“源码默认值”分开写；没有在 `tuning.json` 出现的参数，不要误读成已覆盖。

## 2. 比赛距离与泳池映射

| 项目 | 当前实现 |
| --- | --- |
| 可选总距离 | 50m、100m、200m |
| 单池长度 | 50m |
| 折返 | 每经过 50m，世界 X 映射反向；没有独立转身输入/动画/扣时 |
| 速度单位 | m/s；距离按速度积分 |
| 结束条件 | 累计距离达到所选总距离，马达停止并触发触壁/漂浮表现 |

距离映射公式：

```text
lap = floor(distance / 50)
lapDistance = distance mod 50
worldX = lap 为偶数 ? lapDistance : 50 - lapDistance
```

实际世界坐标会再经过 `RaceCourseLayout` 的起点、终点 marker 校准和边界夹取；策划配置仍应使用 50 的整数倍。

## 3. 跳水输入与判定

### 3.1 输入

- 倒计时阶段长按跳水触控区开始蓄力，松开提交。
- 倒计时结束进入 `DIVING` 后仍可继续按住；在 `COUNTDOWN` 阶段松开只会取消蓄力，不会提前起跳。
- 若玩家一直按到倒计时结束，代码会自动提交当前蓄力值。
- `DIVING` 没有等待超时，玩家可以停在跳台上；AI 按自己的反应延迟先后起跳。

### 3.2 蓄力曲线

蓄力值是一个 0→1→0 的 Ping-Pong 周期：

| 参数 | 运行时值 | 作用 |
| --- | ---: | --- |
| `dive.minPower` | 0.30 | 提交时的最低力度；最终力度 = `minPower + charge × (1-minPower)` |
| `dive.chargeCycleSeconds` | 2.50s | 蓄力条完整往返周期 |
| 最终力度 | 0.30–1.00 | 归一化后送入 `DiveResolver` |

### 3.3 跳水结果

`DiveResolver.resolveDiveResult(power)` 同时服务玩家和 AI：

| 力度区间 | 质量层级 | 入水表现 | 首次心率 | 前几次划水启动修正 | 进入最佳区所需划水数 |
| --- | --- | --- | ---: | ---: | ---: |
| `power ≤ 0.42` | LOW | MESSY | 75→ | 1.0（最不稳定） | 7 |
| `0.42 < power ≤ 0.72` | OK | NORMAL | 75–108 线性 | 0.6 | 4 |
| `power > 0.72` | HIGH | CLEAN | 75–108 线性 | 0.3 | 2 |

力度到跳台初速度是线性映射：`launchSpeed = lerp(4.2, 8.2, power)`。入水轨迹使用 16° 发射角、6.2 的重力；水平初速为 `launchSpeed × cos(16°)`，入水深度为水面下 0.58。`DiveResolver` 理论上接受 0–1，但当前玩家 `minPower=0.30`，所以玩家实际不会落到 0.30 以下。

动画时长由低力度更长的蹲伏（0.26s）到高力度更短的蹲伏（0.18s）线性变化，之后按抛物线运动到入水点。跳水动画完成时，角色以水平初速进入马达并开始累计距离。

## 4. 跳水后的水下阶段

| 阶段 | 运行时值 | 操作/物理 |
| --- | ---: | --- |
| 水下保持 | 2.00s | 角色保持水下深度；输入只走水下踢腿，不启动手臂甜区 |
| 上浮 | 1.35s | 位置从水下平滑回到水面；上浮阶段结束才恢复手臂划水 |
| 额外阻力 | `glideDrag=0.35`（源码默认；当前 JSON 未覆盖） | 仅水下滑行叠加 `glideDrag × speed` |

全局比赛状态在跳水动画完成后先进入 `GLIDING`，固定 0.72s 后切入 `RACING`；角色的水下计时则由自身 2.00s+1.35s 控制。这两套计时当前不对齐，详见 99 文档。

## 5. 速度与阻力

每帧 `SwimPhysicsModel.step` 计算：

```text
speedRatio = clamp(currentSpeed / (maxSpeed + speedCapBonus), 0, 1)
accelLimit = 0.16 + 0.84 × (1 - speedRatio^1.6)
总加速度 = 手臂加速度 × accelLimit + 踢腿加速度
阻力 = poolDeceleration + baseDrag×v + highSpeedDrag×v² + glideDrag×v（水下时）
vNext = clamp(v + (总加速度 - 阻力)×dt, 0, maxSpeed + speedCapBonus)
```

当前运行时覆盖值：

| 参数 | 值 | 说明 |
| --- | ---: | --- |
| `speed.baseSpeed` | 0.80 | 普通游泳起始速度；跳水起跳使用跳水水平速度 |
| `speed.maxSpeed` | 6.00 | 常规速度上限 |
| `speed.strokeBaseAccel` | 0.50 | 每次完整手臂动作的保底推进 |
| `speed.strokeQualityAccel` | 3.00 | 划水质量为 1 时的主要推进 |
| `speed.strokeAccelDurationRatio` | 0.35 | 推进脉冲时长占当前动作一轮时长的比例 |
| `speed.strokeImpulseSharpness` | 0.60 | 加速前段更尖锐；理论总动量不变，只改变手感 |
| `speed.poolDeceleration` | 0.05 | 固定减速 |
| `speed.baseDrag` | 0.42 | 线性阻力 |
| `speed.highSpeedDrag` | 0.14 | 二次阻力 |

跳水可能把速度带到 `maxSpeed` 以上，当前允许额外速度帽不超过 0.90，并按 0.45/s 衰减；这不是连击加速，而是跳水入水速度的短暂超速。

## 6. 手臂划水推进

一次有效手臂动作在释放或完成时结算质量 `strokeQuality`：

```text
referenceTime = 甜区中心对应的按住段时间 + 释放段时间
timeScale = actionSeconds / referenceTime
accel = (strokeBaseAccel + strokeQuality × strokeQualityAccel × conditionSpeedScale) × timeScale
```

推进脉冲持续时间 = 当前动作一轮时长 × `strokeAccelDurationRatio`。`strokeImpulseSharpness` 只改变脉冲曲线形状，不改变平均总量。

手臂动作轮速随当前速度线性变化（运行时值）：

| 当前速度 | 轮速 |
| --- | ---: |
| `v ≤ 1.0m/s` | 0.5 圈/s |
| `1.0 < v < 3.0m/s` | 0.5→2.0 圈/s 线性 |
| `v ≥ 3.0m/s` | 2.0 圈/s |

因此甜区是固定的“动作进度比例”，但速度越高，一圈越短，实际可松手时间越窄。

## 7. 踢腿推进

玩家每次短按在按下瞬间登记一次对侧腿踢水，并按最近两次点击间隔估算频率：

- 推进频率上限 8Hz；测量安全上限 20Hz。
- 连续推进加速度约为 `kickAccelPerHz × 当前频率 × 封顶衰减`。
- 当前 `kickAccelPerHz=0.30`，单靠踢腿速度上限 `kickMaxSpeed=4.00m/s`，距上限 0.50m/s 内逐渐衰减。
- 停止点击后，频率按“自上次点击经过时间”自然下降，推进随之衰减。
- 动画脉冲最低 3.5 圈/s，每条腿最多缓存 2 圈；超过缓存的快速点击会被丢弃。

水下踢腿使用另一条链路，每次输入直接给 `diveUnderwaterKickAccel=0.40` 的小推进，不走表面踢腿频率模型。
