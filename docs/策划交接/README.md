- 整理日期：2026-07-10
- 代码基准：当前工作区（包含未提交的现行修改；HEAD 为 `4c048fe`）
- 数值口径：标作“运行时值”的参数已被 `tuning.json` 覆盖；未被该文件覆盖的，使用源码默认值。
- 表达约定：`已实现` = 代码存在且接入主流程；`未接入/遗留` = 有字段、配置或表现，但不会产生对应规则效果；`待确认` = 无法由代码判断设计意图。

## 当前产品一句话

一款 3D 自由泳竞速原型：玩家在 8 泳道中选择 50 / 100 / 200 米，通过跳水蓄力、全屏按住后在手臂甜区松开、以及短按踢腿来争取名次。主操作难点来自“速度越高，手臂甜区的真实时间窗越短”。

## 交接时最容易误读的四点

1. 触控正式路径是一个自动左右交替的全屏输入区；不是让玩家选择左右区域。`InputManager` 中仍留有按屏幕左右半区分手的编辑器/备用输入，运行时 UI 已把该路径关掉。
2. `RACING` 全局状态开始于入水后 0.72 秒，但角色仍可能水下 2.00 秒、再上浮 1.35 秒；两套阶段并不对齐。
3. `PERFECT` 连击会显示和计入赛后统计，但当前没有连击加速。
4. 心率的“质量修正”目前没有接进划水判定或推进；真正接入速度的是心率区的“效率修正”。详见第 04、99 文档。
