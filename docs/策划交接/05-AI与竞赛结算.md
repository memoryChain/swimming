# 05｜AI、名次与比赛结算

## 1. 参赛阵容

正式比赛使用 8 条泳道：玩家固定第 4 泳道（代码索引 3），其余 7 条为 AI。AI 默认配置按泳道顺序取 `DEFAULT_AI_PROFILES`，每条包含：

| 字段 | 作用 |
| --- | --- |
| `difficulty` | 同时影响松手准确度与划水间隔；越高越快、越稳定 |
| `bpmOffset` | 每泳道的小幅节奏偏移，避免同难度完全同步 |
| `divePower` | AI 跳水力度基准 |
| `diveReaction` | AI 起跳反应延迟基准 |

默认难度大致为 0.50–0.90，默认 AI 名称从一组英文名中随机打乱后分配。

## 2. AI 的实际划水算法

AI 不是只播放一条视觉动画，而是驱动与玩家相同的“按下→按住→松开→甜区结算”链路：

1. 进入游泳后等待 0.04–0.20s 的随机起步延迟；
2. 交替选择左、右手；
3. 调用 `handleStrokeHeld(side, true)` 捕获按下时刻，再调用 `handleStroke(side)` 创建动作；
4. 轮询手臂动作进度，达到目标进度且按住时间达到最小门槛时松开；
5. 目标进度 = PERFECT 区中心 + 难度缩放后的高斯噪声；
6. 松开后等待一个随难度从 0.22s 降到 0.04s 的间隔，再开始另一侧。

AI 的安全松手进度上限为 0.48，且保底按住 0.60s，避免卡在超时状态。每次间隔有 ±28% 抖动。

## 3. AI 跳水

AI 在玩家进入 `DIVING` 时即安排跳水计时：

- 反应延迟 = 配置基准 + 0–0.08s 随机值，最低 0.03s；
- 力度 = 配置基准 ±0.08，夹在 0.38–0.96；
- AI 入水后立即开始自己的游泳马达，即便全局仍处于玩家等待跳水的状态。

因此玩家可以在跳台上停留，而 AI 已经开始前进；这是当前实现，不是一个被额外平衡过的等待规则。

## 4. AI 难度调试入口

登录页的 `AI DEBUG` 不是正式比赛入口，而是 100m 单 AI 对手调试模式，档位为：

| 显示 | 难度 |
| --- | ---: |
| 入门 | 0.30 |
| 普通 | 0.50 |
| 困难 | 0.70 |
| 高手 | 0.85 |
| 大师 | 0.98 |

该模式只生成玩家和第 5 泳道的一个 AI，可显示 AI 自己的左右甜区盘，并允许切换镜头跟随 AI。它仍使用同一套比赛计时和结算。

## 5. 实时名次

比赛中每帧按累计距离从大到小排序，玩家 HUD 显示“名次 X/参赛人数”。这是距离名次，不是最终触壁名次；同距离时排序没有额外稳定 tie-break 规则。

## 6. 完赛与结算

1. `RaceManager` 在 `RACING` 中检测每个选手距离是否达到总距离。
2. 先到者记录自己的比赛计时，并播放触壁/漂浮表现。
3. 玩家完成后不会立即弹结果；必须等玩家和所有仍激活的 AI 都有完赛记录。
4. 最终榜单按记录时间升序排序，名次从 1 开始。
5. 结果面板显示：个人成绩、名次、平均速度、完整榜单；玩家行使用高亮背景。

平均速度 = 所选总距离 / 玩家比赛时间。最大连击、Perfect/Good/Bad 次数会从玩家统计中传入结果数据。

比赛计时从 `DIVING` 状态开始，包含跳水动画、水下和正式游泳；不包含赛前镜头和 3 秒倒计时。AI 即使更早入水，也只有在全局进入 `RACING` 后才会被 `RaceManager` 检测触壁并登记时间。
