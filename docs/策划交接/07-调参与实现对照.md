# 07｜调参入口与代码实现对照

## 1. 调参文件与加载顺序

调参面板定义在 `assets/scripts/core/TuningDebugControls.ts`，项目运行时配置为 `assets/resources/config/tuning.json`。

启动时顺序：

1. 先保存源码默认值快照；
2. 异步加载项目资源 `config/tuning`；
3. 若项目资源不存在，再尝试原生可写目录和 localStorage；
4. 应用值后校验甜区范围、超时边界和速度轮速关系。

项目交付以 `tuning.json` 为准；编辑器面板的保存按钮可能同时写项目文件、原生运行目录或 localStorage，需看保存结果提示。

## 3. 参数关系校验

加载配置后代码会自动：

- 把 GOOD/PERFECT 区间夹在 0–超时进度内；
- 保证区间至少有 0.001 的宽度；
- 保证高速轮速不低于低速轮速；
- 保证 `armCycleSpeedFull > armCycleSpeedStart`，不满足时自动改为起爬速度 + 0.1。

调参时应先改区间和动作轮速，再改推进；否则可能出现 UI 甜区与真实结算不一致的手感。

## 5. 调参验收建议

每次改动后至少验证：

1. 50/100/200m 都能完成并正确折返；
2. 0.20s 附近短按不会误报 BAD；
3. 甜区条显示与实际 PERFECT/GOOD/BAD 一致；
4. 高速动作轮速变快且没有超过超时点；
5. 水下保持期间不会出现手臂甜区和表面水花；
6. AI 低难度和高难度的成绩差异来自时机与频率，而不是额外隐藏速度常数；
7. 结果面板等待所有激活选手后再弹出。
