# 邀请进房与角色同步健壮性

## 玩家实际路径

好友分享携带 `room=<accessInfo>`。首次玩家打开邀请后，登录首屏保留音乐，自动加载业务分包；业务入口读取并保存玩家资料，再用最终身份加入邀请房间，无需先手动进入大厅。新档默认蛙妹 `cartonSwimmer6`、1 级、暖肤色 `warm`、红色衣帽 `red`；有存档则恢复已有选择。房间返回按钮进入大厅，玩家可在那里改选角色，再重新入房。

当前存档仍为本地 MockBackend，没有新增跨设备云存档或角色选择弹窗。

## 本次修复

| 边界情况 | 处理方式 |
| --- | --- |
| 进房早于存档加载 | 等待 PlayerData.load 成功，禁止发布临时随机身份；失败显示重试 |
| 角色属性和外观不一致 | 角色 ID、等级、肤色、衣帽配色共用开赛快照；头像只作账号身份展示 |
| 资料缺失或非法 | 拒绝非法角色、等级、配色和不完整名单，未同步完整不能准备或开赛 |
| 连续邀请和重复点击 | 进退房串行；等待退房期间只保留最新邀请；同房邀请不重复加入 |
| 取消后平台才返回成功 | 原进房事务先清理迟到成功，新进房随后执行；已销毁界面不再写回 |
| 断网或退出失败 | 初始化失败显示重试；退出失败保留原房供重试 |
| 长中文与表情昵称 | 按 UTF-8 限制身份串在 32 字节以内，不截断完整表情代码点 |
| 同名同头像、房主迁移 | 优先平台 clientId/座位；保活重赛继续提供本人标识 |
| 换人后的迟到消息 | MOD 和 rulesReady 绑定当前成员标识；换人后清掉旧摘要、版本与准备确认 |
| 开赛包丢失、重复或乱序 | 有限补发；验证版本、房主、名单、赛制、准备状态、本人选择与完整摘要，冻结快照后只进场一次 |
| 状态轮询积累 | 同一房间仅运行一条开赛轮询链；旧查询和延迟开赛回调不能修改新房间 |

`NetRaceProtocol` 升为 **46**，45 及更旧客户端不得混跑。MOD 新格式为 `MOD|座位|编码后的成员标识|角色ID,等级,肤色ID,配色ID`。开赛消息同时携带成员列表和完整摘要，准备确认也绑定本人摘要。

首局继续由每端调用 startGame；重赛复用保活会话，不调用 endGame，也不重新 create/join/startGame。单机继续从本地选择解析属性。本轮没有修改比赛每帧同步、物理或随机数规则。

## 验证与边界

新增 `tests/room-robustness.test.cjs`，覆盖存档失败重试、断网、重复点击、连续邀请、迟到回调、同名用户、非法数据、丢失首个开赛包与保活重赛。运行入口为 `pnpm test:room`。

2026-09-24 离线回归：房间、启动、资源与养成 114 项通过，角色与网络编解码 32 项通过。游戏 assets 范围 TypeScript 5.4.5 检查通过；全仓检查仍被两个本地历史工具脚本缺少 `CharacterModelLoader` 引用阻挡，未修改这些工具文件。

连接等待超过 15 秒可返回大厅。SDK 的进房 Promise 若永不结束，目前无法可靠取消底层请求；为防止两个房间请求互相污染，新请求仍等待旧请求结束。这类情况下可能需要重启小游戏。开赛采用有限补发，持续断网或所有补发均丢失仍可能无法一起开赛，不等同于可靠传输协议。

尚未构建新的微信包或做双端真机验证。验收需让 iOS 与 Android 都使用协议 46 的同一新构建，重点检查：

1. 清空存档后点邀请：进入正确房间，蛙妹 1 级，双方所见角色及配色一致。
2. 已选其他角色、肤色与配色后点邀请：存档恢复正确，比赛里本机与远端外观一致。
3. 弱网进房、下载途中连续点两个邀请、进房中返回、退房失败后重试：不串房、不出现幽灵成员。
4. 同名同头像、房主离开后迁移、成员离开再入同一座位：本人座位、准备状态和开赛名单正确。
5. 首局结束返回房间，连续重赛至少三局；版本不一致时阻止开赛。
