# 定时炸弹模式玩法说明

## 定位

定时炸弹模式是 200 米娱乐玩法。模式入口 ID 为 `timed-bomb-brawl`，规则 ID 为 `timed-bomb`。旧 `mine-relay-brawl`／`mine-relay` 选择会在读取时迁移到本模式，不再显示旧“漂雷传递”入口。

## 核心规则

- 全程安排 6 轮炸弹，领游者到达 24、52、82、112、142、168 米时依次触发。
- 每轮通过比赛共享种子，从仍在比赛且未处于急救／重生无敌阶段的选手里选择初始携带者；优先在纵向约 4.8 米、横向约 5.4 米内确实存在可追目标的人群中随机，只有全场都没有合适人选时才回退到全部有效选手，避免把炸弹直接判给孤立选手。
- 传递分为三层。人物碰撞系统一旦确认携带者与有效目标发生真实接触，炸弹判定会优先消费同一份稳定接触记录，因此画面已经出现击退／翻滚时必定能够交接，不会再因碰撞求解先把两人分开而漏判。没有人物碰撞记录时，再使用双方身体椭圆相加后的贴身范围与前后帧相对路径扫掠兜底；总静态范围为纵向 `1.6` 米、横向 `1.3` 米。若始终追不上同速目标，则允许对前方 `0.4～2.8` 米、横向相差不超过 `1.2` 米的同一选手持续对齐 `0.18` 秒后完成一次定向短传。它不会因为“附近有人”就任意自动抛出，也不会传给身后或横向未对齐的人。
- 初次接棒保护时间为 `0.55` 秒，后续传递冷却为 `0.45` 秒，上一名携带者仍有 `1.1` 秒防回传保护；引信锁定期间两种传递都停用，超过 `3` 米的相对位置校正也不会沿整段补传。
- 引信最后 0.8 秒锁定，不能再传递。归零时当前携带者遭受致命爆炸，进入 3.5 秒急救阶段；本地压暗层显示运动转播式急救牌，以一个、两个、三个点循环显示“急救中”，卡片短促横向切入后保持稳定，其他玩家看到其保持侧翻漂浮眩晕姿态，头顶三颗卡通星以 20Hz 缓慢旋转。随后在原赛程进度和自己的泳道中心以零速度重新入水，并获得 2 秒无敌保护。
- 爆心外围大幅扩大到约纵向 5.2 米、横向 4.2 米；范围内其他选手会被冲击波击退、翻滚并失速，但不会进入急救，携带者始终是唯一直接击倒者。
- 爆炸不会写入永久淘汰或 DNF；泳者节点、镜头目标和既有体力／角色能力积累继续复用。
- 携带者在引信归零前冲线，或已经离开有效比赛状态，本轮视为拆弹成功。

## 表现与操作

- 炸弹使用独立的精修低多边形模型：三根带深色端盖的红色炸药管由两道有厚度的环形束带固定，前方计时器具有切角外壳、侧扣、内嵌青色显示区、分段读数、实体按钮和两根连续导线；中央引信座承托橙色警示灯，不再复用水雷模式的带刺球模型。
- 炸弹直接挂在携带者身上，以轻微摇摆保持计时器可辨认；警示灯随剩余时间加快闪烁。
- 每轮开始时炸弹不再凭空出现：复用同一枚炸弹模型，从目标所在一侧的观众席上方沿短抛物线旋转飞入，并持续追踪正在移动的目标落点；约 0.55 秒后落到携带者身上。可靠装雷事件实时播放入场，快照补状态时直接挂载，避免晚加入或丢包恢复重复播放已经过时的投掷。
- 发生传递时，权威归属立即切换，画面中的同一枚炸弹再从旧携带者当前位置沿约 `0.22` 秒的小弧线飞向新携带者；飞行只负责交接读性，不延后玩法判定。
- HUD 使用娱乐玩法统一的持续状态条外观，以 10Hz 更新携带泳道、剩余时间、锁定状态和剩余轮数；文本与颜色只在结果变化时写入。
- 炸弹随机发放、爆炸和拆弹属于赛事广播；炸弹落到本人、传入或传出属于个人反馈，不使用通用 Toast。本人被炸倒后使用共用的“急救中……”压暗层和重生无敌状态条。AI 携带者会主动贴近对手；刚装雷或刚传递的保护期内，附近非携带 AI 暂不横移逃开，保护结束后才恢复躲避。
- 本模式不写入或接管 `RaceCameraDirector`，主镜头继续按普通比赛规则跟随角色；定时炸弹改为复用唯一的 `RaceEventPictureInPictureCamera`，在右上角给当前携带者一个斜侧中近景，画面需同时看清人物、挂载炸弹和附近水面关系。
- 每轮首次装雷显示约 1.2 秒；传递发生时，若镜头仍在显示则平滑转向新携带者，若已关闭则重新显示约 0.8 秒。短时间连续传递使用 1 秒重开冷却并只追踪最新携带者，避免画中画反复闪烁。
- 引信进入最后 0.8 秒锁定后，画中画强制显示到结算；拆弹后继续保留约 1 秒携带者结果镜头，爆炸后则使用可靠结算携带的权威爆心切到较高俯角，在同一秒内同时容纳被炸角色和完整水面冲击波。本人持雷同样显示镜头，并使用“你持有定时炸弹”“炸弹已锁定在你身上”等第一人称状态，解决主视角难以确认炸弹归属的问题。
- 镜头优先级为鲨鱼咬合／炮火落点高于定时炸弹，定时炸弹高于漩涡教学俯视。更高优先级镜头占用时仍缓存最新携带者；进入锁定阶段后会在镜头空闲时恢复跟拍。画中画只补充归属与结算信息，不能替代主画面的挂载炸弹、警示灯、持续状态条和个人反馈。

## 联机

- 单机与房主负责发放、传递、爆炸和拆弹判定；初始携带者的“附近存在可追目标”筛选和所有结果随机都来自同一份权威状态与 `SharedRNG`。
- 房主通过可靠帧通道发送装雷、传递和结算事件；爆炸结算同时携带权威赛程距离、横向爆心和受冲击泳道掩码。各端的世界水花都由这组权威距离与横向坐标换算，不读取可能仍在预测或校正中的本地泳者节点；只有快照补漏且缺少结算坐标时才回退到泳者当前位置。权威快照携带当前轮次、携带者、引信、冷却、已结算轮次，以及各泳道的急救／无敌阶段和重生距离。
- 访客只推进显示计时并应用权威事件／快照；迟到事件和重复爆炸通过递增 revision 与轮次掩码去重，恢复快照负责丢包和房主迁移兜底。
- 初始目标筛选、人物碰撞接触消费、身体椭圆与跨帧扫掠、辅助短传候选与 `0.18` 秒确认计时、AI 接棒反应窗口都只由房主运行，仍复用既有传递事件，不新增网络字段。碰撞接触使用已有求解器的稳定接触表，不按客机画面重算；候选确认进度不进入快照，房主迁移后只会重新确认最多 `0.18` 秒，不会产生错误归属。
- 六合一首位选手完赛后，房主取消尚未装载的炸弹轮次；若已经有人持雷，则只保留当前这一枚自然结算。取消结果通过现有 revision、完成掩码和周期快照恢复，提示条在没有当前炸弹时立即消失，或在当前炸弹结算后消失。该收尾语义接入后全局协议版本升至 `82`，旧客户端不能混跑。

## 性能约束

- 同一时刻只有一枚可见炸弹；爆炸接入娱乐模式共享水花池的 `EXPLOSION` 档，复用炮火与障碍水雷的暖色爆心、双层冲击环、环形水冠、有厚度的弧形水柱和块状水滴，不再由本表现类持有独立爆炸节点、网格或材质。水柱约 0.6 秒完成，带白蓝高亮浪尖的立体断续波峰继续扩散并沉降到约 0.95 秒，避免在正常镜头和 256×144 画中画里只剩一闪而过的透明细线。
- 炸药管、端盖、环形束带、计时器、按钮和导线仍合并为一个顶点色网格，另用一个小网格表现警示灯；精修不增加运行时节点、贴图或材质批次。
- 不增加贴图、外部 GLB 或额外材质种类。挂载后不逐帧计算世界跟随；表现最多按 20Hz 更新摇摆、闪烁和爆炸缩放。
- 观众席抛入与传递短弧线复用同一炸弹节点、网格和材质，仅在 0.55 秒入场或 0.22 秒交接期间按 20Hz 更新世界位置与旋转；落地后重新挂到泳者节点，不增加常驻节点、粒子或网络消息。
- 不使用运行时 `Graphics` 绘制特效，不创建逐帧 UI 字符串或临时节点。
- 人物碰撞接触查询复用碰撞求解器已有的固定上限数组，最多八名泳者，不创建逐帧对象或额外物理组件。
- 画中画继续复用现有 256×144 RenderTexture 和相机，不创建第二套渲染器；最多 30Hz 更新，隐藏时关闭相机。面板位于右上排名栏左侧，并避开微信胶囊与安全区。倒计时只在整数秒、携带者、锁定或结算状态变化时更新文字，普通引信阶段不持续开启画中画。
