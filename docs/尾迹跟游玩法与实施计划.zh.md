# 尾迹跟游玩法与实施计划

更新：2026-09-22。状态：第一版代码已接入，离线规则／真实运动／HUD／协议回归通过；引擎实机画面、微信双端与设备帧耗待试玩确认。

## 1. 目标与范围

让玩家通过选位跟游节省体力，再选择时机离开队列超车。每个正常向前游动的选手都可产生尾迹，不限于全场第一名。

用户已确认：只用于狂野模式和娱乐模式；标准竞速不启用。狂野 200／400 米共用规则，娱乐模式中作为常驻规则，不占娱乐导演的事件名额，不随事件轮换重置。开发用单项娱乐入口沿用这套规则，便于验证组合。

下文具体数值、表现与 AI 策略为第一版试验参数，并非已确认的最终平衡结果。用户已同意按计划推进实现。

## 2. 当前机制与接入依据

- 当前普通手臂划水每次结算消耗 1 点体力，左右各计一次，GOOD／PERFECT／失误／超时同价；踢腿免费，无自然体力恢复。
- 体力耗尽后，新开始的手划推进倍率为 0.15，动作轮速倍率为 0.6；在途动作保留原有推进预算。
- 海豚技能目前独立扣 5 点体力，心率、蓄气、技能资格另有规则。
- 身体互相阻挡，前后贴得太近会碰撞；尾迹有效区必须覆盖安全跟随距离。
- 现有 SplashEmitter 已有世界空间脚后泡沫尾流，采用小容量粒子；纯表现包含随机性，不能直接用其粒子作为玩法范围。
- 真人位置和体力由本人设备确认，AI 由房主确认，远端通过权威快照校正。
- AI 目前估算每米体力成本时，将每划成本下限设为普通 1 点；尾迹接入必须一并调整这一假设。

## 3. 第一版玩法规则

### 3.1 产生与跟随

1. 仍在比赛、正常处于水面并持续向前移动时，沿刚游过的真实路径留下有限长度的尾迹。正常手划、踢腿和短暂滑行均可产生。
2. 每个选手独立产生尾迹；B 跟随 A 时，B 仍可为 C 提供尾迹。收益不向后逐级增强。
3. 受益者必须同向游动、位于来源选手后方、进入其有效路径带，并保持短暂稳定跟随。迎面相遇、交叉掠过和自己绕回自己的路径不触发。
4. 按真实世界位置、路径切向和折返方向判断，不只比较累计比赛距离。不同折返泳段互不提供收益，避免折返和套圈误判。
5. 多条尾迹重叠只享受一次折扣。优先保持当前有效来源，失效后再稳定切换，禁止来源来回跳动引起闪烁。
6. 进入确认后，在真正开始一划时锁定该划成本，沿原有成功结算入口扣除；离开后新开始的划水恢复原价。失败输入不产生新扣费，超时结算只扣一次，双手各自保存成本。
7. 尾迹不恢复体力、不直接增加速度、不改变心率、PERFECT 判定、蓄气和海豚技能成本。零体力仍走现有耗尽规则。

### 3.2 初始试验参数

| 项目 | 第一版起点 | 目的 |
| --- | --- | --- |
| 体力节省比例 | 15%，即每划 0.85 点 | 在持续跟游中形成收益，保留领游与超车的价值 |
| 有效路径范围 | 距来源中心沿尾迹约 2.2～5 米 | 避开当前约 1.8 米中心间距的接触边界；最终核对各角色实际碰撞范围 |
| 路径带总宽 | 1.6 米 | 容许小幅摇摆，同时需要主动选位 |
| 路径最大年龄 | 2.5 秒 | 只保留近期游过区域，长度与年龄双重裁剪 |
| 正常生成速度门槛 | 0.8 米／秒；低于 0.6 米／秒停止生成 | 使用进入／退出差异避免低速反复开关 |
| 跟游进入确认 | 0.15 秒 | 避免擦边一瞬领取折扣 |
| 跟游退出宽容 | 0.15 秒 | 容忍轻微横摆；相反方向、起跳、急救、瞬移等硬失效立即退出 |
| 停止后残留上限 | 0.4 秒内失效并淡出 | 停住后不能持续提供增益；折返、瞬移和重生直接切断玩法路径 |
| 路径与候选关系采样 | 15Hz | 固定频率采样，不影响原有游戏和网络模拟步长 |

全部手感参数集中配置，并进入现有调试面板与 tuning.json 覆盖流程。新增键使用明确的英文前缀，例如 drafting.energySavingRatio，不硬编码散落在各模块。

固定起划成本意味着退出后，已经开始的一划仍按锁定价格结算；这是明确的规则，不在一划中途反复变价。新划起手时再次核验来源、方向、有效期和必要的空间边界，不能只信过期的低频缓存。

### 3.3 与现有动作及娱乐事件的关系

| 状态 | 尾迹处理 |
| --- | --- |
| 普通水面手划、踢腿、滑行 | 满足速度与方向条件即可产生；手划才实际享受扣费折扣 |
| 体力耗尽但仍在水面移动 | 可以产生尾迹；自己进入别人尾迹也不会恢复体力 |
| 出发水下滑行、蹬墙潜行、海豚跃出／深潜、角色潜水能力 | 不产生或新领取水面尾迹收益，浮出后重新采样 |
| 转身折返 | 切断旧段，进入新泳段后重新生成，禁止连成穿墙或迎面增益区 |
| 正常碰撞、轻微推挤 | 不凭一次接触强制删除整条路径；继续按状态、速度与真实位移判断 |
| 离水击飞、倒游、急救、隐藏换位、瞬移 | 停止生成和受益，断开路径；重生绝不连接旧位置 |
| 重生后正常水面游动且仍有保护 | 正常适用；无敌并不等于不能跟游，资格不得直接复用碰撞开关 |
| 心跳苏打、冷静冰沙 | 恢复体力／心率／推进等效果沿用原规则，尾迹只作用于普通手划成本 |
| 垃圾、漩涡、巨浪 | 阻力、水流和方向控制保留；尾迹不抵消这些效果，不随外部水流无限延长 |
| 定时水球携带与传递 | 不改变传递距离、冷却或保护；跟游有接近携带者的风险 |
| 完赛、退赛、离房、重开 | 立即撤销对应来源和受益状态；重开清空路径、计时和锁定成本 |

## 4. 玩家能够看见什么

- 身后留下沿实际路径弯曲的短水纹带，前端避开身体，末端自然淡出；有效范围与视觉范围使用同一组路径数据。
- 优先复用现有水面图集及尾流资源，必要时补一张小纹理；不为每个路径点创建节点、碰撞体或独立材质。
- 普通水花与有效尾迹需要可区分：有效带使用克制的色调与连贯轮廓，不能把所有白色泡沫都解释成 buff。
- 本地玩家进入后，在现有体力区域附近显示简短的程序字“跟游省力”；退出撤下。HUD 只在状态变化时更新，不新增按钮、不占广播和画中画区域。
- 隐藏特效或低画质只能降低显示成本，不能关闭离屏泳者的玩法判定。特效开关前后，相同输入的体力结果应一致。

## 5. AI 如何使用

第一版就包含基础跟游能力，确保单人试玩能形成队列：

1. 在既有低频决策中寻找前方附近、同向、可安全跟随的目标，不增加全场寻路。
2. 保体力阶段优先接入合适尾迹；已经有明显超车速度优势或进入现有冲刺阶段时，恢复争位和超车。
3. 保持安全前后间距，不为了精确居中持续顶撞前人；固定短决策窗避免频繁换目标。
4. 跟游意图低于娱乐事件避险与既有事件目标，不能为了省体力追进浮标、炮击、玩具鲨或水球危险区。
5. 估算体力预算时使用实际已结算手划成本，排除苏打恢复与技能消费的干扰；移除“每划至少 1 点”的旧下限假设。AI 不应把以后一直有尾迹当作必然收益。
6. 真人、AI、开发版玩家托管使用相同的折扣、范围、确认时间与退出规则。

## 6. 模块、性能和联机约束

### 实现分工

- 新增独立跟游配置和路径／资格计算模块，放在 swimmer 或同等聚焦目录；GameManager 只负责创建、传入泳者状态、更新顺序和销毁。
- 体力模型仍负责最终扣费。沿 SwimmerMotor 的真实起划时机锁定成本，并将每次实际结算成本交给玩家／AI 体力模型；不能简单把 AI 某一帧累计划数乘以最后一次折扣。
- 泳者提供轻量水面资格快照，明确区别于无敌、可碰撞和鲨鱼可攻击状态。
- 表现放到独立尾迹显示组件，AI 决策留在 AISwimmerController／AiRacePlanner，HUD 只消费状态。

### 第一版性能预算

- 按 8 人上限预分配，每人暂定最多 48 个路径采样点，环形覆盖；固定记录时间、位置、方向和路径代次，比赛变长不增加容量。
- 路径和关系计算以 15Hz 为起点；先做简单距离／方向筛选，再检查有限路径段。起划时的局部复核只检查候选来源，保持成本有界。
- 正常比赛更新不创建数组、对象、向量、闭包和调试字符串；标准模式不创建跟游系统、不采样、不更新跟游 HUD。
- 表现使用固定容量顶点缓冲或复用少量池化水面片，固定拓扑；禁止每帧新建网格或用 Graphics 重画。路径采样时才改必要缓冲，淡出用材质参数处理。
- 美术预算起点：全场额外不超过 2 次绘制提交、1 套共享尾迹材质；优先合并路径带，超预算先减少透明覆盖和表现层。此处是验收目标，尚无真机测量结果。
- 固定设备、视角、人数及事件种子，对比开关尾迹后的 CPU／GPU 帧耗、慢帧、绘制提交、透明覆盖和 GC；整局及连续重开内存不得持续增长。最终帧耗门槛在记录设备基线后确定。

### 联机落地

- 沿用现有权威划分：本机真人根据同步到的泳者状态确认自己的跟游与扣费；AI 由当前房主确认。远端真人不重复扣费。
- 将受益状态和来源编号紧凑地附带在既有状态快照中；真人随 owner 状态走现有可靠帧及原有降级兜底，AI 随房主快照校正。UI 使用相应权威状态。
- 所有广播兜底、序号保护和快照合并路径都要覆盖新增状态，旧包不得恢复已经退出的跟游。修改协议版本，旧版禁止混跑；不提前固定版本号，以实施时仓库最新版本为准。
- 不逐点传输视觉粒子或完整尾迹。远端路径由收到的权威位置有界重建，禁止从插值后的渲染节点反推玩法路径。
- 断流、首次收到位置、较大校正均中断采样，不把缺失历史插成一条长尾迹；来源数据过期后不再批准新折扣。
- 房主迁移保持已确认体力，清掉失效来源和旧任期 AI 跟游判定；新房主从可信位置重新建立路径并短暂重新确认，不能补扣或补发历史优惠。新房主权威状态覆盖其他设备的预测。
- 这种方式延续当前 owner 架构，网络延迟下边界时刻仍可能有短暂空间观感差异；验收目标是每个选手只有一份扣费结果、远端最终一致、没有重复或倒退，而不是声称跨端逐帧完全一致。

## 7. 分步实施与每步交付

1. **做出能准确省体力的尾迹规则。** 完成模式开关、有限路径、有效区、起划锁定成本与统一扣费。用直线／弯线／停止／折返轨迹证明范围正确，并验证有体力与耗尽边界。交付：狂野和娱乐可生效，标准结果不变。
2. **让尾迹范围与受益状态看得清楚。** 接入水纹带和“跟游省力”，处理转向、淡出、起跳、重生和低画质。交付：玩家能看出该跟哪里、何时正在省体力。
3. **让单人比赛出现跟游与超车。** 接入 AI 的低频选位、预算修正和避险优先级，并在调试面板暴露参数、加入可复现的跟游场景。交付：可通过玩家托管和固定阵容观察成队、省力、出队超车。
4. **接齐联机与娱乐组合。** 完成状态协议、真人／AI 权威处理、丢包乱序、断流、迁移及重赛；验证每种娱乐事件不会误清空常驻规则，也不会让尾迹抵消危险。联机实现完成前，测试版本明确限制为单机试玩，不能静默以各端独立扣费的方式上线。
5. **按完整比赛调整参数。** 同角色等级和输入条件对比不跟游、稳定跟游、跟游后超车的 200／400 米耗尽位置、完赛时间、节省点数与碰撞次数；再看不同角色及娱乐组合，防止长期跟游成为唯一优解。交付：一组可试玩默认值及真机表现记录。

第 3 步结束可进行首次单机手感试玩；第 4～5 步完成并通过设备验收后才视为该功能整体完成。调参继续维护本文件，不为每轮数值变化另建方案文档。

## 8. 验收清单

- 数值：在体力足够且每划起手均已确认跟游时，连续 20 次实际结算消耗 17 点；普通 20 次消耗 20 点。脱离后的新划原价，在途划价格不变，无重复扣费。
- 范围：直线、安全间距、弯线、边缘横摆、来源切换、重叠、自身旧尾迹、迎面和不同泳段均符合规则；不能依靠贴身碰撞才能获得收益。
- 生命周期：低速停止、起跳、潜水、折返、击飞、急救、保护期恢复、瞬移、完赛、离房、重开均无残留连接和历史优惠。
- AI：会适度跟游、会冲刺超车、会优先避险，真实预算反映折扣；不会为跟游长期左右抖动或顶住慢速领游者。
- 联机：不同本地座位、真人与 AI 混合、掉包、重复、乱序、降级广播、房主迁移、连续重赛；对同一选手的权威体力及受益状态最终一致。
- 性能：8 人尾迹与娱乐事件同时出现，关闭调试 HUD 后无调试更新；关闭尾迹表现不改变赛果；标准模式无新增尾迹开销；持续比赛和重开保持固定容量。
- 工程：修改 TypeScript 后运行固定 TypeScript 5.4.5 类型检查及上述针对行为的回归；新增静态文案运行 pnpm fonts:build、pnpm fonts:check。
- 如新增纹理，按项目流程等待 Creator 导入并保持元数据，再运行 textures:fix／textures:check。不自动启动／重启或截图 Creator。
- iOS／Android 微信真机确认实际读性、透明叠加、帧耗及双端一致性；离线测试不能替代这些验收，未完成项明确记录。

## 9. 第一版落地记录（2026-09-22）

### 已实现

- `DraftingRules.ts`：每人48点环形世界路径，15Hz采样；同泳段／同向／真实路径距离判定，短暂进入确认，重叠不叠加，低速残留与硬失效清理。起划额外复核来源及当前空间范围，瞬移后的旧确认不能继续用。
- `DraftingController.ts`：集中读轻量泳者状态，普通玩家、真正AI和玩家托管共用规则；潜水、海豚、折返、急救、完赛及重开切断路径。水面保护期不被误当成无资格。
- `SwimmerMotor` 每手动作保存起划成本，正常松手和超时均传递锁定值；`Swimmer` 向玩家投递每划成本、向AI累计实际成本。多人、双手或一帧多个结算不混用最后一次折扣。
- AI 使用普通手划累计账本估算跟游成本，技能扣费与补给恢复不会污染它；标准竞速保留原预算估算。非冲刺且体力低于85%时可选择附近同向队列，事件目标仍优先；速度明显更快时不强行跟队。
- `DraftingPresentation.ts`：复用 `RESOURCE_PATHS.swimmerSplashSurfaceTexture`，全场一个材质、一个固定容量动态网格；每个渲染尾迹的相机一次绘制提交，画中画另算相机开销。只在路径更新时上传缓冲；关闭水纹不关闭玩法。Cocos动态网格更新保留UV与索引流，避免流错位或遗漏索引。
- `RaceHudStatusView`：体力区显示程序字“跟游省力”，只改变节点显隐；耗尽优先，隐藏后清除，无限体力不显示无意义折扣提示。
- 调试面板新增“尾迹跟游”，12个参数存入 tuning.json。可开关整个机制或只关水纹，方便手感与性能对照。

### 联机实现与实际取舍

- 协议升级至 **104**。`S|`、`P|` 和输入帧自状态都复用原来的单字符完赛槽位，按36进制同时编码完赛位、水面资格与来源编号；**没有增加每泳道包长**。旧版0/1仍可解码为无尾迹资格，但房间禁止103及更旧客户端混跑。

## 10. 性能与联机复查（2026-09-22）

用户已认可第一版效果，本次保持水纹外观和15%折扣参数。

### 已复现并修复

- **房主切换后的起划窗口**：旧实现只在下一次尾迹更新时清路径，期间起划仍可能得到旧任期优惠。现在起划入口也检查当前房主，变化时立即清空确认；已经起手的划水仍按原锁定成本结算。
- **位置大幅校正后的采样窗口**：若领游者或跟随者在两次采样之间移动超过1.5米，即使仍落在旧路径范围，也必须立即拒绝旧优惠。采样重建与起划复核共用同一位移上限，并清除跳变者的来源确认。
- **客机AI沿用失效来源**：此前只看AI自身快照的受益位，来源已断流或离房时仍可能预测折扣。现在保留房主空间判定，同时核验来源编号、当前水面资格及有效快照；自身、越界、离水、离房和断流来源不再提供新优惠。
- 三个边界回归均先在旧实现上复现失败，再在修复后通过。它们影响新划成本，玩法协议升级为 **105**，各端必须同版；包字段与长度保持不变。

### 网格开销

- 仍预分配8人×47片上限，全场1个网格、1个材质，每个渲染它的相机1次绘制；路径与上传最多15Hz，标准模式不创建系统。
- 原实现每次清空并上传全部376片。现在初始化时按8片一档缓存缓冲视图，比赛中只上传有效前缀，尾部最多7片清零，减少人数后也不会显示旧残留。容量不增长，不在更新中创建视图或重建网格。
- 在可复现的8人、2.5米/秒、直游稳定路径测试中，每次上传由 **58,656字节降至21,216字节（约减少64%）**，提交三角形由752降至272；按15Hz计算约318,240字节/秒。具体值随有效路径片数变化，满容量上限不变。
