# 巨浪冲浪玩法与落地计划

更新日期：2026-09-22。

状态：独立 200 米调试模式已接入“随机双向起浪 → 顺浪助推／迎浪减速 → 到岸拍散”版本，等待用户在原调试会话确认实际画面与手感。入口为“调试模式 → 模式测试 → 巨浪冲浪”，支持“常规三波／单波定位”。正式娱乐候选池仍为七种，联机整合另行进行，其他候选玩法暂缓。

本文是此玩法唯一持续维护的规则、表现、AI、调参与联机说明。当前版本替代此前“在选手附近生成一段浪、按固定同行秒数消失”的规则，不再沿用旧版中途退场方案。

## 1. 已确认方向

用户认可当前“池端涌出小浪 → 逐渐长大 → 推进到对岸 → 拍岸回落”的美术，并确认将规则改为纯随机双向作用：每波从两端等概率抽一端，横向覆盖独立随机，不根据领先、落后、去程、回程或人群密度选择受益者。

同一道浪，顺向选手借力加速，迎向选手承受短暂阻力。保留约半池宽度及两侧逐渐降低的表现，玩家可以主动并入或侧移绕开，不增加操作按钮，不击倒、不停住、不倒退、不强制转向。随机保证不按人群选边，不保证每个人每局受益相同。

## 2. 随机方向与完整行程

| 阶段 | 规则与可见表现 |
| --- | --- |
| 预告 | 默认 3 秒，预告开始时锁定方向、横向位置、范围、浪速及作用参数；明确广播“出发端”或“折返端”即将起浪。 |
| 池端涌出 | 从已抽中的真实池端启动。初始小浪贴近水边，边前进边长大；前 1.2 秒不产生加速或减速。 |
| 行进成长 | 默认 3.5 秒完成低、窄、短的小浪到完整浪峰的生长，两侧逐渐降低并融入水面。 |
| 统一推进 | 全程按配置浪速行进，默认 4.2 赛程米／秒，再按场景泳程比例换算；取消根据队伍位置追赶、减速等人和同向游速中位数。 |
| 双向作用 | 进入浪面后按当前泳段方向判断：顺浪助推、迎浪阻碍；同一时刻可以对不同选手产生相反作用。 |
| 抵岸拍散 | 前沿抵达真实池壁后停止前移，浪体压缩，默认 1.2 秒内水片和碎滴扬起、向池内回落；抵岸停止玩法作用。 |
| 余沫消散 | 再保留默认 1 秒碎沫，逐渐淡出，不播结束广播。 |

生成与拍岸使用 `poolStartX/poolFinishX`，游速换算使用 `startX/finishX` 对应的选手游程比例。选手提前折返不改变浪的真实岸边落点。

默认浪宽为池宽 55%，长度为池长 12%，最高约 0.48 世界单位。横向中心在池内安全区均匀抽样，不随人群移动。方向和位置由 `SharedRNG` 的独立 `SeededRandom` 子流分别抽样；每波以比赛种子及波次派生，其他系统消耗随机数、跳过上一波或更换人群均不改变这一波的抽样结果。

每波方向为独立 50%／50%，允许连续同向，不强制交替、不按前几波收益补偿。调试重开保留同种子时可以复现结果；观察其他组合可换种子。预告开始后，不因选手折返、掉队、潜水或全员不在浪区而改方向或取消。

## 3. 排期

- 单波定位保留一波；常规三波仍在前三个单程安排预告，默认至少间隔 5 秒及顺浪余速时间。
- `anchorFraction` 默认为单程 4%，按领先赛程触发排期；不再读取领先者游速调整预告位置。比赛进度只决定何时安排事件，不决定方向、横向位置与浪速。
- 错过泳段跳过旧波，不集中补发；后续波使用自身随机子流。
- 首位完赛停止新预告，已激活波完成自身生命周期；退出／重开立即清理。

## 4. 顺逆作用、AI 与角色动作

- 成长期的作用中心、宽度和纵深跟随实际浪面；空间强度从中央向横向边缘平滑降低。只有正常水面游泳时生效。
- 顺浪默认增加最多 1.1 赛程米／秒推进，约 0.35 秒建立，离浪后约 0.6 秒释放；不改写原游速，不替代划水。
- 迎浪中央默认降低 30% 的自身前进速度，约 0.12 秒建立，离浪约 0.2 秒恢复；边缘阻力更小。按比例作用于当前前进速度，疲劳慢游或静止时不会变成倒退，也不吞掉原碰撞反冲。
- 正负作用共用一个有符号状态槽，过零时分别积分助力和阻力，避免独立增益／减益叠加及帧率差异。短路径采样覆盖迎面快速穿浪，瞬移不补算整段作用。
- 海豚、潜水、折返、击倒、停止比赛及重开清理正负作用；折返完成后按新泳段方向重新判断。角色随浪的小幅抬升使用作用强度绝对值，叠加原游姿和碰撞姿态，不改变物理高度。
- AI 与玩家托管每 0.15 秒消费公开预告与位置：顺浪向浪内分散并入，迎浪选最近可用侧边，靠墙窄侧放不下则走另一侧；已经在浪外不额外转向，抵岸前停止追浪／避浪。
- 同一状态条每 0.1 秒更新：“借浪加速／继续划水”或“迎浪减速／侧移避浪”；共用原组件并缓存显示，不重建 HUD。

## 5. 美术重做与性能预算

本版使用固定低面数网格与顶点色，不新增贴图、GLB 或自定义 shader，也不修改场馆、水面材质或角色资源。

| 层 | 表现 | 几何预算 |
| --- | --- | --- |
| 主浪体 | 薄透后坡、青蓝浪腹、浅青卷唇、疏密变化的白色浪冠、前方回落水片；两侧以正弦平方降低并渐隐 | 348 顶点／616 三角形 |
| 碎沫尾流 | 三条宽窄、疏密不同的弧形碎沫合为一层，随行程展开，到岸后向水边铺开，最后消散 | 261 顶点／336 三角形 |
| 拍岸水花 | 接真实池壁的扇形薄水片、起伏浪尖与 12 颗分离小滴，朝池内弯曲、扬起并回落 | 193 顶点／248 三角形 |

合计 802 顶点／1200 三角形、3 个网格／3 个材质，常态显示两层，拍岸短时最多三层。泡沫细节合并网格，不逐滴创建节点、不逐帧修改几何。透明材料复用 `builtin-unlit` 的混合技术，启用深度测试、关闭深度写入，尾流／浪体／拍岸使用明确渲染优先级。

运行期只写显隐、变换与透明度，缓存相同属性；透明度量化，浪冠轻微起伏采样 30Hz，不分配每帧数组／向量。隐藏时直接返回。所有资源在模式创建时建立一次，重开复用，销毁释放。

画中画展示起浪成长，并在抵岸瞬间重新显示拍岸收尾。声音仍复用拍水音效，仅起浪、本地首次顺浪搭乘和抵岸各触发一次；专属连续水流声尚未制作。

透明覆盖和实际排序需在微信 iOS／Android 真机确认。1200 三角形和最多三层是代码预算，不代表已经测得真机帧耗。

## 6. 调试与配置

调参仍在 `TuningDebugControls` 的“巨浪冲浪”组，按原 JSON 机制保存。当前 17 项覆盖宽度、纵深、浪高、预告、入场保护、成长、拍岸、余沫、间隔、统一浪速、顺浪推进、迎浪减速、正负建立／恢复和预告锚点。

- 新增 `giantWave.travelSpeed`、`giantWave.boostSpeed`、`giantWave.oppositionSlowdown`、`giantWave.oppositionRiseSeconds`、`giantWave.oppositionReleaseSeconds`。
- 移除旧追人参数 `catchSeconds`、`approachSpeedScale`、`catchSpeedScale`、`cruiseSpeedScale`、`boostScale`；旧保存项不再驱动行为。此前固定同行秒数 `cruiseSeconds` 同样已停用。
- 方向、横向位置及生成类参数在预告时锁定；浪高在本波起浪时读取。建立／恢复时间实时生效。切换三波／单波预设后重开。

## 8. 本版验收

当前巨浪专项 15 项通过；连同划水、体力、画中画和调试 UI 回归共 43 项，42 项通过。唯一未通过项是另一项水球改名工作的旧 UI 断言：预期“定时炸弹模式”，实际已为“定时水球传递”，本轮未覆盖其修改。

固定 TypeScript 5.4.5 类型检查通过；随包字体已重新生成并通过 1606 字符的字体审计。既有动态预览已按本版统一浪速和随机方向重新导出。

本轮保持用户已认可的三网格美术，只调整规则、预告、状态条和 AI。专项验证覆盖：

- 同种子改变人数、位置、朝向、游速和资格，预告与实际浪完全相同；4000 个种子检查双端约半、允许连续同向、横向无方向偏置、独立子流不扰动公共随机数。
- 预告后不重抽，跳过旧波不改变下一波；单波／三波、完赛收尾、预告及行进恢复、坏数据和旧版本拒绝。
- 同一浪面对顺逆选手产生相反作用，侧边更弱，入场保护及拍岸无作用；真实 Motor 的 30% 阻力、不倒退、原游速和碰撞保留、折返及重开清理。
- 正负过零与离浪恢复在 30／60／120Hz 一致；真实移动路径验证顺浪受益、迎浪短暂受阻及侧移退出。
- AI 按同一份预告并入／绕行，窄侧不可达时选择另一侧；广播来源与抽中的真实池端一致，状态条区分两种作用。
- 原固定几何、隐藏零工作、重开不增资源、到岸水花与余沫生命周期继续回归。

## 9. 联机预留方案与后续恢复验收

首版调试入口限定本地单机，不新增巨浪网络消息、不改正式房间协议、不开放巨浪房间。当前仅把规则、波状态和推进贡献设计为可读取、重置及恢复的独立数据，并用离线恢复测试验证接口。下面的实际双端同步、协议升级与弱网验收在独立玩法通过后、正式整合前完成，不将单机调试通过写成联机可用。

当前项目为混合模型：真人移动由本人端权威提供，AI 移动与最终成绩由房主权威提供。巨浪是持续环境作用，优先沿用漩涡式移动权威链路，不能把它简单实现成房主每帧拉动所有真人。

### 9.1 权威分工

- **房主决定公共浪状态**：候选位置、方向、参考速度、起始时刻、阶段时长、代次、取消和结束。
- **本人端推进自己的角色**：消费已接受的公共浪状态，结合自身位置／动作计算持续贡献；新消息对时不能重复施加过去整段加速，也不回滚本地输入。
- **房主推进真正 AI**；远程真人继续跟随 owner 自报的位置与运动状态，不将本地副本的进出浪判定当作权威。
- 新增巨浪贡献具有短暂余速，不能只同步位置而遗漏它。按需要在 owner frame self／`P|` 和 AI 的 `S|` 追加量化贡献值与搭乘状态，保证姿态、HUD、恢复与接管一致。
- 本方案不把“首次进入”做成离散奖励，无需逐次可靠发放冲刺；进入视觉只消费权威／owner 状态变化。

### 9.2 同步内容与通道

建议公共描述包含：比赛身份（沿用现有外壳）、房主代次、事件激活序号、波次／revision、阶段、公共模拟时间、起点世界坐标、横向中心、宽度、纵深、方向、参考速度、各段时长及结束边界。固定配置可通过同版本规则省略重复传输，最终字段由编解码预算确定。

- 激活、取消、结束走既有可靠玩法事件通道；周期快照补足当前完整状态，覆盖漏收起浪消息的情况。
- 连续浪位置从统一描述与公共模拟时钟求得；访客只插值／有限外推，不各自重新选择路径，不使用本机墙钟累计无限时长。
- 广播降级复用现有恢复体系。快照优先于早到可靠事件时，旧起浪事件不能重开；同版本时间只能前进，已结束不能被旧包复活。
- 长断流不能无限延长收益：沿已接受的硬结束时间衰减退出；恢复后直接呈现当前阶段，不补发错过时段的位移。
- 房主迁移从已同步描述继续原波，并恢复 AI 的贡献状态；不重新抽路线、不重置追浪期。旧房主、已离房成员和异局消息先过滤再处理。
- 开局不创建巨浪对象的单机普通模式保持原路径；联机分支仅在有效网络会话下运行。

正式接入需要升级玩法协议，版本号以实施当时基线为准。现有完整八人快照含外壳有 1536 字节回归预算，必须测量新增最坏情况；若不够，沿项目既有方式采用有界独立状态包，而非偷偷放大限制。独立包仍需同样的身份、代次、乱序与恢复保护。
