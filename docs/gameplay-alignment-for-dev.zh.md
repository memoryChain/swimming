# Swimming 玩法改造对齐文档

## 1. 当前版本的问题判断

当前版本已经有完整的原型闭环：

- 倒计时
- 跳水
- 划水输入
- 稳定性判定
- 推进与速度
- 完赛与结算

但核心问题也很明确：

- 规则层过度集中在“稳定匀速输入”
- 稳定性几乎是唯一制胜条件
- 跳水、中段、终盘没有形成明显不同的玩法目标
- 表现层弱，很多规则只存在于后台数值
- 情绪层太平，缺少紧张、压迫、逆转和爆发

一句话总结：

- 当前版本更像“带竞速外壳的游泳推进模拟原型”
- 目标版本应转向“有阶段结构、状态经营和终盘爆发的竞技游泳游戏”

## 2. 三条改造主线

### 2.1 规则层

目标：

- 让玩法博弈不再只围绕稳定性展开
- 引入新的策略变量
- 让开局、中段、终盘拥有不同规则目标

### 2.2 表现层

目标：

- 把后台规则前台化
- 放大好与坏、顺与乱、稳与崩的差异
- 让玩家一眼看懂当前状态

### 2.3 情绪层

目标：

- 让整场比赛形成明确情绪曲线

目标情绪主线：

- 紧张
- 稳定
- 压迫
- 逆转
- 爆发

## 3. 三阶段玩法方向

### 3.1 第一阶段：跳水博弈

目标：

- 建立开局差异
- 让跳水不只是数值判定，还要影响开局状态

当前问题：

- 只影响起步距离和起步速度
- 好坏差异不够可读

目标方向：

- 跳水结果同时影响物理开局和开局状态
- 表现上要有明显的漂亮入水 / 普通入水 / 慌乱入水差异

### 3.2 第二阶段：中段控节奏

目标：

- 把中段从“机械频率输入”改成“状态经营”

当前问题：

- 规则存在，但玩家不容易感知
- 玩起来更像后台评分器，而不是前台状态经营

目标方向：

- 玩家不只是比输入频率
- 还要经营当前状态和资源

### 3.3 第三阶段：终盘冲刺

目标：

- 提供追赶与反超的真实路径
- 给领先者守成压力，给落后者搏命空间

当前问题：

- 终盘没有独立权重
- 落后后很难追回

目标方向：

- 终盘自动进入
- 玩家主动管理冲刺强度
- 高风险高收益的过载区成为合法策略

## 4. 规则层核心变化

这次改造最关键的规则层变化是：

- 引入体能
- 用心率作为围绕体能运作的中间状态量

这是当前规则改造的核心共识。

## 5. 新规则结构：体能 / 心率 / 动作质量

### 5.1 体能

体能是新的核心策略资源。

它承载的是：

- 前中段要不要省
- 什么时候应该赌
- 终盘还能不能高质量爆发

结论：

- 体能是核心策略维度

### 5.2 心率

心率不是独立策略资源，而是围绕体能运作的显性状态量。

它承载的是：

- 当前输出状态是否合理
- 当前是不是在正确区间
- 当前还能不能继续高压
- 当前状态是否接近失控

结论：

- 心率是体能策略的前台表达
- 心率是规则层和表现层之间的桥

### 5.3 动作质量

动作质量层保留现有系统的核心价值：

- 按住比例
- 局部时机
- 连续稳定性

结论：

- 动作质量仍然存在
- 但不再单独统治整场比赛

## 6. 一条必须明确的规则层共识

后续实现中，建议固定这条原则：

- 输入决定下限，心率决定上限和容错

它的含义是：

- 玩家输入太差，不会因为状态条对了就自动打对
- 但当输入基本合理时，心率和体能会决定这一下到底能兑现到什么程度

## 7. 心率系统的规则理解

### 7.1 心率区间

第一版建议四区间：

- `LOW`
- `OPTIMAL`
- `HIGH_PRESSURE`
- `OVERLOAD`

### 7.2 区间意义

- `LOW`：状态没拉起来，效率偏低
- `OPTIMAL`：动作最顺，体能利用率最佳
- `HIGH_PRESSURE`：主动拉速度，风险与成本上升
- `OVERLOAD`：搏命区，适合终盘短时爆发

### 7.3 阶段化解释

区间本身可以固定，但不同阶段的奖励函数不同：

- 开局：奖励快速进入 `OPTIMAL`
- 中段：奖励长期维持 `OPTIMAL`
- 终盘：奖励合理进入 `HIGH_PRESSURE`，必要时短时使用 `OVERLOAD`

## 8. 体能系统的规则理解

### 8.1 基本原则

- 体能是存量资源
- 心率是即时状态

### 8.2 消耗逻辑

第一版建议：

- 体能按连续方式燃烧
- 当前心率区间决定燃烧速度
- 当前比赛阶段再决定燃烧权重

### 8.3 空体后果

体能见底后，不应直接失去操作权。

建议规则：

- 仍可继续游
- 但高质量爆发能力显著下降
- 动作容错下降
- 高压收益衰减
- 过载区维持成本上升

一句话：

- 空体后不是停机，而是还能拼，但开始发虚

## 9. 跳水与状态系统的联动

跳水不应只输出：

- `distance`
- `speed`

还应输出对开局状态的初始化影响。

设计结论：

- 好跳水不等于单纯更高心率
- 更准确地说，是更接近有效启动区

跳水应影响：

- 开局心率起点
- 开局心率稳定度
- 进入最佳区的速度

## 10. 前台反馈怎么改

### 10.1 主反馈

后续前台主反馈建议改成：

- 心率条
- 身体状态表现
- 节奏稳定 / 失稳的整体感受

### 10.2 局部反馈

不建议继续让 `PERFECT / GOOD / BAD` 作为主反馈。

但建议保留它们的痕迹，以轻量方式表达：

- 条瞬时闪色
- 脉冲
- 水花差异
- 动作顺滑 / 发虚
- 轻量音效反馈

结论：

- 心率是主反馈
- 局部评级只保留痕迹，不再作为主舞台

## 11. 终盘冲刺共识

### 11.1 终盘进入方式

不建议做成纯手动技能触发，也不建议做成纯自动演出。

当前共识：

- 终盘阶段自动进入
- 进入后，玩家主动决定冲不冲、冲多猛、冲多久

### 11.2 终盘的四种选择

终盘应允许玩家至少有这四种选择：

- 稳冲
- 压冲
- 赌冲
- 收一手

### 11.3 领先与落后

基础规则应对称，不建议直接做硬性落后补偿。

但终盘的策略价值可以非对称：

- 领先者更倾向于稳
- 落后者更倾向于赌

结论：

- 非对称应来自风险收益结构，而不是直接规则豁免

## 12. 程序结构上的落地建议

为了避免现有类继续膨胀，不建议把新规则直接塞进已有核心类。

### 12.1 现有类建议保留的职责

- `RaceManager`
  - 负责比赛全局阶段、计时、完赛

- `GameFlowController`
  - 负责流程编排、阶段切换、跳水流程、终盘进入时机

- `SwimmerMotor`
  - 负责局部动作判定和原始推进结果

- `Swimmer`
  - 负责实体行为与表现映射

### 12.2 建议新增的中层结构

第一版建议新增：

- `RaceContext`
- `PlayerConditionModel`
- `DiveResult`

## 13. 第一版建议新增的三个对象

### 13.1 `RaceContext`

作用：

- 承载本局比赛的共享上下文

建议持有：

- 当前主阶段
- `PlayerConditionModel`
- 当前 `DiveResult`
- 是否进入终盘

### 13.2 `PlayerConditionModel`

作用：

- 承载心率、体能和阶段状态修正

第一版最小字段集建议：

- `phase`
- `heartRate`
- `heartRateZone`
- `energy`
- `energyDepleted`
- `sprintTier`
- `qualityModifier`
- `efficiencyModifier`

### 13.3 `DiveResult`

作用：

- 作为跳水阶段对后续比赛的初始化包

第一版最小字段集建议：

- `qualityTier`
- `entryStyle`
- `entryDistance`
- `entrySpeed`
- `heartRateStartModifier`
- `heartRateStabilityModifier`
- `optimalZoneEntryModifier`

## 14. 推荐的数据流

第一版建议把数据流整理成这样：

1. 输入进入 `SwimmerMotor`
2. `SwimmerMotor` 输出原始动作质量和原始推进结果
3. `PlayerConditionModel` 根据动作质量更新心率和体能
4. `PlayerConditionModel` 输出状态修正
5. 外层再用这些修正值修正动作兑现和推进收益
6. `Swimmer`、UI、镜头、特效读取状态模型做表现

一句话：

- 动作层先算原始值
- 状态层再修正兑现结果

## 15. 第一版重构顺序建议

不建议一口气大拆。

推荐顺序：

1. 新增 `DiveResult`
2. 新增 `PlayerConditionModel`
3. 新增 `RaceContext`
4. 让 `GameFlowController` 驱动状态模型接入现有主循环
5. 再逐步把 UI / 表现 / 终盘规则接到新状态层

## 16. 当前版本的最小共识总结

如果要用一句面向开发的总结收束当前方向，可以概括为：

- 这次改造不是推翻现有动作输入核心，而是在现有动作层之上增加一层“体能驱动、心率显性化”的比赛状态层。

更具体一点：

- 保留现有动作质量和推进逻辑的基础价值
- 引入体能作为新的核心策略资源
- 用心率作为体能策略的前台状态量
- 让跳水、中段、终盘真正形成阶段化目标
- 用更强的表现层和情绪层把后台规则前台化
