# 赛前展示与赛后颁奖流程设计

> 参考游戏：马力欧与索尼克奥运会（东京2020）游泳项目。
> 游戏风格：夸张搞笑风竞技，侧重轻松诙谐。目标平台：微信小游戏。

---

## 一、当前流程现状

当前游戏主流程为：

```
READY -> PRECOUNTDOWN(2.35s镜头推入) -> COUNTDOWN(321倒计时)
  -> DIVING(跳水蓄力) -> GLIDING(入水滑行) -> RACING(比赛)
  -> FINISHED(直接弹结果面板)
```

存在的问题：

1. 赛前只有一个 2.35 秒的镜头推入，没有角色登场、亮相、热身等展示环节。
2. 选手虽然站在跳台上，但只是静止站立，没有赛前展示动作。
3. 完赛后直接弹 UI 结果面板，没有颁奖仪式，和 3D 场景脱节，缺乏沉浸感。

---

## 二、新增流程概览

```
赛前:
READY
  -> [选手信息展示]  UI 信息卡 + 全景拉正面 + 全员站立    3-4s
  -> [选手特写亮相]  快速近景逐个 + 各自赛前动作         3-4s
  -> [倒计时起跳]    321 倒计时 + 全员屈膝准备           3s
  -> DIVING(现有跳水蓄力流程)

赛后:
FINISHED
  -> [成绩展示]  UI 成绩卡 + 颁奖台背景 + 三人已站位     2-3s
  -> [颁奖台环绕] 镜头环绕 + 三人各自获奖动作            3s
  -> [冠军特写]  冠军近景 + 独特庆祝动作                 2-3s
  -> showResult(现有结果面板)
```

- 赛前总时长：约 9-11 秒
- 赛后总时长：约 7-9 秒

## 三、赛前展示流程

### 段落一：选手信息展示

| 要素 | 描述 |
|------|------|
| UI | 屏幕中心显示选手信息卡，每个选手包含：赛道编号、名称。具体信息卡内容暂不细化，后续补充 |
| 镜头 | 先是赛道全景俯拍，然后从远景缓慢拉到选手正面 |
| 角色 | 所有选手按赛道横排站立，面向镜头，静止亮相 |
| 时长 | 约 3-4 秒 |
| 结束 | UI 信息卡淡出消失 |

作用：让观众和玩家认识所有参赛选手，建立比赛氛围。镜头从远到近的缓慢拉入配合 UI 信息展示，节奏沉稳。

### 段落二：选手特写亮相

| 要素 | 描述 |
|------|------|
| UI | 无（信息卡已消失） |
| 镜头 | 快速近景依次扫过每个选手，按赛道顺序（1 到 8），每人约 0.8-1 秒 |
| 角色 | 被特写的选手播放自己的赛前展示动作，从赛前亮相池中分配 |
| 时长 | 约 3-4 秒（取决于选手数量） |
| 结束 | 最后一个选手特写结束，镜头切回全体 |

作用：展示每个选手的个性和赛前状态。搞笑风格下，每个选手的赛前动作不同，制造差异化笑点。

### 段落三：倒计时起跳

| 要素 | 描述 |
|------|------|
| UI | 大字 3-2-1 倒计时（复用现有倒计时 UI） |
| 镜头 | 锁定主选手正面近景（复用现有 countdown 镜头） |
| 角色 | 所有选手从站立姿态切换到屈膝准备姿态（DiveReady） |
| 时长 | 3 秒（现有 COUNTDOWN_SECONDS） |
| 结束 | 倒计时归零，进入跳水蓄力阶段 |

作用：衔接现有比赛流程，角色姿态切换为屈膝准备，和现有的 diving 蓄力机制无缝衔接。

### 镜头风格

段落之间采用混合切换：

- 段落一内部：平滑过渡（远景缓慢拉到正面）
- 段落一到段落二：硬切（信息卡消失后快速切到第一个选手特写）
- 段落二内部选手之间：硬切（每人一个镜头，快速跳切）
- 段落二到段落三：平滑过渡（最后一个选手特写推近，过渡到倒计时镜头）

## 四、赛后颁奖流程

### 段落一：成绩展示

| 要素 | 描述 |
|------|------|
| UI | 屏幕中心显示选手成绩卡，每个选手包含：赛道编号、名称、最终成绩。具体信息卡内容暂不细化 |
| 背景 | 切换到颁奖台场景（冠亚季军三级台阶） |
| 角色 | 前三名选手已站在颁奖台对应位置，未上榜选手不渲染 |
| 时长 | 约 2-3 秒 |
| 结束 | UI 成绩卡淡出 |

作用：让玩家先看到完整成绩，再进入颁奖视觉展示。背景从泳池切换到颁奖台，场景转换带来仪式感。

### 段落二：颁奖台环绕

| 要素 | 描述 |
|------|------|
| UI | 无（成绩卡已消失） |
| 镜头 | 围绕颁奖台环绕一圈，拍全景 |
| 角色 | 颁奖台三人各自做获奖动作：冠军从冠军池随机抽取庆祝动作，亚军从亚军池随机抽取沮丧/不甘动作，季军从季军池随机抽取平和/开心动作 |
| 时长 | 约 3 秒 |
| 结束 | 环绕结束，镜头推向冠军 |

作用：展示颁奖台全貌，三人不同的动作形成对比。冠军狂喜 vs 亚军摆烂的反差是搞笑风格的核心笑点。

### 段落三：冠军特写

| 要素 | 描述 |
|------|------|
| UI | 可选显示冠军名称或"冠军"字样 |
| 镜头 | 特写冠军选手正面近景 |
| 角色 | 冠军播放独特庆祝动作。第一版沿用环绕时的同一动作，后续可扩展为独立特写动作池 |
| 时长 | 约 2-3 秒 |
| 结束 | 淡出，显示结果面板（复用现有 showResult） |

作用：给冠军专属高光时刻，冠军的动作应该是全场最夸张最有喜感的。

### 镜头风格

- 成绩展示到颁奖台环绕：硬切（UI 淡出后镜头直接切到环绕起始位）
- 环绕内部：平滑运动（匀速环绕）
- 环绕到冠军特写：平滑过渡（环绕结束减速，镜头推向冠军）
- 冠军特写到结果面板：淡出过渡

### 颁奖台站位

```
        [1名]           <- 最高台阶
      [2名] [3名]        <- 中台阶 / 低台阶
    ==================
    终点池边
```

- 1 名居中靠后，站位最高
- 2 名和 3 名分列两侧靠前，台阶高度递减
- 三人面朝镜头方向（即面朝泳池侧方）
- 未上榜选手不渲染

## 五、动作分配规则

| 阶段 | 对象 | 分配方式 | 动作池 |
|------|------|---------|--------|
| 赛前特写 | AI 选手 | 每场随机抽取 | 赛前亮相池（8 个） |
| 赛前特写 | 玩家选手 | 玩家手动自选 | 赛前亮相池（8 个） |
| 赛后环绕 | 冠军 | 随机抽取 | 冠军池（7 个） |
| 赛后环绕 | 亚军 | 随机抽取 | 亚军池（3 个） |
| 赛后环绕 | 季军 | 随机抽取 | 季军池（4 个） |
| 赛后特写 | 冠军 | 玩家自选（AI 冠军随机） | 冠军池（7 个） |

说明：

- 玩家在设置入口选好自己的亮相动作和庆祝动作，每场比赛固定使用。
- AI 每场随机，保持新鲜感。
- 冠军特写第一版沿用环绕时的动作，后续可扩展为独立的特写动作池。
- 不加鞠躬收尾动作，初版保持简洁。

## 七、动作筛选说明

以下动作经讨论后从池中排除：

| 动作名 | 排除原因 |
|--------|---------|
| Taunt - Flexing Muscles | 前置有握拳动作，不适合游泳比赛 |
| Taunt - Pointing At Wrist | 前置有握拳动作，不适合游泳比赛 |

## 八、技术实现要点（概要）

以下为后续开发参考的技术要点，本版文档以流程设计为主，技术细节在实施时再细化。

### 新增 GameState

在 `core/GameConstants.ts` 的 `GameState` 枚举中新增：

- `INTRO`：赛前展示阶段，位于 `READY` 和 `PRECOUNTDOWN` 之间
- `CEREMONY`：赛后颁奖阶段，位于 `FINISHED` 之后、结果面板之前

### 涉及的核心模块

| 模块 | 改动方向 |
|------|---------|
| `app/GameFlowController.ts` | startGame 改为先进入 INTRO，INTRO 完成后进入 PRECOUNTDOWN；onRaceFinished 改为先进入 CEREMONY，CEREMONY 完成后再 showResult |
| `camera/RaceCameraDirector.ts` | 新增赛前多机位镜头序列和赛后环绕/特写镜头序列 |
| `character/CharacterPoseStateController.ts` | 新增赛前和赛后的角色姿态状态 |
| `character/CharacterAnimationPlayer.ts` | 复用现有 playClip 方法播放 Mixamo 动画 |
| `ui/UIFlowController.ts` | 新增选手信息卡和成绩卡的显示/淡出 |
| `core/ResourcePaths.ts` | 新增赛前和赛后动画 clip 路径注册 |

### 新增文件（预期）

| 文件 | 职责 |
|------|------|
| `app/IntroSequenceController.ts` | 赛前展示阶段时序编排（镜头段落切换 + 角色动作分配 + UI 时序） |
| `app/CeremonySequenceController.ts` | 赛后颁奖阶段时序编排（颁奖台生成 + 角色转移 + 镜头切换） |
| `venue/PodiumBuilder.ts` | 程序化生成三级颁奖台（低面数方块，单色材质） |

### 动画资源导入

1. 从 Mixamo 下载动作（FBX 或 in-place 格式），角色需与现有 `UserSwimmer0621_2` 同骨架。
2. 导入到 `assets/resources/animations/intro/` 和 `assets/resources/animations/ceremony/`。
3. 在 `ResourcePaths.ts` 的 `ANIMATION_CLIPS` 中注册新 clip 名。

### 性能约束

- 目标平台为微信小游戏，动作 clip 需控制面数和骨骼数。
- 颁奖台用程序化生成（`primitives.createBox`），低面数单色材质。
- 赛后未上榜选手不渲染，只保留前三名。
- 单段动画时长不超过 5 秒，总流程不超过 10 秒。
