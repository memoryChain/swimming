## Cocos 设置与构建约束

- 配置集中在 `config/build/wechat-remote-assets.json`，云端与微信模拟器验证后已设为 `enabled: true`。
- 每次微信构建先经过原本的纹理、mip、字体、动作和脚本依赖检查，再由 `extensions/wechat-race-subpackage/remote-assets.js` 转换资源布局。
- 此方案使用项目构建扩展自动转换，不要求手动勾 Creator 的远程包按钮。原有构建扩展仍先生成本地中间分包；不要另外手改引擎或生成的 JS。
- `assets/race/ui.meta` 定义嵌套 `ui` Bundle（优先级 8，高于 `race` 的 7），保留原素材 UUID。只有 `ui` 的 `config/import/native` 放到 CDN，原样保留 UUID、依赖、ASTC 及 PNG/JPG 回退。`index.js` 移至微信本地 `src/bundle-scripts/<bundle>/`，不从 CDN 加载代码。
- 运行时设置使用 Cocos 3.8.8 微信适配器原生支持的 `assets.remoteBundles`、`assets.server`，`RaceBundleLoader` 将逻辑路径 `ui/...` 路由到 `ui` Bundle 并移除前缀，其余路径仍在 `race`；不在各页面散落 URL。
- `gameplay` 和 `startup-ui` 仍为微信分包，登录图片、引擎及首屏代码保持本地。
- UI 不使用整包 ZIP，按文件及 Cocos 依赖下载。角色、动作和泳馆共同使用 `race` 微信原生分包，由引擎调用微信分包下载；首次进大厅会下载整个 `race`，并非角色/场景分别下载。文件下载完成后仍按使用时机解析、实例化。共享依赖不复制，已下载文件走缓存。
- 发布路径只使用负责人填写的 `clientVersion`。构建启用 Creator 原生 MD5 Cache，资源、Bundle 配置和本地脚本引用均使用对应的 MD5 文件名；同号反复构建共用目录，只有变化文件新增，不覆盖旧包仍引用的文件。
- SHA-256 的 `contentHash` 仅用于完整性和清单匹配，不作为版本目录。构建包 `src/cdn-release.json` 固化 `clientVersion` 和摘要；构建后修改版本配置或混用其他构建的清单会拒绝发布。
- 远程文件发布目录在微信构建目录之外，不靠上传忽略规则掩盖包体。

## 按需加载与登录交接

1. 点击「开游」或邀请拉起后先读取云端存档，新用户沿用现有默认角色初始化。
2. 加载 `race` 微信分包，只挂载当前大厅，加载该页实际使用的 UI、字体、当前角色及展示动作。未打开的角色页、赛事弹窗、房间和结算页面不预热；不扫描全部 UI，不遍历全部角色实例，也不在登录解析整套比赛动作或全部音频。
3. 登录遮罩等待当前页面的嵌套资源、角色就绪及两帧渲染提交后移除。进度为分包/页面初始化阶段进度，不是字节下载百分比。失败可重试、销毁可取消，迟到回调不能重新放行。
4. 打开其他页面时才请求其 UI 图片；有效缓存同步返回。首次页面打开可以有加载等待，符合当前按需策略。已创建页面与角色实例仍复用，隐藏角色不更新。
5. 初次进馆，`prepareVenueResources()` 从本地分包集中解析泳池、天空盒与材质，随后创建场景与选手；完整比赛动作仍在进馆加载。赛前/比赛 UI 此时从 CDN 按需加载，现有整场加载遮罩与联网就绪门禁继续覆盖此过程。
6. 邀请目标仍在登录期间保留，加载完成后自动进入最新目标房间；不改存档、联机协议或保活重赛逻辑。

旧 `LobbyCharacterPreload.ts`、全量 UI 路径扫描、逐资源 16ms 解析队列及 `prepareForEntry()` 全角色初始化均已移除。

按旧构建的文件统计估算：仅移出 UI 原生文件约 7.77 MiB，即可使微信本地总量约为 21.74 MiB（尚计入 UI 导入数据，因此此估算偏保守）。它不是新构建实测，新构建仍必须经过主包 4 MiB、总包 30 MiB 的检查；最终以微信上传统计为准。

## 日常自动发布（无需浏览器手动上传）

日常操作：Creator 选择微信小游戏，点“构建” → 等待自动上传、公开下载校验及构建成功 → 微信开发者工具打开 `build/wechatgame`，点“上传”。正常发布无需打开浏览器或执行命令，也无需再双击上传脚本。

`config/build/wechat-remote-assets.json` 已开启 `autoUpload: true`。构建扩展在本地纹理、mip、字体、动作和包体检查全部通过后，使用官方 SDK 和既有 CLI 登录态增量发布本次资源版本，等待完整性检查后才结束构建。上传失败、授权过期或下载校验失败都会使构建失败；解决原因后重新构建。不要把失败构建目录中的代码直接上传微信。

构建使用独立 Node.js 20+ 运行发布工具，不复用 Creator 的 Electron；支持常见安装目录及 `SWIMMING_NODE` 环境变量指定路径。换电脑需先安装 Node、执行 `pnpm install` 和 `pnpm cdn:login`。构建不会自动发起新的授权。

构建会先读取云端对象清单，比对文件大小、存储 ETag/MD5 与已验证记录。相同版本全部命中时，资源上传为零，仅下载当前远程 UI Bundle 配置检查公开访问。同号构建直接跳过同目录已有资源，只有变化文件新增；负责人修改 `clientVersion` 时才创建新目录，未变资源可从旧目录云端复制。旧包引用保持不变。新增或缺少验证记录的资源通过公开 HTTPS 下载做 SHA-256 校验；云端复用项检查复制前后存储摘要一致，复用原 SHA-256 校验记录。上传加校验整体最长 15 分钟。需要离线仅导出时，可明确将 `autoUpload` 改为 `false`，但必须手动发布资源成功后才能上传微信代码。

### clientVersion 接入与 MD5 适配
