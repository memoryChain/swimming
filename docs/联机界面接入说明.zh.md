# 联机界面接入与维护

## 已接入内容

- 1280×720 布局，复用角色详情背景、白色斜切页头和返回图标；货币与设置仍由公共 `ResourceHeadBar` 提供，保留微信胶囊避让。
- 房主卡与成员区顶部对齐；固定八个服务端座位，空位不会因为有人退出而被其他成员挤占。
- 当前头像与昵称取玩家信息；当前使用角色、等级复用已有 `MOD` 养成摘要，没有增加重复角色图片。
- 房主可展开浅色赛制抽屉；成员只读。房主主按钮为“开始比赛”，成员为绿色“准备”或浅蓝灰色“取消准备”。
- 玩家信息深色弹窗：成员不能踢人，房主不能踢自己或当前房主；二次点击确认后调用平台正式踢人 API，并在调用前复查座位、客户端标识、昵称和头像。
- 被踢成员显示退出提示。准备失败、退出失败、踢人失败不伪装成功。

## 切图工作流

源稿为本地 `docs/ui-production/online-room-psd-v1/划水大师-联机-1280x720-v6-成员已准备.psd`，设计源目录按现有规则忽略，不随代码提交。先在 Photoshop 打开对应源稿，再运行 `scripts/export-online-room-runtime.jsx`。

脚本逐项复制工作文档、隐藏文字层、按固定边界裁切、导出 PNG 并关闭副本。角色详情背景、页头、返回、大厅绿色按钮和头像直接引用已有资源。

导出后运行：

```sh
python3 scripts/optimize-ui-images.py --root assets/race/ui/online-room-v1 --apply
```

这是项目已有的无损 PNG 重编码工具，会校验逐像素一致并备份原文件。当前 16 张新切图合计约 49 KiB，不应把 Photoshop 未压缩的约 3.7 MiB PNG 直接交付。

让已有 Creator 会话完成导入并生成 `.meta`，再运行 `npm run textures:fix`、`npm run textures:check`。不要手写 UUID、删除既有 `.meta`、自动启动或截图 Creator。不要把按钮文字烘焙到图片内。

## 字体

静态中文标题、按钮与说明使用项目 `ShuiMaster UI SemiBold`。联机英文与数字沿用公共金币栏的 `Arial Black` 系统字体声明，统一入口是 `ProjectUiFonts.ts` 的 `PROJECT_UI_ENGLISH_BOLD_FAMILY`；覆盖座位号、等级、房间号、人数和距离，昵称内的英文数字也沿用该声明。动态昵称的中文保留系统完整字形回退，不能换成只含静态文案的中文子集。

注意：工程目前只打包了中文 Regular/SemiBold 两个 TTF，`Arial Black` 不是内置英文字体资源；缺少该字体的设备会使用系统回退。PS 源稿使用的是 `Arial-BoldMT`，与金币现有 `Arial Black` 不同。本次先按“沿用工程现有英文粗体”接入，不能把本机预览通过当成跨设备字形一致。若需要两端完全一致，应由设计确认可分发的英文字体文件后接入真实字体资产，不要擅自复制系统商业字体。

距离拆成数字与“米”两个固定 Label，本地预览文字与真实房间编码使用各自字体的固定 Label，通过显隐切换，避免异步中文字体加载覆盖英文字体。六位房号按 `826 419` 格式展示，只改变显示，不改变服务端房间标识。修改文案后运行 `pnpm fonts:build`、`pnpm fonts:check`，不要手工维护字符表。

### PS 排版复核记录

后续确认：八个成员空位的“邀请好友”使用 `ShuiMaster UI Regular`、19 号字，保留字号、颜色和位置；赛制上拉标记改为项目字体中的 14 号实心三角 `▲`，整行 320×54 点击区域不缩小。顶部“点击空位邀请好友”的说明字重保持原样。

以 v6 分层稿的文本图层数据为准，不能只根据截图目测所有文字都用一个深色：

| 用途 | 字色 | 字号／对齐 |
| --- | --- | --- |
| 标题、昵称、主操作 | `#091E46` | 房主 34，成员区标题 27，主操作 38 |
| 页头与退出 | `#17243A` | 页头约 36，退出 28 |
| 角色名、房间号标签、赛制说明、邀请说明 | `#49648C` | 成员角色名 14；邀请说明与赛制权限右对齐 |
| 等级 | `#134297` | 22，右对齐 |
| 人数、已加入、当前赛制 | `#00B395` | 人数 42，已加入 24，左对齐 |
| 成员昵称／角色名／准备状态 | 主色／辅助色／状态色 | 19／14／16，分别保留独立行 |
| 弹窗角色名／关闭／踢出 | `#B5C9E1`／`#C8D8ED`／`#FF9E8F` | 14／22／19 |

所有 Label，包括动态昵称，必须显式设置 `lineHeight = fontSize + 4`，并保证行高不超过文本框高度。Cocos 默认行高 40 配合 27 高的昵称框与 SHRINK 会导致意外缩字，离线浏览器预览不能复现全部引擎字体行为；回归测试应模拟默认行高并检查这条约束。等待提示位于右下主按钮正上方，赛制名称左对齐，数字和单位独立排版；第二行成员位与第一行相隔 217 像素。

当前分支原本缺少 package.json 的字体脚本，已恢复跨平台入口。首次运行 `pnpm fonts:setup`，需要 Python 3.10 或更新版本；若系统 Python 太旧，可用 `UI_FONT_PYTHON` 指定解释器。工具固定为 fonttools 4.64.0，安装到被忽略的 `.cache/ui-font-venv`，不会改系统 Python。

## 联机协议与边界

- 协议版本由 10 升为 11；两台真机都需更新，同旧版本混连会被版本检查阻止。
- 房主广播赛制身份、修订号与模式；成员准备确认绑定该赛制版本。每 1.5 秒重发，丢包后可恢复；准备 ACK 带递增序号，旧 ACK 不得覆盖取消准备。
- 房主切换赛制清除旧准备确认；成员需重新准备。准备请求过程中收到新赛制，旧请求成功也不得恢复准备。
- 开赛消息附带一致赛制，成员必须已准备且赛制版本相同才进入；当前实际赛距依然统一 200 米，未根据设计示意图修改平衡配置。
- 房主迁移以服务端客户端标识更新平台 owner 状态；新房主可继续设置、开赛、踢人和退出转移房主。
- 保留原 keep-alive 重赛流程，绝不通过 `endGame` 或重复 `startGame` 修复重赛。
- 房间定时器进入比赛或销毁时停止，不新增比赛逐帧工作。
- 既有广播接口只提供消息字符串，没有服务端认证的发送者信息；赛制广播沿用项目现有可信客户端模型，不应视为防篡改安全边界。踢人通过微信服务器校验房主权限，不能用广播模拟踢出。

正式踢人接口与参数依据微信官方类型定义：`GameServerManager.kickoutMember({ kickoutPos })` 和 `onBeKickedOut`。参考：[微信小游戏官方类型定义](https://github.com/wechat-miniprogram/minigame-api-typings/blob/master/types/wx/lib.wx.api.d.ts)。

## 验证

运行 `pnpm test:room`、`pnpm test:net`、固定 TypeScript 5.4.5 类型检查、字体检查与纹理检查。离线排版预览：`pnpm ui:room:preview`，结果在 `output/online-room-runtime`，不作为真机验收依据。

真机仍需验证：iOS 与 Android 的字体和透明边缘；微信胶囊避让；双端准备／取消准备；换赛制后重新准备；房主退出后的权限移交；踢人与被踢通知；弱网重试；比赛返回后的第二局。所有测试应在两端同为协议 11 的包上进行。
