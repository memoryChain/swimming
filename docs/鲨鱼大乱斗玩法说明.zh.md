# 鲨鱼大乱斗玩法说明

## 已确定规则

- 玩法归入“娱乐模式”，固定为 200 米。
- 鲨鱼属于关卡，不属于任何角色技能，也不消耗角色蓄气。
- 比赛开始后第 15、35、55 秒各触发一轮追猎。
- 第一轮前鲨鱼隐藏；首次出现后，轮次之间继续在泳池低速巡游，并作为会推挤选手的重型障碍。
- 每轮按距离选择最近且可攻击的选手，先警告和锁定，再给予短暂变向窗口，随后追击。
- 每轮最多咬中一人；被咬者进入 2.5 秒急救阶段，本地玩家画面压暗并显示“急救中……”，随后在原赛程进度和自己的泳道中心重新入水，初速度清零。
- 重新入水后获得 2 秒无敌保护；击倒和无敌期间不能再次被鲨鱼锁定。
- 巡游鲨鱼与选手逆向持续接触时，若选手约 1.5 秒无法有效前进，或从接触后的最远进度被反向推回 0.8 米，鲨鱼会直接补咬并让选手走现有急救复活流程。短暂擦碰、同向同行、仍能正常前进以及急救／无敌状态均不触发。
- 巡游补咬后同一选手有 6.5 秒防重复判定时间（覆盖 2.5 秒急救、2 秒无敌及额外脱离时间），鲨鱼自身两秒内也不会连续补咬其他选手。
- 第三轮追猎结束后，鲨鱼下沉并停止参与比赛；不会因为咬中选手而提前结束整场比赛。

## 表现

- 使用正式 `SharkModel`、循环游动动画、目标锁定标记与咬合水花；首次现身会先在安全出生点的水下保持游动，并在第一轮三秒警告的前 1.1 秒上浮，接近水面时复用现有池化大水花。上浮阶段不参与碰撞或咬人，不额外延长比赛节奏；后续巡游和再次锁定不会重复进场。
- 咬伤瞬间先保存角色的世界接触点，再复用角色现有的大水花在该位置明确喷发，遮住人物与鲨鱼交叠；鲨鱼画中画当前目标不会被主镜头的离屏水花裁剪误关。被咬者用 0.18 秒过渡到项目已有的竖直踩水姿态，表达被重物撞停。仍不增加咬合专用网格、材质或常驻更新。
- 画中画复用娱乐玩法共用的 256×144 RenderTexture 和事件相机，只在警告、追击和咬合阶段开启，最高 30Hz；巡游阶段不额外渲染。面板位于右上排名栏左侧，并避开微信胶囊与安全区。
- 警告从泳池全景推进到鲨鱼本体；咬合后画中画保留约两秒。
- 巡游补咬不额外打开画中画或增加新网格，只复用鲨鱼短促下扎、大水花、竖直受击和急救提示。
- 鲨鱼横幅已提炼为六种娱乐玩法共用的赛事广播和个人反馈；文字按状态边沿更新，不在每帧重写。击倒阶段使用独占压暗层，无敌提示使用统一持续状态条，角色节点始终复用，主镜头持续跟随原目标。

## 联机权威

- 单机直接运行同一套关卡控制器。
- 水下上浮完全由既有首轮 `WARNING`、序号和剩余时间驱动，只改变模型视觉高度；不新增联机字段，也不改变权威鲨鱼位置和判定。
- 联机只由房主决定目标、轨迹、咬合与击倒；其他设备不自行判定结果。
- 持续纠缠计时同样只在房主运行；房主使用收到的远程真人权威位置判断接触、方向和进度，再沿用现有可靠鲨鱼击倒事件广播结果。
- 击倒使用可靠帧事件同步泳道和权威重生距离；周期快照携带鲨鱼完整状态，以及各泳道的击倒／无敌阶段和剩余时间兜底。
- 房主掉线后，新房主从最近收到的鲨鱼和恢复状态继续运行，不重置轮次或让选手永久离场。
- 鲨鱼急救表现和统一提示语义自协议版本 61 起生效；当前全局协议版本统一以 `NetRaceProtocol.ts` 和联机总文档为准，旧客户端不能与当前版本混跑。

## 验证清单

- 单机确认首轮鲨鱼从水下游动上浮、破水大水花在主镜头和画中画均可见、上浮完成前不会推挤或咬人，且后续轮次不重复进场；同时确认三轮时间、最近目标切换、持续逆向推挤会补咬、擦碰和同向同行不会误咬、2.5 秒急救、速度清零、2 秒无敌和镜头连续跟随。
- 双端分别让房主和访客被巡游鲨鱼逆向推挤，确认均由房主在相同阈值结算，且目标、画中画、咬合、恢复阶段和重生位置一致；同时测试房主在三种状态下退出。
- iOS／Android 微信真机确认第一轮游动动画、水下模型可见性、上浮和破水时机、画中画开关、大水花遮挡范围、模型贴图及比赛帧耗时。
