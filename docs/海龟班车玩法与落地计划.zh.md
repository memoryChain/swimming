# 海龟班车玩法与落地计划

更新日期：2026-09-28。版本：实施规格 v3（池端先龟后圈入场）。

**状态（2026-09-28）：已完成本轮 Blender 海龟、厚圈、握带、绳索重制并接入；按全部11个正式角色校准双手抓握，修正乘客锚点、抓取扫掠、发车提前量、软避让与出入场。桌面自动验证和 Blender 离线样件已检查。当前开发分支已有娱乐候选入口，但这不代表 P5 发布验收通过：未打开 Creator，也没有本轮微信 iOS／Android 真机画面、双端弱网与性能结果。第14节记录当前实现及前文方案的收敛。**

本文统一维护规则、模型动作、联机、参数、实施与验收，不再为每轮讨论另起文档。历史“鸭鸭班车”主体已改为大海龟。

## 1. 目标、确认项与首版范围

一句话：大海龟从出发／折返池端附近浮起，用绳子拖着游泳圈提供一趟慢速省体的公共班车；选手自动双手抓圈，能被撞落，也能恢复左右划水自然离车。

### 1.1 用户已确认

| 项目 | 确认规则 |
| --- | --- |
| 主体与连接 | 大海龟拖三四个游泳圈，人物用双手抓圈 |
| 上车 | 靠近空圈自动抓住，无上车按钮 |
| 主动下车 | 哪只手真正开始划水，哪只手松开；另一侧也起划后完全脱离，正常交替即可，不要求同时操作 |
| 单手状态 | 停划后保持单手抓圈，不自动把松开的手抓回；连续同侧划水不等于双手松开 |
| 碰撞 | 乘客保留人物碰撞，可以被其他选手撞落 |
| 收益 | 不提供正常划水之外的速度优势；乘车停止划水消耗，以较慢车速换体力 |
| 发车方向与时机 | 房主共享种子决定短随机等待，再选择池端可搭窗口和方向；不强制追随人数最多的泳向或等到单趟末段 |
| 航次 | 单程横穿泳池一趟；到另一端下客、下潜收车，不同轮内往返 |
| 进出场 | 池端浮起；先释放所有乘客，再收拢空圈、随海龟下潜；不吊装 |
| 被替代方案 | 不采用“单侧长按0.4秒直接下车”，不新增松手按钮，不按鸭子或鲸鱼制作 |

### 1.2 本计划采用的首版默认值

以下是为执行补齐的设计默认值，不冒充用户逐项确认：

- 一只海龟、四个独立拖圈，一圈一人，绳子前端连接海龟背带，后端连接各圈。
- 四圈横向展开并小幅前后错开，全部位于海龟后方；不串成只能从最后上车的单列。
- 途中持续开放空位，直到进入到站减速阶段；撞落乘客不会自动把座位转给撞人者。
- 固定路线、固定单次速度曲线；以四圈可接近为先，首版直行，仅圈和四肢有轻微摆动，不加入蛇形改道、急转弯和甩人技能。
- 不划水不消耗划水体力，也不恢复体力；心率沿现有自然回落和锁定规则，蓄气沿现有被动增长规则，不额外发放班车奖励。
- 单手抓圈较容易被撞落；主动下车不额外加速，被撞落不额外附加眩晕/急救惩罚。
- 先完成开发版独立测试，再完成娱乐池、现有事件组合和联机接入。达到全部验收门槛后才开放正式候选。
- 首版一个固定强度；调试可改参数，但不为凑五档同时开放五套未经验证的联机规则。未来五档不增加同时存在的海龟或改变下车操作。

## 2. 一趟班车的完整过程

### 2.1 班车状态

`WAIT_WINDOW → PREVIEW_RISING → BOARDING → ACCELERATING → CRUISING → UNLOADING → SUBMERGING → DONE`。

| 阶段 | 初始时长/条件 | 可见动作与玩法 |
| --- | --- | --- |
| 等待发车窗口 | 到达本事件原赛程锚点后，最多18秒 | 先按共享种子等待0.5～2.49秒，再低频寻找可搭泳段和出生安全位置 |
| 预告并浮起 | 3秒 | 黄色预告与上浮并行；前1.2秒海龟本体浮起，0.35秒后逐渐软推附近选手；1.2秒起四圈间隔0.12秒随后浮起，约2.16秒全部出水。3秒后开放抓圈；入场不击倒、不伤害 |
| 缓游接客 | 0.6秒 | 转红色行动提示，持续3秒；开放空圈，按1.85赛程米/秒缓游 |
| 稳定车速 | 0.6秒 | 从1.85微升至2赛程米/秒，绳子绷紧，人物平滑接上牵引 |
| 巡航 | 由剩余路程决定 | 固定2赛程米/秒；乘客跟圈修正最多2.2米/秒，不叠加个人划水速度 |
| 到站下客 | 进入终点端安全范围 | 立即关上车，保持碰撞；0.6秒减速到1.85赛程米/秒并释放剩余乘客，角色继续正常游向折返/终点 |
| 空车下潜 | 约1.4秒 | 确认占座为零、人物已解除牵引；海龟向前下潜，空圈依次牵入水中 |
| 结束 | 尾部水花消失 | 清理玩法引用、占位和镜头，不播全屏结束广播 |

这里的“终点端”指本趟目的池端，不一定是比赛最终终点。两端使用同一套方向转换和真实池壁数据。

上浮包含在3秒预告中，不能额外串行等待“3秒预告＋上浮＋长时间接客”。这既提供可见准备，也避免车刚开时所有人已游远。

预告时冻结班次编号、方向、纵向出发位置、横向位置、圈布局和速度曲线。正式发车随机性由共享种子生成，房主选中的出发位置写入 `TB|` 快照；访客不自行重抽。装饰随机不得影响赛果。

### 2.2 池端空间与终止

- 所有纵向玩法参数统一用赛程米；通过 `RaceCourseLayout` 转成世界距离。横向距离按泳道宽度/人物实际接触尺寸计算。禁止把实际池长、人物起终点间距、累计赛程直接混用。
- 出发位置固定在出发／折返短边池端向内约7世界单位处，按场地比例换算为赛程米并向上量化到0.1米；不再随选手位置移动到池中段。这段留白容纳四个拖圈和最长角色身体。允许本体附近有人，上浮渐进侧推；圈、绳索和人物不得伸出池壁。
- 卸客阈值初值为海龟中心到本泳段42米处。实际阈值取该值与“龟头、减速距离、前鳍、身体和池壁余量”的更保守结果。不能等龟头撞墙才停。
- 减速前关闭新抓取；所有乘客在本泳段内释放，实际位置不改回出生泳道、不跳赛程、不替代触壁判定。
- 首位完赛：未预告班次取消；预告中的空车取消上车并下潜；已载客班次停止接收新乘客，现有乘客完成本趟到站释放。全场进入结算/退出时立即解除人物绑定，再清理实例。
- 班车自己下潜后不能留下可抓取的隐形圈。销毁、异常超时和场景退出必须先统一 `releaseAll(reason)`，再销毁节点。
- 本轮从预告至退场设30秒硬上限。超时按当前位置安全释放并退场，不冲刺穿墙、不强行延长比赛。

## 3. 发车窗口与搭乘机会

### 3.1 先随机等待，再找真正可搭的泳段

1. 正式事件到达原赛程锚点后，以房主共享种子计算0.5～2.49秒的短等待；开发灰模也使用可复现的种子短等待，玩家可以直接观察随机发车。
2. 每0.25秒检查当前泳者，种子决定候选泳者与横向路线的尝试顺序。临近折返的多数人不再支配发车方向；少数方向若有可搭窗口也能发车。
3. 分别检查两个池端，纵向出发点固定。对相向接近者预测到壁减速、转身蹬墙和水下滑行，使用当前转身时长、角色蹬墙倍率及水阻估计出水时间和位置，禁止把水下穿过圈算作可搭。最后一趟触壁是完赛，不能预测一次不存在的折返。
4. 编队须在池内，且至少两名仍在比赛的泳者能在预告后10秒内抓到不同圈并保留至少2秒车程；单人或独立试玩允许一名。可达性包含横向移动、抓取确认和联机预留，慢车主要由身后选手追上空圈，不靠突然冲刺追人。
5. 预告后冻结方向、纵向出发位置和横向路线；联机由房主广播并在快照中重复携带。随机顺序只决定可行候选之间的选择，不能跳过出生安全和抓圈资格检查。

### 3.2 等待、取消和导演衔接

- 原赛程锚点作为最早申请时机，加入班车专属的发车许可，不改其他事件的锚点和预告时长。海龟不能排本局最后一个事件槽，也不加入首版返场池。
- 班车控制器随本局选中结果装配，预告阶段允许它消费自己的计划并显示上浮；抓圈和伤害接触仍以BOARDING之后的资格开关为准。不能为了显示上浮提前设置正式激活/驻留标志，误触发其他系统的玩法判定。
- 等待18秒仍无窗口：在任何海龟预告出现前，用预先生成的候选顺序替换该槽。替代事件必须未被本局选中，并通过完整顺序校验，保留200米3～4种、400米5～6种及三类保底；不减少种类数、不随机重抽整局。
- 替代顺序由种子确定，房主发布新的导演修订；访客不能本地自行替换。替代是未公开计划的修订，不伪造“海龟已发车”。
- 当前六候选扩为七候选后，非末槽总有可校验的替换空间；测试必须覆盖3～6事件及三类保底。若未来清单变更使无合法替代，开赛编排时即剔除不满足条件的海龟槽，不能临场默默减一事件。
- 预告后不因人群移动改变已承诺路线。本体附近有人不再推迟入场：上浮前0.35秒不推人，随后0.85秒逐渐增加到正常软推速度。泳圈始终无推挤体积，3秒后按水面、同向、空位规则自动吸附。
- 班车专属 active 时长由冻结路线推算到下客完成，加0.5秒余量；不套用普通事件的0.75/1.4时长乘数。导演 `canFinishCurrent` 在下客完成前为false，之后允许下一段正常间隔，剩余空车退场仅作短时驻留。
- 现有残留事件继续工作；不为班车清场。入场规划检查现有硬障碍和漩涡核心，不把必经路线穿进不可通过的危险区。
- 若回放中大量替换/取消，视为排期设计失败，调整锚点窗口或参数后重验，不能用“有兜底”代替有效出场。

### 3.3 现行可达性与测试边界

发车规则用相同的分段慢速轨迹枚举抓圈时间，含3秒预告、0.6秒接客、0.6秒稳定速度、最少2秒可搭时间，以及不同人物分占不同圈的匹配。固定池端起点配合折返、蹬墙和出水预测；不同种子改变最早等待时刻，但都必须等到有效窗口。自动测试覆盖真实角色的翻滚与水下滑行、两端方向、非等比池长、最终触壁不虚构折返；仍需真人操作和联机弱网验证实际可抓比例。

## 4. 四个圈、上车与人物状态

### 4.1 编队与几何

- 四圈共用网格材质，可用顶点色/材质实例参数区分色彩；外观不代表不同加成。
- 左右对称、内外错列，圈间人物接触椭圆至少留0.25个角色接触宽度的空隙。摆动极值也不得导致四个乘客不断自撞。
- 编队总宽目标不超过池宽的55%，两侧都留可游通路；若最大体型放不下，先调整错列和圈间距，不能缩小人物碰撞体冒充放得下。
- 牵引带贴合龟壳，绳子避开鳍的运动范围，连接点有真实几何接触；圈后有左右两个可辨认握点。
- 仅海龟本体采用轻量平面软阻挡：接触引导角色侧滑绕过，不触发击倒/急救、不附赠攻击。泳圈与绳索完全不推人，靠近空圈的合格选手直接吸附到握位。
- 人与人继续用原碰撞规则。绳子不作为拦截泳池的碰撞体。海龟不被选手推动改变预定路线。
- 软推速度沿现有调参上限，横向目标限制在池内；路线预留两侧空间。龟身正中央按稳定泳道编号选择挤开方向，避免房主／访客数组顺序不同导致向相反方向推。软避让不是刚体无穿透保证。

### 4.2 抓圈资格与仲裁

- 正常水面、有效比赛、同向、非转身/海豚/潜水/击倒/恢复保护、非忽略人物碰撞状态；使用正式资格快照，不按可见模型高度猜测。
- 没有另一圈占用，没有重抓限制，接近的是空圈后侧。迎面经过不能自动被反向拖走。
- 抓取默认采用宽容自动吸附：相对精确乘客锚点，纵向差−1.15～0.65、横向±0.9世界单位。进入范围即占空圈并由马达一次对齐圈后位置；不能要求玩家先精确摆出最终抓握姿态。相对速度上限仍为4赛程米/秒，迎面经过不反向拉走。
- 默认确认时间为0，当前帧已靠近即抓住；相对轨迹扫掠用于同帧候选排序。大位置校正不沿途补抓，帧末已离开区域不远程吸回。吸附范围可单机调试，联机使用统一默认值。
- 同一判定步多人争圈，按合格接近区间先后、归一化接近距离、稳定参赛座位依次裁定；相同输入重放结果一致。联机不承诺消除网络延迟差异。
- 一名选手与一个圈只能建立一份占位；房主当步仲裁，不增加预留或伸手等待。抓稳时取消旧划水，之后新的左右起划逐手松开。

### 4.3 人物状态与左右手语义

`FREE → CLAIMING → HOLD_BOTH → HOLD_LEFT / HOLD_RIGHT → FREE`；撞落、有效特殊动作、到站释放可从任意抓握态直接到FREE。

| 当前状态/输入 | 结果 |
| --- | --- |
| 刚上车的1.2秒内，左右手真正起划 | 保持双手抓圈，消费动作编号；保护结束不补执行这些松手动作 |
| 双手抓圈，左手真正起划 | 左手松开并正常划水，仅右手保持抓圈 |
| 双手抓圈，右手真正起划 | 右手松开并正常划水，仅左手保持抓圈 |
| 仅右手抓圈，再次左划 | 仍仅右手抓圈，不能误记作双手松开 |
| 仅右手抓圈，右手起划 | 当步先解除牵引，再进入该次正常划水 |
| 单手抓圈，停止输入 | 保持单手；不计时自动抓回，不强制下车 |
| 保护结束后，两侧同一步真正起划 | 双手都松开，只处理一次离车 |
| 普通短点踢腿 | 不算手臂起划，不松手；仍有原踢腿表现 |
| 潜水角色短点实际触发有效潜水 | 先双手脱离再执行原潜水，不能把海龟拖入其动作 |
| 满气海豚按钮成功触发 | 先双手脱离，再沿原资格和费用执行；失败点击不让人掉下车 |

- 以SwimmerMotor真正开始一划为准，而不是触摸按下、松开、原始InputRouter回调次数。现有队列/自动续划都必须经过同一个起划通知。
- 起划通知增加侧别和单调动作编号；不能只在最外层按钮回调里松手，遗漏AI、键盘或续划入口。未搭乘时仅一次空监听/状态短路，不创建动作事件对象；单调编号沿马达既有动作时序维护。
- 抓稳前已开始的一划和旧按住状态不作为新松手动作：抓稳时取消旧动作剩余部分，不退款、不补发超时/失误/质量奖励，旧推进残量不带入搭乘叠加；对应旧长按等待实际松开后重新接受新按下。抓取接近期间出现的新起划优先取消尚未完成的抓取。
- 抓稳后新发起的离车划水，保留原起手体力、心率、质量和能力结算，一划只结算一次，不额外收“下车费用”，不因下车清空刚开始的新动作。
- 单手划水时原动作可以继续，但海龟牵引只补足追随需要，不能计算为“海龟速度＋完整个人游速”。尚未释放的划水预算不能在离车瞬间一次性补发。
- 牵引期间不享受其他泳者尾迹减耗、不生成可领优惠的尾迹；离车后按真实路径重新建立，不能把海龟本身当选手来源。

## 5. 牵引、碰撞与脱离

### 5.1 运动解算顺序

1. 接受有效网络事件和本步真实起划；处理已确认的击倒/特殊动作/主动脱离。
2. 从冻结路线与权威阶段计算海龟及各圈的玩法锚点。视觉摆动使用独立的小幅偏移，不反向改变结果。
3. 抓圈后用较慢车速取代划水推进，并在2.2赛程米/秒以下作小幅跟圈修正。保留人物独立根节点，不直接parent到圈上、不每帧写死其位置。
4. 使用实际运动速度（包含牵引）处理人物碰撞，保留位置分离、击退、侧滚和俯仰。
5. 根据本步真实受击、牵引偏离与抓握状态判断脱离。碰撞后不能再强制拉回锚点抹掉结果。
6. 写权威/owner状态，随后显示扶圈或自由动作。离车动画不延迟操控释放。

位置转换必须在人物当前泳段内进行，不能用世界X反推到另一个累计泳段。牵引的世界位移通过马达更新赛程，不能只移动显示节点而不更新排名。

### 5.2 撞落规则

- 新接触产生的有效击退用该角色经既有体重分配后的平面冲量判断，首试双手1.4米/秒、单手0.9米/秒；数值与原碰撞单位对齐。
- 轻擦只让角色/圈偏移并保留抓握。新撞击超过门槛即双手脱离；原击退与转体继续，不额外添加第二份“班车撞击”。
- 持续挤压使手掌超出可达范围，也应松手：持续0.12秒超过该角色可达上限时释放。可达上限由实际肩臂长度校准，不能只给全部角色同一固定根距离。
- 上车接近阶段的追随误差、船正常加速、装饰摆动和网络校正不算真实撞击；但上车期间不提供人物碰撞无敌。
- 碰撞大角度翻滚即使冲量数值偏小，也不能把手臂拉成长绳；手臂约束越界时退出抓握，原翻滚继续。
- 现有SwimmerCollisionImpactListener偏向水花，只给世界接触信息，不足以确认谁掉落。给碰撞解算新增可复用的按选手结果缓冲，包含本步接触、新接触冲量和分离位移；不要借水花回调推测乘客身份或重复做一套人物碰撞。
- 新接触、持续挤压和网络校正分开标记；多次松弛迭代不重复累计受击次数。

### 5.3 下车后的速度和再次上车

- 主动下车继承当前实际前进/横向速度，不另赠冲刺；交给正常阻力衰减。牵引通道撤销一次，不能在马达里留下一份持续助推。
- 撞落保留该步实际速度和已结算冲量，不能先清零再补一份，也不能使用碰撞前的班车速度覆盖击退。
- 到站释放继承已减速后的实际速度，不跳位置；之后正常游到墙边。
- 脱离后全圈重抓冷却初值0.8秒，并且必须实际离开原圈抓取区外再重新接近。冷却到期但一直重叠，仍不自动吸回。
- 空圈立即释放给其他人，不把前乘客冷却套给全体；撞人者同样满足靠近规则才能上车。
- 离开原因保留枚举：划水、撞击、超出抓握、技能、到站、击倒、断流兜底、取消/销毁。用于动作、恢复和调试，不需要逐帧打印日志。

## 6. 与现有事件和角色能力的组合

总原则：海龟不是无敌罩；角色仍按原资格受影响，重复结果只结算一次。致命/恢复事件先释放牵引，再执行原恢复流程。

| 系统 | 首版规则 |
| --- | --- |
| 苏打/冰沙 | 按乘客真实世界位置和原资格拾取。体力/心率效果照常；冰沙的个人推进倍率不改写海龟发动机速度，离车后的剩余时效照常 |
| 定时水球 | 携带者可搭车、继续计时；乘客之间及车外按原传递距离、方向、锁定与冷却交接，不自动沿四圈轮流传球。携带者结算先离车再恢复，外围冲量可能撞落其他人 |
| 水球点名 | 瞄准真实乘客位置，预警和判定照常；受击先解除牵引，海龟不替人挡弹 |
| 玩具鲨 | 乘客仍可被选中和撞到；命中照常恢复，海龟不改变鲨鱼既有路线或受击规则 |
| 漩涡 | 对乘客施加原水流，牵引有上限；过度偏离抓握则脱离。不能用抓圈硬锁抵消漩涡。海龟按已冻结路线，不新增动物被吸走的第二套运动 |
| 障碍场 | 乘客真实接触瓶子、餐盒和浮标，沿原阻力/冲量/击倒规则处理。海龟不碾碎或清除物品，入场规划避开不可通过路线 |
| 巨浪独立调试 | 个人浪效与牵引通过同一外部推进合成入口消费，不把两种速度直接相加；实际外力超出抓握能力则离车。巨浪仍未加入统一候选，不顺带开放 |
| 恢复保护/忽略碰撞能力 | 状态有效时不允许新抓圈；搭乘中若获得此类与可撞落冲突的状态，先释放，保留能力本身 |
| 海豚/潜水/转身 | 成功开始前释放；技能费用和网络输入沿既有路径，不假触发技能来实现下车 |
| 完美连击等被动 | 真正划水依旧走原能力计数；抓圈静止不伪造PERFECT或划水次数 |
| 标准与狂野比赛 | 不实例化海龟控制器、不注册相关热路径，不改变现有行为 |

组合首测按补给→人物碰撞→障碍→水球点名→定时水球→漩涡/玩具鲨推进。禁止用互斥掉全部现有事件来掩盖组合问题；若某组合未通过，海龟保留开发入口，不能带着未定义结果进正式池。

## 7. AI与玩家托管

- 用同一套上车、手臂起划、碰撞和重抓资格；AI不得直接指定occupied或瞬移到圈后。
- 决策每0.15秒更新，最多评估四个空圈。估计拦截时间、转向距离、剩余搭乘时间和路径危险；选择有收益的目标，目标保持至少0.3秒减少左右摇摆。
- 普通抢圈意图与补给同级低优先，低于紧急浮标/炮击/鲨鱼避让；按剩余收益和转向代价在同级目标中选择。
- 已在车上时不继续输出日常交替划水，否则AI会立即自己下车。危险退出时发送真正的左右起划，正常消耗与动作相同。
- 同侧碰撞有可达机会且抢座收益高时允许卡位；不增加专用攻击键，不让AI超出正常转向能力追车。
- 人群分散、空车驶远或剩余收益不足时放弃追赶；不能长期横游追一个已无法接近的圈。
- 玩家托管直接使用同一决策，远端真人的回放控制器不运行本地抢圈AI。

## 8. 模型、动作、UI与性能

### 8.1 资产与动作交付

| 项目 | 首版内容 | 验收重点 |

- 作者源与导出脚本放 `art/turtle-bus/`。运行时拟用 `assets/race/items/TurtleBus.glb`、`TurtleTowRing.glb`、`TurtleTowRopes.glb`，资源常量集中到ResourcePaths，沿race子包加载，保留.meta。

- 人物可参考RecoveryFloatPose已有左右臂接触解算，但新建TurtleBusGripPose，不直接更改急救扶圈动作，也不把急救状态复用成乘车状态。

- 原型允许简化几何，正式模型须在主跟拍、反向跟拍和共用画中画尺寸下检查，不能只凭Blender近景通过。

### 8.2 HUD与镜头

- 复用娱乐广播：暂用四字栏目“海龟班车”。黄色预告明确出发端，红色行动字为“班车发车 · 靠近空圈搭乘”，结束静默。
- 20组配对广播由独立子流选择，不能改变路线/速度随机；左右池端文案与实际方向一致。
- 本地搭乘复用无图标EntertainmentStatusStrip：双手时“搭乘中／左右划水松手”，单手时“右手抓圈／右划松手”或对应左手。四圈占用通过实体显示，不加四套屏幕跟随标签。
- Label约10Hz消费量化状态且只在文本变化时赋值；显隐、颜色与Tween按状态边沿修改。隐藏时不格式化、不投影、不分配。
- 画中画只短暂拍入场和发车，默认约2秒，服从共用事件镜头仲裁；水球紧急事件优先。不得常驻第二个相机/RenderTexture，主镜头继续跟玩家。
- 中文保持程序字，沿用ShuiMaster UI真实字体；新增文案后执行fonts:build与fonts:check。

### 8.3 性能目标（待真机测量，非已达成指标）

- 最多1只海龟、4圈、4根绳、4乘客抓握；未启用时零新增比赛帧工作。
- 新增模型几何合计目标不超过6000三角面，海龟1个蒙皮渲染器、圈4实例、绳1个渲染器；共享简单材质。新增主体主视角目标不超过6次绘制，水花额外最多2次；画中画重复绘制另计，不能假定共享材质必然合批。
- 绳预制小骨架目标不超过16骨；海龟动画骨架目标不超过16骨。人物只叠加现有骨架，无额外人物副本。
- 主逻辑按既有步长，玩法碰撞保持原更新频率；装饰摆动/抓握表现按30Hz或现有角色姿态采样上限，AI约6.7Hz、发车检查4Hz、HUD10Hz。不得降频玩法来换美术性能。
- 根运动和网络状态持续正确；离屏只裁剪表现，不停止座位、碰撞和下客。
- 复用数组/向量/颜色，池化接触与网络编码缓冲；不逐帧new、不逐圈启动Tween。
- 增量CPU目标为指定iOS微信测试机P95不超过0.8ms，且不造成超过一帧的持续卡顿；这是初始预算，P0记录基线机型与场景后固定比较。超过预算先剖析姿态/碰撞/绳/画中画各项。
- 新PNG/GLB由现有Creator会话生成.meta后执行textures:fix/check；不自动启动或重启Creator，不截取其窗口。最终在用户现有会话和iOS/Android真机验收。

## 9. 联机权威、消息与恢复

### 9.1 权责分配

沿用当前“真人owner位置权威、AI房主权威、本地预测+校正”的架构，不为班车把所有真人运动迁到房主。

| 状态 | 权威与消费方式 |
| --- | --- |
| 班次/路线/阶段/替代排期 | 房主生成并同步，其他端按冻结计划预测，用阶段快照校正 |
| 圈占用与占用代次 | 房主唯一分配/释放，不能两端自行各抓一人 |
| 真人身体位置/速度/碰撞运动 | 真人owner继续模拟与上报；远端显示沿owner校正，不能再用圈位置覆盖远端根节点 |
| 真人抓握手与主动/受撞离车 | owner从真实起划/受击产生带动作号的单调释放请求，本地立即预测；房主核验当前占座身份后确认释放结果 |
| AI动作与离车 | 房主决定，其他端重放同一抓握状态与权威运动 |
| 显示骨骼、水花、绳摆动 | 从已确认/本地预测的紧凑状态派生，不上传逐骨骼数据 |

双手到单手到脱离在同一次占座内只能单向减少，不接受旧消息把手重新抓回。新上车必须取得更高占座代次。

### 9.2 早期消息草案（已由第14节的简化协议取代）

以下 `CLAIM`、`CLAIM_RESULT`、`RELEASE_HANDS` 等独立消息是规划时的备选方案，并非当前线上协议；当前上车由房主实际接近仲裁，离车复用原可靠划水输入。

- 稳定身份为 `raceId + hostEpoch + tripId + ringId + occupancyRevision`；人物用稳定参赛座位，不使用本地数组下标。
- 新增紧凑请求/结果类型：`CLAIM / CLAIM_RESULT / RELEASE_HANDS / DETACH / TRIP_STATE`；侧别用2位手掩码，原因用小枚举，位置/时间用量化整数。
- 真人CLAIM含请求序号、owner状态序号、班次/圈号、量化接近采样；房主结合已收到owner位置及班车历史校验。历史验证窗口初值0.4秒，不接受远距离伪接近或跨泳段请求。
- 房主同一步候选按第4节稳定规则分配，授予具体占座代次。客户端等待时只表现伸手，不在未获座位时给完整牵引收益；获批后还须有可达接近距离，超出手臂/接近上限则立即放弃，不瞬移补抓。
- 等待CLAIM回复超过0.4秒取消本地预留意图，发送取消/释放关联请求；迟到授予不得让已离开的真人重新上车。
- owner的左右起划与原输入顺序绑定，抓握释放不再生成第二次划水。离车请求含本次占座代次、单调动作/接触序号及原因；房主对合法owner的单调减少予以确认，不用房主远端预测姿态强行要求人继续抓着。
- 主动/碰撞离车本地立即可操作；待确认期间本地脱离记录阻止旧占座快照吸回。房主确认后开放空圈给其他人，其他客户端不因看到owner离车动画就擅自抢占。
- 最终事件通过现有可靠帧权威事件路径传输，广播降级沿项目既有补发与快照兜底；关键结果不只发一次broadcast。

### 9.3 快照与带宽规划

当前 `TB|` 实际只编码班次、阶段、年龄、方向、横向路线、四圈固定泳道身份与抓手掩码，并复用房主的整包序号；下列逐占座代次与额外 self 墓碑是早期冗余方案，尚未实施。旧快照拒绝、离圈冷却和主人即时松手由现有单调包序号与本地状态处理。

- 班车快照包括：班次与房主任期、计划版本/摘要、方向、路线中心与端点、阶段/年龄、速度段、停止接客标记、四圈占用及占用代次、每乘客左右手掩码与最后离车/动作序号。
- 玩家self状态追加紧凑班次/占座引用与手状态修订；离车墓碑保留到班次结束或有更新占座，不被普通P包或其他频道更早状态覆盖。
- 规划使用独立有界TB快照，5Hz，完整UTF-8含比赛前缀目标不超过768字节；原S包压力预算仍为1536字节。文本字段不得带姓名、长资源路径或逐点绳数据。
- 需要逐帧恢复的真人位置仍用原frame self/P，TB不再重复四人的全套位置；不把一份旧TB在每帧重新应用为新抓握。
- 关键结果与TB按班次/占座代次幂等；序号跨帧通道、广播与快照一起审计，旧任期/旧比赛/旧动作直接拒绝。

### 9.4 弱网、迁移、退出规划

当前已经实现0.7／1.2秒访客断流兜底、最近快照占座恢复与房主切换。以下额外 owner 租约与逐占座代次策略尚未实施，属于真机弱网验收后可进一步加固的方案。

- 0.7秒无有效班车状态时禁止新上车。已有owner按冻结路线短时继续预测，最长1.2秒；仍无新状态则本地正常松手，保留离车记录等待确认，不无限吊在车上。
- 房主对乘客owner断流保留短租约，1.5秒无有效owner状态则释放该座位；重新收到旧占座不能恢复，必须重新申请。短时丢包不重复重置租约计时。
- 房主迁移接续最新有效计划、阶段、占用代次和释放账本；不重新抽方向/横向，不重新开始3秒预告、不重置人物体力或速度。
- 新房主先接受更高owner释放序号再裁定后续CLAIM；不能从旧TB恢复已脱离的人。仅缺必要完整快照且超过恢复期限时，统一释放所有座位并终止班次，作为可记录的故障兜底。
- 人物离房立即释放其圈；首位完赛按第2节处理，最终成绩权威不变。重赛继续房间保活，不调用endGame。
- 非联机比赛不创建请求、序号队列和补发计时器。

### 9.5 协议与导演扩展

- 接入前正式候选为6种，历史LITTER=6仍保留，3位事件编码支持0～7。现已新增 `TURTLE_BUS=7`，不重用历史6、不重排旧ID；MAX_EVENT_COUNT仍为6。
- 同时更新显式候选清单、Record映射、事件掩码校验、三类保底、测试入口、模式说明、驻留与关闭逻辑。海龟归争夺/收益事件，但单独禁止排末位；不把它改成field导致三类统计混乱。
- 新增 `canPreviewCurrent` 或等价紧凑许可接口，以及该事件专属3秒预告/预计行程时长。导演只接收计划与许可，不查询角色节点。

### 14.5 池端入场与接客修正（2026-09-28）

用户明确选择出发／折返的短边池端。纵向出生点固定约7世界单位，四圈和最长身体留在池内；不再为追赶选手把起点推到泳段中部。共享种子短等待之后仍需等到可搭窗口，因此大家已经游离出发端时，会迎接下一池端的折返选手。

本体先上浮并渐进挤开附近水面选手；泳圈随后错峰浮起，前侧推人判定已删除。3秒预告后沿原宽容范围自动抓圈，原1.2秒防误松手保护及慢车速度保留。折返预测计入蹬墙倍率、水下滑行和最早出水时间；强爆发角色不能在水下错过圈却被计作有效上车机会。
