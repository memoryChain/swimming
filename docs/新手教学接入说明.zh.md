# 一次性新手教学

## 产品流程

新建账号的 `tutorialCompleted` 为 `false`。第一次进入大厅显示“欢迎来到划水高手”，原快速比赛按钮文案改为“开始教学”，沿用原节点、背景和唯一点击监听，按账号状态分支进入教学；完成后恢复快速比赛分支。半透明遮罩阻挡其他入口，仅放行原按钮的真实矩形，大厅不叠加新的教学按钮。大厅已挂载的角色和控件不重建。教程使用临时纯色面板与项目字体，后续可替换美术表现。

教学固定为 **200 米（50 米泳池四趟）**，泳程条从进场开始可见。顺序为基础操作 → 心率 → 海豚跳 → 体力，海豚跳为倒数第二课，体力为最后一课。

| 泳程 / 阶段 | 操作与通过条件 | 比赛状态 |
| --- | --- | --- |
| 0–50 米：起跳与基础 | 加载后直接站在出发台，一次说明后按住蓄力、松手起跳；浮出水面后按左一下、右一下交替完成三轮（六划），再交替成功六次，再交替短按踢水四次 | 无赛前镜头展示、倒计时或发令等待；讲解暂停；仅最初六划跟练长按时 25% 时间流速，进入完美区 12%；后续交替六划与踢水按正常速度 |
| 第一次折返 | 自由游到 50 米池壁，真实自动转身并浮出水面后进入心率课 | 不能只用距离越线代替真实折返，不打断转身及滑行 |
| 50–100 米：心率四档 | 固定真实心率 90 / 120 / 150 / 170，每档交替长按松手四次，允许失误计入体验 | 只在开头说明一次；随后自动换档，HUD 旁两行分别提示心率与进度、具体操作，不逐档暂停 |
| 心率回落 | 解除固定值，停止划水，亲手左右交替短按踢水四下；至少观察四秒且真实心率降至 ≤100，再交替划四次 | 教会“用踢水保持前进并降心率”，长按不产生划水，不补体力 |
| 100–150 米：海豚跳 | 游过第二次折返，回到水面后介绍海豚按钮；保留前面蓄气，每次合格交替划水额外补给 25%，满气可直接操作 | 亲手点击真实按钮，必须完成起跳、落水、浮回水面 |
| 海豚跳后衔接 | 左右交替成功划六次，再游过 150 米折返 | 落水后直接衔接，无二次说明弹窗，之后只剩体力一课 |
| 150–185 米：末段游进 | 使用已学操作继续游，体力随教学泳程预算逐步减少 | 不提前弹出体力课 |
| 185 米附近：真实耗尽 | 延续上一划的左右节奏，左右各划一下，先感受动作与推进变弱；失误也计体验 | 正常时间流速与真实位移，不锁在 185 或 190 米；若仍未耗尽，整场暂停等待一次真实长按划水 |
| 体验后的说明 | 通常等两划动作完整结束、回到水面后，仅在闪电旁暂停说明一次；若已到 195 米则直接整场暂停说明 | 位移、动作、计时及划水输入一起冻结，解释刚才变慢的原因，说明踢水可以前进但不会恢复体力 |
| 最后几米 | 保持真实耗尽状态，自由划水、踢水或海豚跳到 200 米池壁 | 不补满，不再强制练习；必须亲手游到，触壁反馈后才可确认保存 |

基础操作、心率和海豚衔接的练习次数保持不变；末段体力体验只需左右各一次，不再做耗尽/补满两组四划。错误侧、重复同侧、短按不会跳过相应课程。普通划水练习需要 GOOD / PERFECT，心率和体力体验允许 BAD；整课完成后保留 0.8 秒反馈；最初跟练的中间划只留 0.25 秒，保持左右交接。第一下的右侧说明只出现一次。

前半程各课程保留后续泳程：基础练习最多到 45 米、心率练习到 95 米、海豚与衔接练习到 145 米。完成这些课程后释放边界，不重置位置或假装增加总赛程。体力阶段不使用位移边界，整个末段开放到真实 200 米终点；需要引导或说明时使用整场暂停，不能继续播放划水却把位置锁住。

教学专用体力预算以 `185` 米为耗尽点，**在真实划水结算或成功海豚跳扣费时**将比例推进到 `max(0, 1 - 实际距离 / 185)`。它为早期反复失误预留体力，又让末段的真实划水耗尽；养成数值不改变课程触发。踢水、滑行、停手和弹窗不会自行扣费，避免误教“踢水也消耗体力”。若玩家只用踢水到 185 米，等现有动作结束后真正暂停整场，提示试一次划水，观察闪电变化。暂停中只运行长按分类，短按不产生踢水动作、推进或扣费；真实手臂划水开始后恢复正常时间与位移，不清掉本次长按。该次动作结束并回到水面后进入两划体验，通常等体验动作收手后说明原因。若一直踢水或未完成交替体验而游到 195 米，直接暂停说明，保留最后五米供玩家亲手游完。此后直到触壁都不补充体力、不改写心率；预算仅在离场时解除。

沿用全屏左右半屏输入，不把手掌图标大小当作触控范围。桌面 A / D 对应左右，起跳也可按住 A 或 D 再松开；空格在教学中被屏蔽，海豚跳必须点击 HUD 按钮。无需排名或 PERFECT，但必须亲自抵达教学终点。

教学复用现有泳池，采用单人标准规则。`TUTORIAL_AI.opponentCount = 0`，阵容创建返回空数组，居中泳道允许一名参赛者，不加载占位 AI，也不显示排名栏。普通生涯赛事的 AI 配置校验保持原样。教学期间关闭转向并使用基础角色能力，保留外观和养成属性，避免无限体力或无法海豚跳的角色跳过/卡住课程；不写回角色存档。

`getRaceDistance()` 在教学期间固定返回 200；Motor 的教学进度边界不会触发正式完赛或停止动作。`RaceManager.tutorialMode` 禁止正式比赛结算和落后者倒计时，不颁发生涯成绩、金币或比赛凭据。离场清除临时进度边界、体力预算、心率覆盖与时间流速。

## 完成与中断

本地反复测试：大厅“快速比赛”下方提供“重置新手教学（临时）”按钮。点击后立即恢复欢迎遮罩和“开始教学”，无需控制台或刷新页面；仅重置教学完成标记，保留金币、角色和生涯。按钮仅在非微信的本地模拟后端显示，云端拒绝该重置操作。教学尚未完成时直接使用已有“开始教学”即可。

- 完成状态在 `PlayerProfile.tutorialCompleted` 中按账号保存；微信通过现有可信 OPENID 身份、事务、版本校验和请求去重持久化，换设备读取同一状态。本地预览沿用本地模拟存档，不模拟多个微信账号。
- 新账号显式保存 `false`；旧档没有字段时定向迁移为 `true`，免除老玩家教学。保留当前 schema 7，这是兼容的附加字段，不迁移金币、等级、外观、赛事凭据。
- `tutorialComplete` 只能接受空参数并写入 `true`，不提供重置接口。重试不会发放奖励。写入失败保持完成界面，提供重试按钮；仅云端确认成功后恢复大厅正常入口。
- 关闭应用或加载失败不会写入完成标记；下次进入大厅仍出现教学，从第一课开始。教学不提供主动跳过或中途返回入口，完成后返回大厅。
- 新账号从邀请链接进入时先完成教学，本轮邀请不自动加入房间；完成后可再次打开邀请。已经在进行的联机会话重连保留原流程。教程不会在真实联网比赛中激活，不新增联机协议。
- 返回大厅失败时提供重试返回，已成功保存的教学状态不回滚。

## 实现与生命周期

- `assets/scripts/tutorial/TutorialLesson.ts`：独立课程状态机，接收真实划水结算和短按确认；不伪造通过判定；体力/心率演示由控制器按课程显式设置真实模型。
- `TutorialContent.ts`：集中维护玩家文案与五个章节名称，不在控制器里混杂策划内容。
- `TutorialRaceController.ts`：课程、真实状态对照、子弹时间、池壁终点与保存流程。体力与心率在暂停前同步刷新 HUD，避免面板显示新档位而 HUD 仍停在旧值。
- `TutorialOverlay.ts`：稳定节点树；步骤变化或窗口变化时才写文案/绘制遮罩。HUD 目标跨 Canvas 经过来源相机与弹窗相机转换。
- `TutorialSession.ts`：一次性场景请求与教学运行标志。真实房间/联机会话优先，不继承教学状态。
- `GameManager` 只负责编排接入。暂停时冻结玩家、AI、RaceManager、骨骼表现、比赛摄像机和条件消耗；调度器同时冻结起跳延迟与 Tween，按钮仍可响应。离开场景释放暂停、监听和界面。
- 手机和键盘在相同输入分类入口门控。步骤切换清空触摸、鼠标和键盘持有状态，同时丢弃未完成的动作队列，避免上一课按住状态或心率快照泄漏到下一课。

## 发布与验证

微信首次发布账号教学完成状态时，需要先用 `pnpm cloud:build` 生成并部署更新后的 `swimming-player` 云函数，再发布客户端。旧云函数不认识 `tutorialComplete`，客户端会停留在保存重试界面。大厅按钮、遮罩和进入教学均为客户端逻辑，本次大厅修复无需再次更新云函数，需要重新构建并上传客户端代码。无需新增集合或数据库权限。云函数部署属于发布步骤，本次代码实现不代表线上已部署。

自动回归：`tests/tutorial-runtime.test.cjs` 覆盖真实划水减速/松手、体力耗尽倍率、四档心率判定窗口、自然恢复、蓄气起跳落水、真实移动到终点、空 AI 阵容和单人倒计时/触壁；`tests/tutorial-scene-entry.test.cjs` 覆盖跨场景界面生命周期；`tests/tutorial-dive-start.test.cjs` 执行真实赛事控制器与鼠标、触屏、键盘起跳输入，核验直接进场、松手立即提交、等待不超时及普通比赛规则隔离。另运行相关开场、加载和 HUD 回归。运行固定 TypeScript 5.4.5 类型检查；静态中文变动后运行 `pnpm fonts:build` 与 `pnpm fonts:check`。

尚需在现有 Creator 会话和 iOS/Android 微信真机人工验收：宽屏/安全区遮罩，手机多指与取消触摸，实际高亮位置，起跳后暂停/恢复，重复出入节点与监听数量，存档超时重试、完成后重启/换设备不再触发。未自动启动或截图 Creator，不将单元测试视为引擎或真机视觉验收。

## 进场卡住修复记录

大厅暂存会把隐藏的弹窗 Canvas 一并带入比赛场景。原 `UILayers` 按同名节点查找画布，导致教学挂进隐藏的大厅画布，比赛已暂停而继续按钮不可见。现按所属 Canvas 缓存独立弹窗画布，比赛弹窗相机排在比赛 HUD 相机之后；所属 Canvas 销毁时同步释放弹窗，返回大厅仍复用原大厅画布。教学面板成功挂载后才施加暂停，挂载失败释放面板并由加载错误页提供退出入口。

`tests/tutorial-scene-entry.test.cjs` 使用真实分层、暂存、教学界面与控制器代码复现原故障，覆盖连续三轮进出、暂停后点击继续、相机层级、返回大厅、销毁与挂载失败不锁死调度器；渲染组件使用替身，不作为真机视觉验收。

## 教学节奏与玩家文案

基础操作完成后游过第一次折返再学习心率；完成心率对照后，游过第二次折返学习海豚跳。体力教学只在末段真实耗尽后触发，等待当前动作结束。所有距离触发的课程都等待转身结束、回到水面。

提示每屏只讲当前要做的事，使用“继续按住”“现在松手”“到池边会自动转身”等短句；不显示时间倍率、教学固定值、补给比例或账号持久化说明。四档心率体验保留；体力阶段先体验，再解释“划水变慢，是因为体力用光了”，不通过凭空补满来做对照。


## 2026-09-30：按学习目标整理后的设计

### 目标与节奏

目标是让第一次玩的玩家独立游完，并知道下一场怎么操作、怎么调整节奏。计数是确认亲手尝试的门槛；教学不以完美率、速度或名次考核。固定 200 米提供应用空间，不强制每一屏按时间结束。易失误玩家可留在当前项重试，已掌握玩家完成目标就继续。

课程仍按五个章节安排：起跳入水 → 左右划水与踢水 → 掌握心率 → 学会海豚跳 → 分配体力，游到终点。基础操作阶段保留章节与跟练卡；从心率课开始不再常驻章节标题或中央口令，操作时只在对应 HUD 旁显示小提示：单行 54 像素、两行 78 像素。首次介绍心率、海豚跳和体力耗尽时使用 HUD 旁的 190 像素小卡暂停说明；自由游、跳跃和最后冲线不显示教学文字。

| 章节 | 希望玩家形成的理解 | 体验安排与再次运用 | 验收行为 |
| --- | --- | --- | --- |
| 起跳 | 按住是在蓄力，松开才起跳 | 同时看屏幕操作和真实蓄力条；入水后自然滑行 | 亲手长按、松手、入水 |
| 划水与踢水 | 长按松手划水，轻点踢水；左、右由自己选择 | 跟练左、右三轮，再独立交替六下；只在最初六划跟练时放慢，之后六划自主巩固恢复正常速度；踢水用短按对照 | 能换侧并在判定区松手，能区分四次短按与长按 |
| 心率 | 心率越高，松手窗口越窄；应变方式是换踢水缓下来 | 四种颜色分别亲手划四下；红色后实际踢水降心率，再划四下看窗口重新变宽 | 四档均体验、成功交替短按、自然降到轻松档后继续划水 |
| 海豚跳 | 划水攒气，满气点击按钮，跳后可重新攒气 | 在第二次折返后、浮回水面时介绍；保留已攒蓄气，真实跳跃后接六划，让圆环重新增长 | 亲手点按钮并完整起落，落水后能够继续游 |
| 体力 | 体力耗尽会削弱划水动作与推进；踢水可以继续前进但不能恢复体力 | 185 米附近真实划水耗尽，延续左右节奏体验两划，收手后解释原因；保持耗尽状态自由选操作抵达终点 | 感受真实耗尽倍率，知道没有体力也能游完，实际触壁完成 |

### 反馈规则

- 最初跟练只开放当前侧，之后的计数练习提示应换的侧；按错不推进，立即指出左或右。不会替玩家自动产生划水。
- 最初跟练的真实判定为松早，提示“等白点进入亮色区域”；松晚或按住超时，提示“一进亮色区域就松手”。后续只消费现有 HUD 判定反馈与小提示中的应操作侧，不重复逐划口令；心率体验中失误仍算一次尝试。
- 教踢水和降心率时，长按不能晋升为手臂划水，既不涨心率也不误计短按次数。其他教学中的短按不计划水目标。
- 子弹时间只用于最初左、右交替六划的跟练，两档沿用 25% / 12%。自主交替练习、心率四档与恢复对照、海豚蓄气与衔接、体力耗尽、自由游和终点段全部保持 100% 时间流速。操作提示与反馈独立于减速，释放、取消输入、切课、销毁时恢复；讲解弹窗仍可暂停。
- 起跳高亮蓄力条；左右跟练高亮对应判定弧线；心率、蓄气、体力分别高亮真实 HUD。讲解结束后的体验也保留目标指示，不只在读文字时指一下。
- 计数和反馈改变只更新文案；同一布局与目标不重复清空 Graphics。遮罩、目标框及卡片只在模式、目标或窗口变化时重绘；节点、组件、监听保持稳定。

### 验证边界

自动回归覆盖完整 200 米、三次折返、真实左右划水与子弹时间、松早/松晚反馈、真实 InputRouter 的短按/长按分类、踢水降心率、末段耗尽体验与保持耗尽游完、重复进出与 UI 节点稳定性、普通比赛及远端耗尽不受影响。类型检查与字体字形检查另行运行。

实机验收需关注：提示卡是否避开角色与判定弧线，章节/目标是否一眼可读，慢动作后恢复是否自然，首次玩家是否无需额外解释就能换边与松手，能否主动用踢水处理高心率。通过单元测试不代表这些感受已在 Creator 或微信真机验证。


## 2026-10-01：子弹时间限于示范跟练

最初六划用于看懂长按与松手，所以保留慢动作。进入“把左右连成节奏”后，所有体验都按正常比赛速度进行，包括按住期间和完美区。心率窗口缩窄、耗尽后动作与推进变弱由真实模型产生，不再叠加子弹时间。讲解弹窗暂停独立保留。回归覆盖跟练到自主练习的恢复边界，并检查全部划水体验和自由游阶段的长按、完美区、松手时间倍率均为 1。

## 2026-10-01：后半程连续体验与提示精简
