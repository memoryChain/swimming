# 微信启动加载画面

引擎初始化之前的 `first-screen.js` 使用既有登录背景和 Logo，底部显示黄绿色细进度条。
素材来自 `assets/startup/StartupResources.ts`；构建脚本通过 `.meta` 的 UUID 定位主包
已经导出的原生图片，兼容 MD5 文件名，不复制图片、不新增运行时素材或字体。
定位范围为 `assets/resources/native` 和 `assets/start-scene/native`：开启首场景分包后，
显式预加载的背景和 Logo 会由 Cocos 移到后者。构建钩子执行时业务分包可能尚未搬移，
因此不递归查找其他 bundle；缺失或重复候选会输出素材 UUID 和查找目录。

构图沿用现有 `StartupView` 的 1280×720 坐标：背景 cover，Logo 尺寸 608×262、
位置 (28,157)，保持到登录页的视觉衔接。进度条宽 352、高 8、位置 (0,-264)，
统一等比缩放。背景与 Logo 不参与假进度或额外动画；进度沿用 Cocos 的加载阶段值。

实现位置为 `extensions/wechat-race-subpackage/wechat-first-screen.js`，只在构建时
替换首屏配置值及两处静态布局函数，保留 Cocos 原有 `start/end/setProgress`、
WebGL 初始化、加载和资源释放流程。布局模板位于同目录 `templates/first-screen-branding.js`。
没有运行时模板注入，也没有额外超时控制器。背景、Logo、进度条各一个四边形，
结束后释放，比赛期间不再执行；不涉及联机状态或比赛结果。

构建钩子自动应用；Creator 插件缓存时，执行 `pnpm wechat:finalize` 可独立更新并备份。
上传前运行 `pnpm wechat:check -- --build` 校验实际产物。首屏脚本与默认版本大小基本一致，
实际字节数随导出路径变化，最初方案中额外约 4 KiB 的运行时接管代码已移除。

验证：`npm run test:wechat`；独立 WebGL 预览脚本
`scripts/preview-wechat-first-screen.cjs` 使用 Playwright，可通过 `CHROME_EXECUTABLE`
指定已安装的浏览器。它只执行导出的首屏脚本，不启动 Creator 或游戏引擎。
输出为 `art/startup-loading-preview/`，覆盖 1290×720 和 1920×900、DPR 2.2，
检查 GL 错误和退出释放。此预览不代替 iOS/Android 真机启动衔接验收。

## 登录场景交接

登录场景的 `StartupManager` 显式引用现有背景和 Logo 纹理，作为场景依赖提前加载。
`StartupView.build()` 在首次异步等待之前同步创建背景与 Logo；按钮图片和首屏字体
完成后只补充按钮，不重建背景。这样相机开始渲染时已经有完整美术，不会在等待字库
期间先清屏成深色。未配置场景依赖时保留原异步加载回退。

此修复涉及 `Login.scene` 和启动 TypeScript，必须由 Creator 重新构建；仅运行
`wechat:finalize` 不能把场景和业务源码编译进旧包。回归覆盖延迟字体、延迟按钮、
资源复用及销毁后的迟到回调。真机仍需核对加载页到登录页的实际连续画面。
