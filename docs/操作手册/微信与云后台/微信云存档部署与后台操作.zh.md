拿到环境 ID 后，在仓库根目录执行：

```sh

```

第一条更新 `assets/scripts/backend/WechatCloudConfig.ts` 并生成本机 `project.config.json`；第二条生成 `cloud/functions/swimming-player` 和 `cloud/functions/swimming-admin` 两个可上传目录。生成包与本机配置已忽略，不提交。

## 2. 建集合和设置权限

在该环境的数据库中创建：

| 集合 | 用途 |
|---|---|
| `players` | 每账号唯一档案，含金币、角色、生涯、版本及待结算赛事元数据 |
| `operations` | 玩家写操作的幂等回执 |
| `adminAudit` | 管理员操作原因、操作者、前后档案与版本 |
| `counters` | 服务端发号计数器，只有一条 `playerUid` 记录 |
| `gameConfig` | 全局功能配置，`global` 文档中的 `tutorialEnabled` 控制新手教学 |

这些集合都使用 `cloud/database.rules.json` 中的安全规则，拒绝客户端直接读写：

```json
{"read": false, "write": false}
```

云函数和云控制台仍有管理权限；玩家身份由云函数中的 `getWXContext()` 验证，客户端不能指定别人账号。不要把集合改成所有人可写。

玩家读写主查询使用确定性文档 ID。按公开短 ID 查人使用顶层数值字段 `uid`；数据量增长时可为 `uid` 建索引。不要给 `operations` 或 `adminAudit` 自动设置 TTL，也不要为省空间直接清空；回执和审计的归档需另行制定策略。应配置备份、费用和到期提醒。


### 公开玩家编号初始化

部署支持短 ID 的云函数前，在 `counters` 创建文档：文档 ID 为 `playerUid`，数值字段 `lastUid` 为 `9999`。仅首次初始化一次，绝不能在已有编号后重置、调小或删除；编号不回收。计数器缺失或值非法时，新玩家及未补号旧玩家会收到 `UID_UNAVAILABLE`，不会自动从头发号。

新账号建档、旧账号补号均在同一数据库事务内更新计数器与 `players.uid`，首号为 10000。同账号重复请求、事务冲突重试不会重新领号；事务整体失败不消耗编号。旧档补号不改 profile、revision、updatedAt 或未结算比赛。编号独立于 profile，管理回档不能把它还原掉。普通客户端不能直接修改 uid 或 counters。

公开短 ID 仅在当前环境内唯一；测试/正式环境、未来各平台独立环境不能视为同一编号空间。删除玩家档后重新建档会获得新号，因此不要通过删档实现重置养成。恢复数据库备份时应保持计数器与玩家数据一致，避免回退计数器造成重号。

## 3. 上传两套云函数

在微信开发者工具导入**仓库根目录**生成的项目配置；其中小游戏目录指向 `build/wechatgame/`，云函数目录指向 `cloud/functions/`。小游戏构建输出须已存在。该配置不会将仓库的源模型、云函数或测试文件打入小游戏包。

选择刚创建的环境，对两个函数目录执行「上传并部署：云端安装依赖」。函数入口 `index.js`，固定依赖 `wx-server-sdk@3.0.1`，新建时优先选可用的 Node.js 20 或更新运行时，建议超时 10 秒。本次开发者工具目录上传自动创建为 Node.js 16.13（256 MB），已通过实际调用验证；该配置弹窗不提供运行时切换，上线前应安排升级至受支持的运行时。不要只上传入口文件，规则目录和 `service.cjs` 也必须一起上传。

两个云函数都需要环境变量：

| 变量 | 值 |
|---|---|
| `WECHAT_APP_ID` | `config/build/wechatgame.json` 中实际小游戏 AppID，必须准确匹配调用上下文 |

`swimming-admin` 另外需要：

| 变量 | 值 |
|---|---|
| `ADMIN_PLAYER_IDS` | 有管理权限的内部玩家 ID，多个用逗号分隔；默认留空即禁止所有管理调用 |

管理员玩家 ID 不是昵称或微信号。先让拟授权账号调用 `swimming-player` 建档，再由账号负责人检查身份并把返回的 `playerId` 加入云函数环境变量。**不要把待修改玩家的 ID 误设为管理员**。

小游戏控制台可以用以下只读/首次建档请求获取当前登录账号 ID：

```javascript
wx.cloud.callFunction({
  name: 'swimming-player',
  data: { protocol: 1, rulesVersion: 3, action: 'load', data: {}, writerId: 'admin-console' }
}).then(res => console.log(res.result));
```

以上示例适用于生涯调整后的经济规则3；此前函数分别使用规则1或2，客户端、管理脚本与两个云函数需要同步更新。调用必须来自已初始化当前环境、已登录的小游戏上下文。云函数控制台的无用户测试调用缺少可信 OPENID 时会被拒绝，不能通过在参数里伪造 OPENID 绕过。

管理函数仍要求可信 `APPID/OPENID` 和独立管理员名单。客户端包不包含名单、管理员令牌或云密钥；任何普通玩家直接调用管理员函数都会被拒绝。

## 4. 管理员如何查人、补金币和改等级

按负责人最新确认，日常查看和直接编辑数据使用腾讯云官方控制台「文档型数据库 → 集合管理 → players」，无需自建网页、发布微搭应用或配置域名。可视化编辑步骤与实际核查结果见[腾讯云管理后台接入说明](腾讯云管理后台接入说明.zh.md)。管理云函数和下述请求生成脚本继续保留，供需要业务版本检查、补偿和审计的操作使用。

可在 `players` 查询昵称辅助定位，最终以 `playerId` 确认目标；昵称不唯一。控制台可直接编辑字段，但不会自动递增业务版本或生成管理审计；需要这些保障的经济修改通过下述管理函数完成。

先创建本机文件（建议放在被忽略的 `cloud/admin-local/`）：

```json
{
  "action": "inspect",
  "data": { "playerId": "目标玩家的64位playerId" }
}
```

执行：

```sh
pnpm cloud:admin cloud/admin-local/inspect-player.json
```

脚本生成 `.request.json` 及一段可审阅的 `wx.cloud.callFunction` 调用，不自动执行。用已授权管理员账号的微信开发者工具**小游戏控制台**执行，查看返回的 `revision` 和档案。

补偿 500 金币的输入示例（将版本号替换成刚读取的实际值）：

```json
{
  "action": "coins",
  "expectedRevision": 12,
  "data": {
    "playerId": "目标玩家的64位playerId",
    "delta": 500,
    "reason": "工单123：补偿未到账奖励"
  }
}
```

支持的管理操作：

| action | data 中额外参数 | 说明 |
|---|---|---|
| `inspect` | 无 | 读取玩家资料和版本 |
| `coins` | `delta` | 金币增减，单次绝对值不超过 100 万，余额不低于 0 |
| `level` | `characterId`、`level` | 修改指定已存在角色的等级，范围 1～30 |
| `clearPending` | 无 | 清理卡住的未结算赛事，保留杯赛进度供重新参赛 |
| `restore` | `auditId` | 恢复指定管理审计的修改前档案 |

所有写操作还须 `expectedRevision`、`playerId`、`reason`。遇到 `CONFLICT` 必须重新查档并审阅后生成新操作，不能盲目替换版本重试。

**管理写操作会取消当前未结算赛事，防止经济修复或回档后用旧赛果领奖。请先让玩家回到大厅再处理，并告知正在进行的比赛需要重开。** 赛中不会修改已生成泳者的属性；下次回大厅/重新进房使用更新档案。

一次操作固定一个 `requestId`；响应丢失时用保存的 `.request.json` 原样重试。不要重生成 ID 重复补偿。脚本发现同名请求文件已存在会拒绝覆盖。

成功返回 `auditId`；`adminAudit` 保存前后完整档案、操作者、原因和版本。`restore` 只能恢复该玩家已有管理审计的修改前档案，属于**撤销管理修改**，不是任意时间点回档。任意历史时点恢复需要另行启用数据库备份并设计恢复流程。恢复也会递增版本并取消旧赛事；已经执行的操作回执不会被删除。

## 5. 客户端和云端约定

- 本次源码协议/规则版本为 `1/2`（2026-09-27 已部署），来自 `assets/scripts/backend/CloudProtocol.ts`；角色、经济与赛事规则由同一 TypeScript 源文件生成云函数代码。修改规则时递增规则版本并同步部署客户端和两个函数。
- `cloud:build` 拒绝 `cc` 等客户端运行时依赖，并生成 SHA-256 规则清单；部署必须使用重新生成的目录，不能保留旧函数只换客户端。
- 云端只接受载入、昵称头像、角色选择、单角色外观、金币升级、生涯开始/放弃/结算。拒绝客户端整档覆盖、调试加币和未经验证的广告发币。
- 当前产品昵称是随机动物昵称，云端仅允许现有生成语法；若未来开放自由输入，必须另接内容审核。
- 每次经济写入在一个事务内完成，并保存请求回执。两设备旧版本冲突返回新档案，不覆盖新值。结算若只遇到其他字段版本变化且原赛事仍有效，会重读版本后重试同一赛事。
- 客户端先把请求写入账号隔离的本地待发送记录，再调用云函数。超时/响应丢失保留同一 ID，重新进入时恢复；缓存不被用来假装云端载入成功。
- 玩家云档案键按 AppID 与可信 OPENID 的 SHA-256 分配。客户端备份/待发送记录还按环境分开，换账号不能重放另一账号请求。
- 本次档案 schema=7，支持 schema 6 定向迁移；其他未知云端 schema 明确拒绝，不静默生成新档覆盖。未来 schema 变更必须补迁移。
- 云端为单人生涯生成种子和不可复用赛事凭据。当前每账号一个有效未结算赛事；任意设备重新开赛可替换它，中途退出无需结算才能继续玩。已替换或过期的凭据不能领奖。
- 结算校验参赛人数、数值范围、组合计数及保守耗时范围；这不是完整反作弊，客户端伪造比赛表现仍需进一步加固。
- 联机/调试比赛保持原有“不发单人生涯奖励”规则。云档案只在登录、大厅回前台、进房和业务操作时请求，不进入比赛 update，也不改变房间保活重赛流程。
- 广告功能尚未正式开放，云端不会仅凭客户端“看完”回调发币；测试加币使用管理员命令。
- 本阶段没有离线经济合并和跨平台账号互通；微信云环境不可用时，微信正式养成操作停止，浏览器/编辑器本地调试不受影响。
