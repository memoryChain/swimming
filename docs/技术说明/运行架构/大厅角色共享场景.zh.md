# 大厅、角色与联机页共享背景（2026-09-22）

按用户确认，将两页视作同一个角色展示场景。背景只绘制一个空展台，角色保持实时3D；切换页时只移动取景和背景，控件交叉淡出淡入。之前两张不同展台位置的图片及两段离场/入场不再用于这条往返路径。

## 资源与导出

- 当前统一背景：`assets/race/ui/lobby-b/background.png`，2115×743、RGB、不透明，保留UUID `f7acb818-ef85-4e5a-ae74-c6f21243848b`。使用原ASTC 6×6与JPG回退预设，边缘采样改为clamp-to-edge。大厅、选角和联机页均通过`RESOURCE_PATHS.lobbyB.background`加载它；原图宽高常量同样集中在`ResourcePaths.ts`。
- 生成方式：内置image_gen编辑，参考源稿保留在`art/shared-lobby-scene/character-reference.jpg`。旧运行时`character-v1/background.jpg`及其.meta、资源声明已删除，移除约137KiB的源图片；已确认没有残留路径或UUID引用。
- 联机页固定使用大厅的全景位置和缩放（共享布局的detail=0），进入联机时不改变取景、不播放背景移动；窗口尺寸变化时按同一大厅布局重新适配，销毁时解绑监听。房间状态和网络协议不变。
- 本地美术源文件：`art/shared-lobby-scene/panorama-source.png`；原大厅背景备份为`lobby-before.png`，参考备份为`character-reference.jpg`。这些源稿沿项目约定不进入运行时目录。
- 可复现导出：`node scripts/export-prepare-panorama.cjs`，也可传入源PNG路径。脚本检查尺寸、格式及已有.meta，再原样复制；不重编码图片。旧`export-lobby-b-runtime.jsx`跳过背景，避免旧PSD覆盖全景。
- 导入后运行`npm run textures:fix`和`npm run textures:check`。全景PNG约1.30MiB；真实微信上传包按构建后的ASTC与回退计算，不以源文件大小代替包体测量。

## 站位与过渡

- 布局入口：`PrepareSceneLayout.computePrepareSceneLayout`，供大厅、角色页及联机页共用。原图台面横向中心x=1049，脚底参考线按原720高画布y=600映射，避免宽屏缩放移动脚底接触线。
- 大厅取景中心x为`-174 × max(可见宽/1280, 可见高/720)`，角色页为-15个设计单位。取两端点所需覆盖范围计算唯一等比缩放，移动过程中缩放保持不变；背景全程覆盖屏幕。
- 共用420ms、cubicInOut进度驱动全景位置、`PrepareRaceCharacterPreview.setScreenOffset`及两页UI透明度。相机维持完整非负视口，模型身份不变时不重建骨架、不重启展示动作或重置用户旋转。
- 左右控件仍由原Widget锚点适配；页面透明度由稳定父节点控制。平移期间单个透明输入阻挡层防止连点与误拖角色，结束后关闭；没有常驻update、逐帧文字刷新、Graphics重绘、贴图处理或网络数据变化。
- 缓存两页节点和单张背景。离开大厅进入比赛/房间或销毁时停止时间线、释放阻挡节点与页面资源。赛事页/快速弹窗更换角色返回继续保留原导航和选择。

## 完整生成提示词

编辑所附的游戏背景图片，制作一张统一用于大厅和角色选择界面的超宽横向全景背景，目标尺寸2048×720、宽高比128:45。以参考图原有1280×720画面为中央区域，向左右各扩展384像素的自然连续场景，不要缩小或挤压中央内容。保持同一画风、色调、柔和虚化、明亮青蓝天空、海滨泳池、薄荷绿瓷砖地面、白墙蓝顶小屋和原有单个圆形展台。中央展台是最重要的固定物：横向圆心在整图中心附近（约1024），保持原有白色外沿、青色内圈、淡金色中心、约700像素宽的椭圆透视和原参考相同的大小；展台中心约在画面y=574，前沿底部约y=687，后沿约y=490，地平线约y=412。只扩展左右背景，中央展台和垂直构图应尽可能保持。左右扩展区继续铺展池畔地砖和远处小屋，边缘自然开放，便于在一张图上平移摄影机。画面只能有一个空展台，不能加人物、角色、文字、UI、按钮、边框、水印，不能复制第二个台子。输出完整无透明的横向全景图。
