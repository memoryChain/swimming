# 大厅返回与加载流程审计

2026-09-28：按负责人要求，清理返回大厅和相邻导航中的重复读档、重建及启动式加载。此次只修改客户端导航与页面生命周期，不修改比赛人数、奖励、结算或云端规则。

## 已调整

| 入口 | 原流程 | 当前源码行为 |
| --- | --- | --- |
| 比赛返回大厅 | 销毁大厅，再读云档，重建 UI 和预览，显示启动进度 | 进场前暂存同一份大厅 Canvas、弹窗 Canvas、角色预览；比赛期间停用，返回时恢复并显示当前档案，无启动遮罩与强制读档 |
| 大厅进入房间再返回 | 销毁大厅并重建 | 暂停/恢复大厅，保留已访问页面和角色，恢复到大厅而非残留角色页 |
| 场景或分包加载失败 | 销毁仍可用的大厅再重建 | 恢复原页面与按钮，可重试加载 |
| 首次邀请直达房间 | 先创建隐藏大厅及其角色，再进入房间 | 只准备真实存档、共用分包、字体和头像栏，直接进房；首次退出房间才按需创建大厅 |
| 初次进大厅、进房、房间重连 | 即使已有档案仍强制云读取 | 复用已确认档案；进房先等待在途换色及存档写入，缺档或上次失败仍走正常恢复 |
| 页面加载时收到邀请 | 原页面的等待与遮罩可能留到回调完成 | 暂停时取消页面等待并释放遮罩；不完整页面下次按需加载 |

## 生命周期约束

- `app/LobbySceneSession.ts` 只保存一组大厅根节点，返回时解除常驻。使用 Creator 3.8.8 官方常驻节点机制：返回原 Login 场景时，引擎用同 UUID 的旧 Canvas 替代新 Canvas，避免再次执行 StartupManager/LoginManager 初始化。比赛场景本身仍正常销毁。
- 大厅和预览在比赛期间 `active=false`，页面 Tween 暂停，旋转触摸清空；回前台监听在进场前注销、返回时只注册一次。隐藏页面跳过档案刷新、布局和错误弹框。没有增加比赛每帧查询。
- 返回只恢复被导航禁用的控件，不强行启用业务禁用按钮。快速比赛回大厅，生涯赛保留原赛程/晋级回顾；保留中的赛事面板清除上一场开赛忙碌状态。
- 暂停前发出的开赛请求即使迟到成功，也不能在用户已经切页后自动启动比赛；导航代次检查只取消页面动作，不篡改已提交的存档。
- 联机进场时释放旧房间 UI 和定时器，沿用 `_raceEntered` 的会话保活行为；回房仍走 reconnect，不新增 `create/join/start/endGame`。进房先等已发起的保存完成，再发布角色快照。

## 核查后保留的必要流程

- 首次登录的真实身份/存档读取及失败重试。
- 首次进泳馆的分包解析、场景创建和实际资源就绪等待；资源缺失不放行。
- UI 首次使用时的按需加载和透明中央转圈。
- 大厅从后台回到前台时的后台档案刷新，用于接收其他设备或管理端变更；它不重建页面、不显示全屏进度。比赛期间此监听已注销。
- 云端结果不确定时的原请求恢复，以及联机角色快照与准备握手。
