# 跨平台埋点接口

当前接口在 2026-10-03 从 butterfly 分支功能迁移到 main。比赛和大厅共用事件，平台实现承担 SDK 适配。当前仅抖音上报已接线；微信、网页及编辑器显式关闭。

## 职责与调用

| 模块 | 职责 |
| --- | --- |
| `platform/IPlatformAnalytics.ts` | 统一契约：`platform`、`enabled`、`getLaunchContext()`、`report(event, fields)` |
| `platform/PlatformAnalytics.ts` | `gameAnalytics()` 单例；按构建平台选择具体实现 |
| `platform/GameAnalytics.ts` | 大厅事件一次性去重、共用字段、异常隔离、按能力创建比赛记录器 |
| `platform/RaceAnalyticsTracker.ts` | 锁定每局上下文，开赛和终态各一次，重置与原地重赛 |
| `platform/AnalyticsConfig.ts` | 各平台共用的构建版本、字段版本和测试标记 |
| `platform/DouyinAnalytics.ts` | 统一接口的抖音实现，调用抖音服务 |
| `platform/DouyinEngagement.ts`／`PlatformEngagement.ts` | 仅抖音的来源、侧边栏能力／导航及宿主上报，复用早期启动桥接 |
| `platform/DisabledAnalytics.ts` | 尚未接入时关闭；不缓存、不上报、不启动任务 |
| `config/analytics-events.json` | 共用事件字典和字段类型，不是任何平台的官方导入文件 |

源码以上均位于 `assets/scripts/` 下。业务调用 `gameAnalytics().reportLobbyReady()` 与 `gameAnalytics().createRaceTracker()`，不判断 `BYTEDANCE`／`WECHAT`，不直接访问 `tt`／`wx`。比赛流程通过注入的可选记录器消费事件，对平台 SDK 没有依赖。

大厅只在现有资源屏障完成且可操作后报告；比赛在发令状态锁定模式、赛程、角色和本地／联机类型。教学不产生普通比赛事件。联机终态采用主干权威成绩解析后的名次与时间，埋点不得改变任何输入、模拟、票据或结算。

所有公共事件的 `build_version`、`schema_version`、`is_test` 由公共层附加，平台实现接收完整字段。`time_ms`、`placement`、`progress_percent` 使用整数。按字典维护字段，不采集身份凭证或任意启动 query。

## 后续接入平台

1. 增加实现 `IPlatformAnalytics` 的平台适配类；SDK 初始化、权限／可用性及事件映射只放在这个实现内。
2. 未配置或不可用时令 `enabled=false`；不要先缓存比赛事件，避免无界积压和额外后台任务。公共层不创建记录器，也不查询来源。
3. `getLaunchContext()` 返回该平台已捕获的启动时间与来源；来源分类由平台实现决定，耗时与一次性去重由公共层计算。
4. 在 `PlatformAnalytics.ts` 选择该实现。新增平台名称时与现有 `IPlatform.ts` 的 `PlatformName` 保持一致。大厅和比赛的业务触发点无需复制。
5. 使用共用字典注册平台后台字段。补齐平台实现测试，继续执行统一契约、权威结算、教学和性能回归；最后验证实际平台构建、真机和后台入库。

禁止在比赛 `update()` 中上报或补发，禁止让 SDK 失败阻断玩法／云结算。现有抖音来源服务是应用级单例，场景往返不重复订阅；界面订阅需要按自身生命周期解绑，不能在普通场景销毁时释放全局服务。

## 当前边界

当前版本配置仍为 `is_test=1`；正式发布前应确认后台字段注册并修改构建版本和测试标记。微信目前使用 `DisabledAnalytics('wechat')`，统一接口接入不代表微信已有实际统计。

侧边栏来源验证只属于抖音能力：`homepage + sidebar_card` 且 `showFrom != 0` 才算；普通切前后台及导航 success 都不算复访。第二批只接来源服务，侧边栏引导按钮和弹窗尚未接入。
